# Трёхмерная схема установки кодом

Все предыдущие главы этой части считали числа. Эта — о том, как из тех же чисел получить чертёж.

## Зачем описывать геометрию программой

Трёхмерную модель установки обычно рисуют мышкой в CAD-редакторе. Для машиностроения это правильно, а для ускорителя — не очень, и вот почему.

Магнитная структура живёт в текстовом файле, где перечислены элементы с длинами, градиентами и углами поворота. Этот файл меняется постоянно — добавили квадруполь, передвинули диагностику, поменяли угол поворотного магнита. Каждое такое изменение означает, что нарисованная мышкой модель устарела, и кто-то должен вспомнить, что её надо перерисовать. Обычно не вспоминает.

Библиотека [CadQuery](https://cadquery.readthedocs.io) предлагает другой путь. **Геометрия описывается кодом на Python.** Из этого следует всё остальное — модель ложится в репозиторий рядом с расчётом, различия между версиями видны в `git diff`, сборка чертежа встаёт в конвейер тестов, а главное, тело установки строится **прямо из описания структуры**, а не параллельно ему.

## Структура как данные

Начнём с описания. Возьмём кусок тракта: два квадруполя, дрейфы между ними и два поворотных магнита по 45°.

```python
import numpy as np
import cadquery as cq

# тип элемента, длина в метрах, параметр
LATTICE = [
    ("drift", 0.30, None), ("quad", 0.20, +1), ("drift", 0.30, None),
    ("bend",  0.50, np.pi / 4),
    ("drift", 0.30, None), ("quad", 0.20, -1), ("drift", 0.30, None),
    ("bend",  0.50, np.pi / 4),
]
```

В настоящем проекте этот список не пишут руками — его читают из файла магнитной структуры, того самого, по которому считает расчётный код. Здесь мы задаём его явно, чтобы пример был самодостаточным, но весь смысл в том, что **источник геометрии и источник физики — один и тот же файл**.

## Один тип элемента — одна функция

Дальше на каждый тип элемента заводится своя функция-конструктор. Каждая знает про своё тело и ничего про соседей:

```python
def drift(length, _):
    return cq.Workplane("XY").circle(0.02).extrude(length)

def quad(length, sign):
    body = cq.Workplane("XY").rect(0.24, 0.24).extrude(length)
    return body.edges("|Z").fillet(0.03) if sign > 0 else body

def bend(length, angle):
    r = length / angle                       # радиус по длине дуги и углу
    return (cq.Workplane("XY").rect(0.20, 0.16)
              .revolve(np.degrees(angle), (r, 0, 0), (r, 1, 0)))

BUILDERS = {"drift": drift, "quad": quad, "bend": bend}
```

Тела здесь строятся **выдавливанием и вращением плоского контура**, а не составлением из примитивов. Дрейф — окружность, вытянутая на длину; поворотный магнит — прямоугольник, повёрнутый вокруг оси на нужный угол. Так геометрия остаётся параметрической. Поменял угол в описании структуры — тело перестроилось само.

Словарь `BUILDERS` в конце — привычная замена длинной цепочке `if`. Добавить секступоль значит написать функцию и дописать строку в словарь; трогать код расстановки не придётся.

## Где ставить каждый элемент

Самое интересное — расстановка. Элементы идут вдоль траектории пучка, а траектория эта не прямая, потому что поворотный магнит меняет направление.

Заведём две величины: положение начала текущего элемента и направление, в котором смотрит пучок. Для каждого элемента нужно знать, куда сместится его конец относительно начала:

```python
def local_step(kind, length, param):
    """Смещение конца элемента относительно начала, в его собственных осях."""
    if kind != "bend":
        return np.array([0.0, 0.0, length]), 0.0
    r = length / param
    return np.array([r * (1 - np.cos(param)), 0.0, r * np.sin(param)]), param
```

Прямой элемент просто сдвигает пучок вперёд на свою длину и направления не меняет. Поворотный ведёт пучок по дуге радиуса \\(R = L/\theta\\). Конец дуги смещён вперёд на \\(R\sin\theta\\) и вбок на \\(R(1-\cos\theta)\\), а направление доворачивается на \\(\theta\\).

Дальше остаётся пройти по структуре, поворачивая локальное смещение в лабораторные оси:

```python
def build(lattice):
    assembly, pos, heading = cq.Assembly(), np.zeros(3), 0.0
    for i, (kind, length, param) in enumerate(lattice):
        assembly.add(BUILDERS[kind](length, param), name=f"{kind}{i}",
                     loc=cq.Location(cq.Vector(*pos),
                                     cq.Vector(0, 1, 0), np.degrees(heading)))
        step, turn = local_step(kind, length, param)
        c, s = np.cos(heading), np.sin(heading)
        pos = pos + np.array([c * step[0] + s * step[2], 0.0,
                              -s * step[0] + c * step[2]])
        heading += turn
    return assembly, pos, heading
```

Порядок трёх действий внутри цикла существен. Сначала элемент ставится **в текущее** положение с **текущим** направлением, потом сдвигается положение, и только потом доворачивается направление. Переставь местами последние две строки — и каждый элемент после поворотного магнита уедет.

## Проверка

Геометрию легко проверить, не открывая просмотрщик. Два поворота по 45° должны развернуть пучок ровно на 90°, а сумма длин элементов даёт длину траектории:

```python
acc, pos, heading = build(LATTICE)
print("элементов:", len(acc.children))
bb = acc.toCompound().BoundingBox()
print(f"габарит: X {bb.xlen:.2f} м, Z {bb.zlen:.2f} м")
print(f"конец траектории: X {pos[0]:.3f} м, Z {pos[2]:.3f} м")
print(f"поворот: {np.degrees(heading):.1f}°")
assert bb.zmax >= pos[2] and bb.xmax >= pos[0]   # тела обязаны накрывать траекторию
```

    элементов: 8
    габарит: X 1.32 м, Z 2.10 м
    конец траектории: X 1.202 м, Z 2.002 м
    поворот: 90.0°

Два поворота по 45° дают ровно 90°, полная длина 2.60 м, а конец траектории лежит внутри габарита. Вот так **чертёж и покрывается тестом**.

Главное здесь — `assert` в последней строке: тела элементов обязаны накрывать траекторию, по которой их расставляли. Пока писалась эта глава, магнит строился вращением вокруг не той оси, и обнаружилось это не глазами — картинка выглядела правдоподобно, — а тем, что Z-габарит вышел 1.83 м при конце траектории на 2.002 м. Тело уехало из-под пучка, и арифметика сказала об этом сразу.

Готовую сборку выгружают в обменный формат, который откроет любой CAD:

```python
cq.exporters.export(acc.toCompound(), "layout.step")
```

## Что из этого вынести

**Геометрия — такой же продукт кода, как график.** К ней применимо всё, чему учит эта книга: контроль версий, сборка в конвейере, тесты. Модель, собранная из описания структуры, от него не отстанет. Нарисованная мышкой отстаёт всегда.

**Разбиение на конструкторы — это та же декомпозиция**, о которой шла речь в главе [«От скрипта к приложению»](../../dev/app.md). Одна функция отвечает за одно тело и ничего не знает о соседях; расстановка не знает, из чего сделан квадруполь. Границу провели там, где ожидаются изменения — новые типы элементов появляются часто, а правило расстановки почти никогда.

**Проверяемость важнее красоты картинки.** Ошибку в трёхмерной модели глазом почти не видно. Установка на экране выглядит правдоподобно, даже если один магнит уехал на полметра. Зато арифметика ловит её мгновенно, что и случилось при подготовке этой главы: суммой углов, длиной траектории, габаритом.
