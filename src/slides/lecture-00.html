Пояснение

Между научной идеей и инструментом на рабочем столе проходят годы: трансформеру к выходу ChatGPT было уже пять лет.

Изложение. Нынешний подъём растянут на десятилетие, однако до 2022 года он почти не выходил за пределы исследовательских лабораторий. В 2012 году сеть AlexNet выиграла соревнование ImageNet и показала, что глубокие свёрточные сети, обученные на графических ускорителях, решают задачи компьютерного зрения лучше прежних методов. В 2014 году Ян Гудфеллоу предложил генеративно-состязательные сети: нейросети начали порождать данные, а не только раскладывать их по классам. В 2017 году статья «Attention Is All You Need» ввела архитектуру трансформера, лежащую в основе практически всех больших языковых моделей. В 2018–2020 годах были обнаружены законы масштабирования, связывающие качество модели с числом параметров, объёмом данных и вычислительным бюджетом, появились GPT-2 и GPT-3. ChatGPT в 2022 году стал прорывом не архитектуры, а дообучения под диалог и удобного интерфейса к модели, существовавшей и раньше. К заявлениям руководителей индустрии о скором «взлёте» и сингулярности целесообразно относиться с поправкой на их заинтересованность в притоке инвестиций: речь идёт об инструменте с конкретными сильными и слабыми сторонами.

Изложение. В 2025 году организация METR провела эксперимент со строгим контролем. Опытным разработчикам, годами ведущим проекты с открытым кодом, давали задачи в их собственных хорошо знакомых репозиториях; часть задач, выбранная случайным образом, решалась с ИИ-ассистентом, часть без него. С ассистентом задачи выполнялись примерно на 19 % медленнее. Важна не сама цифра, а знак, противоположный ожиданиям и авторов, и участников. Те же участники после эксперимента были уверены, что ИИ ускорил их работу примерно на 20 %: ощущение разошлось с замером почти на 40 процентных пунктов. Результат получен на экспертах в знакомом им коде, где человек и так работает близко к пределу, а ассистент добавляет накладные расходы: прочитать фрагмент, проверить и исправить. Он ничего не говорит о ситуации, где разработчик осваивает незнакомую библиотеку, пишет шаблонный код или работает на неродном языке программирования: там выигрыш реален. Отсюда два вывода: ощущение ускорения не заменяет измерения; выигрыш тем меньше, чем лучше разработчик знает задачу, и тем важнее умение отличить дельное предложение от правдоподобной ошибки. Умение пользоваться ИИ является отдельным навыком, осваиваемым так же, как отладчик или система контроля версий.

Пояснение

Изложение. Большая языковая модель решает одну задачу: предсказывает по имеющемуся тексту, какой фрагмент будет следующим. Диалог, генерация кода и объяснения надстроены над этим механизмом. Текст разбивается токенизатором на токены, токены преобразуются в векторы и проходят через десятки слоёв трансформера. Ключевым механизмом внутри является внимание (attention): при обработке каждого токена модель взвешивает, насколько для него важен каждый из остальных, и благодаря этому связывает определение функции в начале файла с её вызовом в конце. На выходе получается распределение вероятностей следующего токена; выбранный токен дописывается к тексту, и цикл повторяется, пока ответ не завершён.

Обучение и его

пределы

Предобучение: месяцы на корпусе текстов из интернета — язык, факты, приёмы программирования

Дообучение: следование инструкциям и полезность в диалоге

Важно

Дата среза: о событиях после окончания обучающего корпуса модель не знает.

Важно

Модели недоступны файлы пользователя, пока они не переданы ей явно.

Изложение. Обучение состоит из двух этапов. Сначала модель в течение месяцев обрабатывает корпус текстов, собранных со всего интернета, и учится предсказывать продолжение, усваивая язык, факты и типовые приёмы программирования. Затем её дообучают следовать инструкциям и быть полезной в диалоге. Отсюда следуют два ограничения: модель не знает ничего после даты, на которой обрывается обучающий корпус, и не имеет доступа к файлам пользователя, пока они не переданы ей явно. Для физиков: на вопрос о свежей версии библиотеки или о недавно опубликованной работе модель отвечает правдоподобно, но по устаревшим сведениям; такие ответы проверяются по документации.

Для физика

Несуществующая библиотека обнаруживается сразу, а перепутанный коэффициент может дойти до отчёта. Сведения ассистента о физике, численных методах и API проверяются по документации.

Изложение. Здесь заключена главная причина, по которой ИИ-ассистент не заменяет понимания. Модель обучена порождать правдоподобное продолжение, а не истинное, и механизма проверки фактов у неё нет. Если правильный ответ ей неизвестен, она не сообщит об этом, а сгенерирует то, что выглядит как правильный ответ. Такие выдумки называют галлюцинациями; в программировании они принимают узнаваемые формы: аргумент функции, придуманный по аналогии; правдоподобная, но выдуманная ссылка; формула с перепутанным коэффициентом; библиотека с осмысленным названием, которой не существует. Для физиков: несуществующая библиотека обнаруживается на первом же импорте, а перепутанный коэффициент в научном коде может остаться незамеченным — программа запускается, выдаёт числа, числа попадают в отчёт. Всё, что ассистент сообщает о физике, численных методах и API библиотек, проверяется по документации и здравому смыслу; код, в котором разработчик не разобрался, в проект не включается.

Пояснение

Названия моделей и цены меняются каждые несколько месяцев; сравнение по качеству, скорости и стоимости ведут независимые площадки artificialanalysis.ai и openrouter.ai.

Изложение. Характеристики модели складываются из трёх составляющих. Размер — число обучаемых параметров, от единиц миллиардов до триллионов: чем модель больше, тем более тонкие зависимости она способна уловить, но тем дороже и медленнее её работа; для простых задач небольшая модель отвечает быстрее и дешевле при том же результате. Контекстное окно — число токенов, которое модель видит за раз, включая вопрос, приложенные файлы и собственный ответ; это главный практический предел, и чем ближе к нему, тем хуже модель удерживает детали из середины контекста. Способность к рассуждению: часть моделей обучена перед ответом порождать промежуточные шаги, такие модели сильнее в математике и отладке, но отвечают дольше и стоят дороже. Названия моделей и цены здесь не приводятся: они устаревают быстрее, чем пишется текст. Выбор модели для работы с кодом делается прогоном двух-трёх кандидатов на собственных типичных задачах.

Изложение. Зрелые инструменты читают из репозитория файл с правилами, описывающий, как принято писать код в проекте; агент добавляет его к каждому запросу, и повторять одно и то же не приходится. Сюда записываются договорённости группы: версия языка и стиль кода, система единиц, приёмы обработки массивов, требование сопровождать код тестом, запрет на фиксацию данных экспериментов. Парным механизмом является файл игнорирования по образцу .gitignore. В него заносится всё, что не должно передаваться в модель: файлы с паролями и токенами, персональные данные, неопубликованные сырые данные экспериментов и материалы, закрытые соглашением с институтом. Пояснение

Изложение. Ошибки ассистента делятся на три вида, и все три обнаруживаются чтением и запуском. Наиболее безобидна неэффективность: предложение решает задачу, но лишним проходом или лишней копией; на учебных объёмах это незаметно, на рабочих начинает мешать. Наиболее опасно выдумывание: модель уверенно называет библиотеки, методы и аргументы, не существующие в природе, и выглядит это так же, как верный ответ. Метод, придуманный моделью, приводит к ошибке при первом же вызове, а неверная формула молча возвращает правдоподобное число — её выявляет только тест.

Изложение. Ветка позволяет экспериментировать, не затрагивая работающий код: для проверки другого алгоритма фильтрации сигнала не требуется комментировать половину файла, достаточно создать ветку, названную по сути эксперимента. git branch выводит список веток и отмечает текущую звёздочкой, git switch -c создаёт ветку и переходит на неё. Важно

git reset --hard без предупреждения уничтожает незафиксированную работу: перед ним вызывается git status. Историю, уже отправленную коллегам, не переписывают.

Изложение. Зафиксированное в коммите почти невозможно потерять: Git скорее сохранит лишнее, чем удалит нужное. В таблице собраны типовые ситуации. git restore возвращает файл к версии из индекса, и правки, не добавленные в индекс, при этом исчезают. git commit --amend исправляет последний коммит, пока он не отправлен на сервер. git reset --soft HEAD~1 отменяет последний коммит, оставляя его изменения в индексе, а git reset --hard HEAD~1 удаляет его вместе с изменениями. Уже отправленный коммит отменяется командой git revert, создающей новый коммит с обратным изменением, без переписывания истории. git stash прячет незаконченные правки, git stash pop возвращает их. Если коммиты пропали, git reflog показывает журнал последних положений HEAD. Коммит, недостижимый ни через ветку, ни через тег, хранится в журнале около месяца, после чего удаляется сборщиком мусора, поэтому этот приём действует ограниченное время. Историю переписывают reset, --amend и rebase; в ветках, уже отправленных на сервер и полученных коллегами, их не применяют: коллегам придётся разбираться с разошедшимся графом.

Пояснение

git add -p позволяет принять часть правок агента и отвергнуть остальные.

Важно

git restore не удаляет новые файлы, созданные агентом: их перечисляет git status.

Изложение. Две половины лекции сходятся в одном порядке работы. Перед поручением агенту рабочий каталог приводится к чистому состоянию: всё нужное зафиксировано коммитом, который служит точкой возврата. Агент вносит правки, после чего git diff показывает каждую изменённую строку, и каждая из них читается. Принятые правки добавляются в индекс, при необходимости по частям командой git add -p, и фиксируются коммитом с сообщением, объясняющим изменение. Отвергнутые правки отменяются командой git restore .; новые файлы, созданные агентом, эта команда не удаляет, их перечисляет git status. Такой порядок делает работу агента наблюдаемой и обратимой: всё, что он сделал, видно в git diff и git status, а правки отслеживаемых файлов отменяются одной командой.

Без .gitignore в репозиторий попадают __pycache__ и виртуальное окружение. Код, предложенный ассистентом и не понятый автором, на защите не засчитывается.
