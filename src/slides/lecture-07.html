Цель лекции

Не вычислять всё сразу: элементы по одному, вычисления по запросу, ожидание без блокировки

Итератор выдаёт элементы по одному, генератор приостанавливает функцию на yield и продолжает её с места остановки, сопрограмма принимает значения извне, а цикл событий переключается между сопрограммами, пока они ожидают. Эти механизмы позволяют обрабатывать данные, не помещающиеся в память, описывать бесконечные последовательности и в одном потоке одновременно ожидать ответов нескольких приборов.

Изложение. Список из ста тысяч квадратов целых чисел вместе с самими числами занимает около 4 МБ, а генератор тех же чисел — сотни байт: значения вычисляются тогда, когда их запрашивают. На этом основаны три приёма. Первый — потоковая обработка: файл, журнал или последовательность событий читаются по одному элементу, и объём данных ограничен диском, а не оперативной памятью. Второй — бесконечные последовательности: генератор описывает правило получения следующего элемента, а момент остановки определяет вызывающий код. Третий — сопрограммы и асинхронность: функция, способная приостановиться, позволяет одному потоку переключаться между задачами, пока каждая ожидает ответа от сети или прибора. Для физиков: журналы смены, потоки событий детектора и шаги интегрирования естественно описываются итераторами и генераторами; асинхронность нужна там, где программа опрашивает приборы или обращается к сетевым сервисам.

Пояснение

StopIteration перехватывает сам цикл: в коде исключение не видно.

Изложение. Цикл for в Python не перебирает индексы: он получает у объекта итератор функцией iter и вызывает для него next, пока тот не сообщит об окончании исключением StopIteration. Исключение перехватывает сам цикл, поэтому в коде оно не видно. В байт-коде это две инструкции: GET_ITER вызывает iter для перебираемого объекта, FOR_ITER на каждом шаге вызывает next и при окончании элементов переходит за конец цикла. Встроенные функции iter и next вызывают специальные методы __iter__ и __next__, как len вызывает __len__; напрямую специальные методы почти никогда не вызываются. По тому же протоколу работают распаковка, списковые включения, функции sum, max, sorted и list, конструкторы коллекций и оператор in для объектов без метода __contains__. Для физиков: любой источник данных, поддерживающий протокол, — файл, генератор событий, набор измерений — обрабатывается тем же циклом for, что и список.

Итератор однопроходный: после StopIteration каждый следующий next снова даёт StopIteration.

Пояснение

Проверка: isinstance(x, collections.abc.Iterator) отличает итератор от итерируемого объекта.

Изложение. Протокол итерации разделяет две роли. Итерируемый объект (iterable) выдаёт итератор: его метод __iter__ возвращает новый объект-итератор при каждом вызове. Итератор (iterator) выдаёт элементы: метод __next__ возвращает следующий элемент или возбуждает StopIteration, если элементы закончились. Итератор в Python обязан быть и итерируемым — его __iter__ возвращает self, поэтому итератор можно передать в цикл for. Отсюда различие в поведении: по списку можно пройти сколько угодно раз, поскольку каждый for получает новый итератор, а по итератору — один раз, после чего он исчерпан. Документация требует, чтобы исчерпанный итератор и дальше возбуждал StopIteration при каждом вызове next; итератор, который после этого снова начинает выдавать элементы, считается некорректным. Для физиков: список измерений можно обойти несколько раз — для среднего и для дисперсии; файл или генератор событий после первого прохода пуст, и второй проход требует открыть файл заново или сохранить данные.

class Linspace:
    def __init__(self, a, b, n):
        self.a, self.n = a, n
        self.h = (b - a) / (n - 1)
    def __iter__(self):
        return LinspaceIterator(self.a, self.h, self.n)
 
class LinspaceIterator:
    def __init__(self, a, h, n):
        self.a, self.h, self.n, self.i = a, h, n, 0
    def __iter__(self):
        return self
    def __next__(self):
        if self.i == self.n:
            raise StopIteration
        self.i += 1
        return self.a + (self.i - 1) * self.h

Пояснение

Счётчик обхода i хранится в итераторе: каждый for получает новый итератор и начинает с первой точки.

Важно

Если __iter__ контейнера вернёт self и счётчик будет храниться в нём, второй проход окажется пустым.

Для физика

Linspace — упрощённый аналог numpy.linspace. Точка вычисляется как a + i·h, а не накоплением: ошибки округления не растут с номером точки.

Изложение. Собственный итератор — класс с методами __next__ и __iter__. Linspace — аналог numpy.linspace: n равноотстоящих точек отрезка от a до b. Роли разделены: контейнер Linspace хранит параметры сетки и на каждый вызов __iter__ создаёт новый LinspaceIterator, а итератор хранит состояние обхода — номер следующей точки. Поэтому по одной сетке можно пройти сколько угодно раз, и каждый цикл начинается с первой точки. Если совместить роли в одном классе, где __iter__ возвращает self, а счётчик хранится в объекте, кода станет меньше, но второй проход окажется пустым: он начнётся там, где закончился первый. Такое совмещение оправдано для объектов, которые сами являются однопроходными, — файлов, сетевых потоков, генераторов. Точка вычисляется как a + i·h, а не прибавлением h к предыдущей: при накоплении ошибки округления складываются и растут с номером точки, а при умножении погрешность каждой точки остаётся в последних разрядах. Последняя точка и при умножении может отличаться от b в последнем знаке, поэтому numpy.linspace присваивает ей значение b явно. Во второй части тот же обход записывается генератором в несколько строк. Для физиков: сетки по времени, энергии или координате — частый случай собственного итерируемого объекта; при работе с массивами их заменяют numpy.linspace и numpy.arange, но протокол тот же.

Первый — протокол последовательности: если у объекта нет __iter__, но есть __getitem__, iter создаёт итератор, запрашивающий элементы с индексами 0, 1, 2 и далее, пока __getitem__ не возбудит IndexError. Для чтения файла блоками границей служит пустая строка байтов: read возвращает b'' в конце файла. Оператор in вызывает метод __contains__, а при его отсутствии перебирает объект через __iter__ или __getitem__, пока не найдёт равный элемент. Для итератора это означает расход элементов: после проверки 0.5 in it в итераторе остаются только элементы после найденного. Встроенные коллекции — итерируемые объекты, но не итераторы: каждый проход создаёт новый итератор. range не хранит элементы, а вычисляет их и при этом остаётся последовательностью с длиной, индексами и проверкой in без перебора. Для физиков: zip(times, values, strict=True) защищает от молчаливого усечения рядов разной длины, например при объединении отметок времени и показаний.

Изложение. Вторая часть посвящена генераторам — объектам, которые возвращает функция с yield: выполнение приостанавливается на yield и продолжается с места остановки. Генератор заменяет класс итератора несколькими строками и позволяет строить конвейеры обработки данных и бесконечные последовательности.

Генераторная

функция

def countdown(n):
    print('старт')
    while n > 0:
        yield n
        n -= 1
    return 'пуск'
 
g = countdown(3)   # тело не выполняется
next(g)            # старт, 3
next(g), next(g)   # (2, 1)
next(g)            # StopIteration: пуск

Пояснение

Генератором можно написать __iter__: «for i in range(self.n): yield self.a + i * self.h» заменяет класс LinspaceIterator.

g = countdown(3)

объект-генератор без выполнения тела

next(g)

печать «старт», выполнение до yield: 3

next(g)

продолжение после yield: 2

return 'пуск'

StopIteration('пуск')

Изложение. Функция, в теле которой встречается yield, при вызове не выполняет тело, а возвращает объект-генератор. Генератор — итератор: next запускает тело и выполняет его до ближайшего yield, значение yield становится результатом next, а функция приостанавливается, сохранив локальные переменные и место остановки. Следующий next продолжает выполнение с инструкции после yield. Когда тело завершается, возбуждается StopIteration, и значение return, если оно есть, сохраняется в атрибуте value исключения; цикл for это значение не использует. Поэтому «старт» печатается не при вызове countdown(3), а при первом next. Генератор заменяет класс итератора: метод __iter__ контейнера, написанный генератором, возвращает новый генератор при каждом вызове, и по контейнеру можно проходить многократно, как по Linspace из первой части, но без отдельного класса. Для физиков: генератор удобен там, где следующий элемент вычисляется по предыдущим, — шаги интегрирования, итерации метода Ньютона, последовательные приближения.

Генератор описывает правило перехода к следующему состоянию, а момент остановки выбирает вызывающий код.

Изложение. Генератор с бесконечным циклом описывает последовательность без конца: значения вычисляются, пока их запрашивают. Генератор oscillator выдаёт состояния гармонического осциллятора с шагом dt по полунеявной схеме Эйлера: сначала обновляется скорость, затем координата по новой скорости. Условия остановки в генераторе нет: его задаёт вызывающий код: islice берёт заданное число состояний, takewhile — пока выполняется условие, next с генераторным выражением возвращает первое состояние, удовлетворяющее условию, например первое пересечение нуля. Генератор, из которого взяли часть элементов, продолжает с того места, где остановился; takewhile при этом забирает и первый элемент, не прошедший условие, и этот элемент теряется. Для физиков: так разделяются схема интегрирования и условие остановки — по времени, по числу шагов или по событию (пересечение нуля, выход за границу, достижение равновесия); одна и та же функция служит и для коротких проверок, и для длинных расчётов.

Изложение. Когда генератор лишь передаёт элементы другого итерируемого объекта, цикл for x in g: yield x записывается короче: yield from g. Обход двоичного дерева поиска в порядке возрастания — пример, где это особенно удобно: рекурсивный генератор выдаёт элементы левого поддерева, значение узла и элементы правого поддерева, а вложенные вызовы соединяются через yield from. Конструкция (PEP 380, Python 3.3) не сводится к сокращению цикла. Она передаёт во вложенный генератор значения, отправленные через send, и исключения, отправленные через throw (оба метода разбираются в четвёртой части), а значением самого выражения yield from становится результат return вложенного генератора. Это позволяет разбивать сложный генератор на части, как функцию на подфункции, и было основой первой реализации сопрограмм asyncio до появления await. Изложение. Кроме send, у генератора есть ещё два метода управления. throw возбуждает исключение в точке, где генератор приостановлен, — так, будто его выбросила инструкция yield. Если генератор перехватывает исключение, он продолжает работу до следующего yield, и throw возвращает выданное значение; если нет, исключение выходит наружу из вызова throw. В счётчике на слайде ValueError служит командой сброса. close возбуждает в точке остановки GeneratorExit: генератор обязан завершиться — выполнить блоки finally и выйти. Если вместо этого он снова выполнит yield, возникнет RuntimeError: generator ignored GeneratorExit. Поэтому после перехвата GeneratorExit генератор не выполняет yield: исключение возбуждают повторно или завершают генератор оператором return, а для освобождения ресурсов достаточно finally или with. CPython вызывает close и при уничтожении незавершённого генератора, поэтому файлы и соединения, открытые в теле генератора, закрываются и при прерванном обходе. Важно

Исключение из блока with возникает в точке yield: без try/finally код после yield не выполнится.

Изложение. Декоратор contextlib.contextmanager превращает генератор с одним yield в менеджер контекста. Код до yield выполняется при входе в блок with и играет роль __enter__; значение yield связывается с переменной после as; код после yield выполняется при выходе из блока и играет роль __exit__. Если в блоке with возникает исключение, оно возбуждается в генераторе в точке yield, поэтому завершающий код помещается в finally — иначе при ошибке он не выполнится. Исключение, перехваченное в генераторе и не возбуждённое повторно, считается обработанным. Такой менеджер короче класса с методами __enter__ и __exit__ и подходит для однократных действий вокруг блока: замер времени, временная смена каталога или настроек, захват и освобождение ресурса. В contextlib есть и готовые менеджеры: suppress подавляет указанные исключения, chdir (3.11) временно меняет рабочий каталог, closing вызывает close по выходе, ExitStack собирает переменное число менеджеров. Менеджер из contextmanager применяется и как декоратор функции. Важно

Асинхронность ускоряет ожидание, а не вычисление: поток один, и долгий расчёт останавливает все задачи.

Изложение. Программа, опрашивающая несколько приборов или скачивающая файлы, большую часть времени ожидает: запрос отправлен, ответа нет, процессор простаивает. При последовательном опросе задержки складываются: три прибора с задержками 0,3, 0,5 и 0,8 с опрашиваются за 1,6 с. Если ожидания перекрываются, общее время равно наибольшей задержке — 0,8 с. Перекрыть ожидания можно потоками, но поток — дорогой ресурс: память под стек и переключения контекста операционной системой, а при тысячах соединений их число становится ограничением. Асинхронность решает задачу в одном потоке: задача, дошедшая до ожидания, добровольно отдаёт управление, и планировщик переключается на задачу, готовую продолжить. Для расчётов этот подход бесполезен: поток один, и задача, занявшая процессор, останавливает все остальные. Вычислительные задачи распределяют по процессам, векторизуют средствами NumPy или компилируют — им посвящены главы раздела «Ускорение расчётов». Для физиков: опрос приборов и датчиков по сети, обращение к базе данных эксперимента, загрузка файлов с сервера — задачи ожидания; численное моделирование и обработка массивов — вычислительные.

Пояснение

Задачи переключаются только в точках yield: многозадачность кооперативная.

Изложение. Планировщик, переключающийся между задачами, записывается в десяток строк, если задачи — генераторы. Задача выполняет шаг работы и отдаёт управление инструкцией yield. Планировщик хранит очередь готовых задач, берёт первую, продвигает её вызовом next до следующего yield и ставит в конец очереди; завершившаяся задача возбуждает StopIteration и из очереди удаляется. Две задачи чередуются, хотя поток один: переключение происходит только в точках yield, поэтому такая многозадачность называется кооперативной — задача, не дошедшая до yield, удерживает поток. В цикле событий asyncio задача, ожидающая данных, не возвращается в очередь сразу: она регистрирует ожидание у селектора операционной системы и снова становится готовой, когда данные пришли или истёк тайм-аут. Полную реализацию такого планировщика на генераторах по Д. Бизли разбирает глава книги «Асинхронность»; asyncio устроен по тому же принципу, но вместо генераторов использует нативные сопрограммы и объекты Future.

Изложение. До Python 3.5 сопрограммы asyncio были генераторами: они ожидали друг друга через yield from и помечались декоратором @asyncio.coroutine. Изложение. Сопрограммы выполняются одновременно, только если каждая обёрнута в задачу (Task): await a(); await b() выполняет их по очереди. asyncio.gather запускает переданные сопрограммы как задачи и ожидает все, возвращая результаты в порядке аргументов. create_task ставит сопрограмму в цикл событий и возвращает объект Task, который можно ожидать позже; ссылку на задачу сохраняют, иначе её может уничтожить сборщик мусора. С Python 3.11 предпочтителен TaskGroup: задачи, созданные в блоке async with, ожидаются при выходе из блока, а ошибка одной из них отменяет остальные и выходит наружу как ExceptionGroup — после выхода из блока незавершённых задач не остаётся. asyncio.timeout ограничивает время блока: при превышении отменяется текущая задача, а вместе с ней — задачи, которые она ожидает через gather или TaskGroup, и блок завершается TimeoutError. Пояснение

Пока источник ожидает следующего элемента (await внутри __anext__), цикл событий выполняет другие задачи; источник без await управление не отдаёт.

Изложение. Протокол итерации имеет асинхронный вариант для источников, следующий элемент которых приходится ожидать: сообщений из сети, отсчётов прибора, строк из базы данных. Асинхронный итерируемый объект определяет __aiter__, асинхронный итератор — __anext__, возвращающий ожидаемый объект, а окончание сообщается исключением StopAsyncIteration. Цикл async for вызывает эти методы и ожидает результат __anext__; если источник при этом ожидает данных, цикл событий тем временем выполняет другие задачи, а источник без await управление не отдаёт. Асинхронный генератор (PEP 525, Python 3.6) — функция async def с yield — реализует протокол автоматически, как обычный генератор реализует синхронный. Аналогично async with вызывает асинхронные методы __aenter__ и __aexit__, а встроенные функции aiter и anext (3.10) — асинхронные аналоги iter и next. Асинхронное включение [x async for x in source] собирает элементы асинхронного источника внутри async def. Для физиков: поток отсчётов прибора, поступающих с заданным интервалом, описывается асинхронным генератором, а потребитель обрабатывает отсчёты по мере поступления, не блокируя опрос других устройств.

Важно

Блокирующие вызовы в асинхронном коде недопустимы: time.sleep или синхронный запрос останавливает весь цикл событий.

Изложение. Механизмы лекции различаются назначением. Итераторы и генераторы — средство последовательной обработки данных по одному элементу: файлов, потоков событий, бесконечных последовательностей. Конвейеры генераторов и функции itertools собирают обработку из независимых стадий. Сопрограмма с send хранит состояние, меняющееся по входным данным, — счётчик, статистику, конечный автомат; если состояние сложное или нужен доступ к нему извне, класс нагляднее. contextmanager описывает действия до и после блока. asyncio предназначен для одновременного ожидания многих операций ввода-вывода в одном потоке, а не для ускорения расчётов: вычисления распределяют по процессам, векторизуют или компилируют. Главное правило асинхронного кода — отсутствие блокирующих вызовов: одна функция, надолго занявшая поток, останавливает все задачи цикла событий; такие вызовы выносят в поток через to_thread или в процесс через run_in_executor.

Нативные сопрограммы async def и await выполняет цикл событий, переключая задачи в точках ожидания. Первое проверяет итерируемый объект с методом __iter__ в виде генератора и накопление ошибок округления при вычислении точек сетки сложением. Второе собирает конвейер генераторов с сопрограммой статистики. Третье — скользящие фильтры на очереди фиксированной длины. Четвёртое сравнивает схемы интегрирования: у явной схемы Эйлера величина x² + v² осциллятора с ω = 1 на каждом шаге умножается на 1 + dt², у полунеявной остаётся ограниченной, а период по пересечениям нуля близок к 2π. Пятое — асинхронный опрос с тайм-аутом и обработкой отказа: ExceptionGroup разбирается конструкцией except* (Python 3.11).
