Хеш-таблица обеспечивает O(1) лишь в среднем и при равномерной хеш-функции, дерево поиска — O(log n) лишь при сбалансированности. Задачи о связях — соседство пикселей, маршруты, зависимости этапов обработки — сводятся к графам и их обходам.

Изложение. Цель лекции состоит в том, чтобы выбирать структуру данных по набору операций, которые она выполняет быстро, и понимать, при каких условиях её гарантии нарушаются. Оценки сложности структур этой лекции условны. Хеш-таблица обеспечивает поиск за O(1) лишь в среднем и лишь при равномерной хеш-функции и ограниченном заполнении: при неудачной функции та же таблица вырождается в список и снова требует перебора. Дерево поиска обеспечивает O(log n), только если его высота логарифмическая, а это зависит от порядка вставки ключей. Куча выдаёт минимум за O(1), но не позволяет быстро найти произвольный элемент. Вторая половина лекции обращается к задачам о связях между объектами. Соседство сработавших пикселей детектора, маршруты между помещениями, зависимости этапов обработки данных представляют собой графы, и ответы на вопросы о них — какие пиксели образуют кластер, какой путь кратчайший, в каком порядке выполнять этапы — дают обходы графа и несколько алгоритмов на их основе. Таким образом, лекция переходит от вопроса о том, как быстро найти элемент, к вопросу о том, как устроены связи между элементами.

Для физика

Справочник «имя канала → калибровочный коэффициент»: тысячи каналов и обращение при каждом событии.

Изложение. Интерфейс массива состоит из двух операций — получить значение по индексу и записать значение по индексу, — и обе выполняются за O(1). Ограничение массива состоит в том, что индексом может быть только целое число, а в программах значение часто требуется найти по другому признаку: страну по названию города, калибровочный коэффициент по имени канала, запись о событии по его идентификатору. Сопоставление, при котором каждому объекту первого множества отвечает единственный объект второго, называется отображением; это другое название математического понятия функции. Город при этом служит ключом, а страна — значением: на одну страну может указывать сколько угодно городов, но у города страна одна. Массив также является частным случаем отображения — из целых индексов в значения. Структура, реализующая операции get(key) и set(key, value) для ключей произвольного типа, называется ассоциативным массивом, а сам интерфейс — Map. В Python ассоциативный массив представлен встроенным типом dict, а множество set хранит только ключи. Распространены два способа реализации: хеш-таблица, которой посвящена эта часть, и дерево поиска, рассматриваемое в четвёртой части. В Java присутствуют обе реализации, HashMap и TreeMap, в C++ — std::unordered_map и std::map, а в стандартной библиотеке Python дерева поиска нет. Для физика типичный пример — справочник калибровочных коэффициентов: тысячи каналов и обращение к справочнику при обработке каждого события.

реализация

class NaiveMap:
    def __init__(self):
        self.pairs = []            # пары (key, value)
 
    def get(self, key):
        for k, v in self.pairs:    # перебор: O(n)
            if k == key:
                return v
        return None
 
    def set(self, key, value):
        for i, (k, _) in enumerate(self.pairs):
            if k == key:
                self.pairs[i] = (key, value)
                return
        self.pairs.append((key, value))

Пояснение

Хеш-таблица хранит те же пары, но ищет ключ только в одной короткой корзине.

Изложение. Простейшей реализацией ассоциативного массива является обычный список пар (key, value). Метод get перебирает пары, пока не встретит нужный ключ, и возвращает значение или None, если ключа нет. Метод set выполняет тот же перебор: найдя пару с ключом, он заменяет в ней значение, а не найдя — добавляет новую пару в конец списка. Реализация корректна, но каждая операция в худшем и в среднем случае просматривает O(n) пар, а заполнение справочника из n ключей требует O(n²) сравнений, поскольку каждая вставка сначала проверяет, нет ли уже такого ключа. Для справочника из десятка записей это незаметно, для тысяч каналов, опрашиваемых на каждом событии, — неприемлемо. Хеш-таблица хранит те же пары, но разложенными по множеству коротких списков, и вычисляет по ключу, в каком из них искать; демонстрация после нескольких следующих слайдов сравнит обе реализации на одних и тех же ключах.

Изложение. Хеш-таблица является способом реализации ассоциативного массива, при котором пары (key, value) разложены по ячейкам обычного массива — корзинам, — а номер корзины вычисляется непосредственно по ключу. Для этого необходима хеш-функция: функция, преобразующая ключ в целое число, называемое хешем. Рассмотрим пример главы — склад фруктов. Пусть хешем служит сумма порядковых номеров букв названия: для «груши» она равна 70, для «яблока» — 92. Хеш может быть сколь угодно большим, поэтому номер корзины получают из него отдельным шагом, чаще всего остатком от деления на число корзин M: при M = 11 «груша» попадает в корзину 70 mod 11 = 4. Таким образом, отображение «ключ → значение» распадается на три независимых отображения: хеш-функция переводит ключ в число, остаток переводит число в номер корзины, массив по номеру выдаёт корзину, в которой лежит значение. Разделение позволяет менять размер таблицы, не меняя хеш-функцию: при перестройке пересчитывается только остаток. Запоминать номера корзин не требуется: их достаточно в любой момент вычислить той же функцией, поэтому поиск, вставка и удаление сводятся к вычислению хеша и обращению к одной ячейке массива. Отметим последнюю строку кода: у «яблока» остаток тоже равен 4, и два разных ключа претендуют на одну корзину.

Важно

Равномерная раскладка и достаточное число корзин — O(1) в среднем; массовые коллизии — O(n).

Изложение. Коллизией называется ситуация, при которой хеш-функция возвращает для разных ключей одно и то же значение или, после взятия остатка, один номер корзины. Коллизии неизбежны: ключей может быть сколько угодно, а корзин конечное число, поэтому любая хеш-таблица обязана их разрешать. Распространены два способа. В методе цепочек каждая корзина хранит список всех пар, попавших в неё; поиск вычисляет номер корзины и перебирает только её список. Так устроены хеш-таблица главы и HashMap в Java, где слишком длинная цепочка дополнительно превращается в дерево поиска. При открытой адресации в ячейке хранится не больше одной пары, а при коллизии пара помещается в другую свободную ячейку по правилу пробирования — в простейшем случае в следующую по порядку. Поиск повторяет ту же последовательность проб, пока не встретит ключ или пустую ячейку, поэтому удалённую пару нельзя просто стереть: ячейку помечают как удалённую, иначе оборвётся последовательность проб для ключей, вставленных позже. Открытую адресацию используют словарь и множество CPython. В обоих способах цена операции определяется числом ключей, делящих корзину или последовательность проб. Пока хеш-функция распределяет ключи равномерно, а корзин достаточно, цепочки остаются короткими, и поиск, вставка и удаление требуют в среднем O(1). Если же коллизий много, таблица вырождается в список пар с предыдущего слайда, и поиск снова обходится в O(n).

Изложение. Условие «корзин достаточно» выражается числом — коэффициентом заполнения α = n/M, отношением числа ключей к числу корзин. Оценим, что он означает при случайной раскладке, когда каждый ключ независимо попадает в любую из M корзин с равной вероятностью. Вероятность того, что корзина не получила ни одного из n ключей, равна (1 − 1/M)^n ≈ e^(−α): при α = 1 пустой остаётся примерно треть корзин, 37 %. Число ключей в корзине распределено по Пуассону со средним α, и успешный поиск в методе цепочек просматривает в среднем 1 + α/2 пар: сам ключ и все ключи, лежащие в его корзине раньше него, — в среднем половину из α остальных ключей корзины. Следовательно, пока α ограничено константой, средняя цена операции O(1) не зависит от n. Чтобы α не росло, таблица перестраивается: как только коэффициент превышает порог, выбранный реализацией, заводится массив корзин в несколько раз больше прежнего, и все ключи раскладываются по нему заново, поскольку номер корзины зависит от M. Эта операция называется перехешированием и требует O(n), но при кратном росте происходит всё реже, и по той же арифметике, что реаллокация динамического массива в лекции 17, средняя цена вставки остаётся O(1) амортизированно. В CPython порог словаря равен 2/3, множества — 3/5. Важно

Остаток отрицательного числа зависит от языка: номер корзины может стать отрицательным.

Изложение. Простейшим способом получить номер корзины для целого ключа k является остаток от деления на число корзин M. Любое целое число представляется в виде k = j·M + r, где r лежит в диапазоне от 0 до M − 1, — это те же числа, что служат номерами корзин. С отрицательными числами языки обращаются по-разному: в Python −13 % 5 равно 2, как и в математике, а в C и в функции math.fmod результат равен −3, и без учёта этого номер корзины может оказаться отрицательным. Метод деления чувствителен к закономерностям в ключах. Пусть ключами служат номера каналов, где пятый канал каждой платы из 64 каналов имеет номер 64·k + 5. При M = 64 все такие ключи дают один остаток и попадают в одну корзину; в общем случае занятыми окажутся M/НОД(64, M) корзин, и чем больше у M общих делителей с шагом ключей, тем хуже раскладка. Поэтому для метода деления число корзин выбирают простым: у простого M нет делителей, кроме единицы и его самого, и регулярная последовательность ключей распределяется по всем корзинам. Отметим, что эта рекомендация относится к методу деления со слабой хеш-функцией. Распространённые реализации поступают иначе: словарь и множество CPython и HashMap в Java используют таблицы размером 2^k, у которых остаток вычисляется маской младших битов, а равномерность обеспечивается перемешиванием битов хеша — в CPython старшие биты подмешиваются при пробировании, в Java к хешу применяется исключающее ИЛИ с его сдвигом на 16 бит.

Изложение. Второй распространённый способ вычисления номера корзины — метод умножения. Хеш h умножается на константу α из интервала (0, 1), от произведения берётся дробная часть, лежащая в [0, 1), она умножается на число корзин M, и целая часть результата даёт номер корзины от 0 до M − 1. Умножение на иррациональную константу рассеивает соседние ключи по всему отрезку [0, 1), поэтому метод не требует простого M и работает в том числе при M = 2^k, когда умножение и взятие дробной части в целочисленной арифметике сводятся к умножению и сдвигу. Дональд Кнут предложил брать в качестве α число, обратное золотому сечению, (√5 − 1)/2 ≈ 0,618. По теореме о трёх расстояниях точки {k·α} для последовательных k при любом α делят отрезок на промежутки не более трёх различных длин; при α = 1/φ эти длины различаются меньше всего, а каждая следующая точка попадает в один из наибольших промежутков и делит его в золотом отношении, поэтому последовательные ключи рассеиваются наиболее равномерно. Отметим, что речь идёт об обоснованном выборе константы, а не о доказательстве того, что такая хеш-функция наилучшая для любых ключей. Важно

Выбор q важен и для длинных строк: при q = 256 все имена run_0000.dat … run_9999.dat получают один хеш.

Изложение. Строки хешируются полиномиально: коды символов служат коэффициентами многочлена от основания q, и значение многочлена берётся по модулю R. Вычисляется оно по схеме Горнера: хеш умножается на q и складывается с кодом очередного символа, поэтому на строку длины n требуется n умножений. Вычисления ведутся по модулю, поскольку для длинных строк сумма не помещается в машинное целое; R выбирают по размеру типа, 2³² или 2⁶⁴, и тогда в языках с машинными целыми остаток получается автоматически, как результат переполнения беззнакового типа. Выбор q важен и для длинных строк. Рассмотрим чётное основание q = 256: его четвёртая степень равна 2³² и по модулю R = 2³² обращается в ноль вместе со всеми старшими степенями. Следовательно, хеш зависит только от четырёх последних символов строки, а у имён файлов данных вида run_0001.dat это всегда «.dat»: все имена получают один хеш, и хеш-таблица вырождается в список. Чем меньше общих делителей у q и R, тем реже такие вырождения; при R = 2³² любое нечётное q взаимно просто с R, а большое простое q, кроме того, взаимно просто с любым числом корзин, не кратным q. Таким образом, q необходимо брать нечётным, а ради универсальности — большим простым числом. Демонстрация на следующем слайде показывает этот эффект на десяти тысячах имён файлов.

Ограниченность означает, что номер корзины лежит в диапазоне от 0 до M − 1; обычно её обеспечивает отдельный шаг — остаток или метод умножения. Равномерность требует, чтобы на большом наборе различных ключей каждое значение встречалось примерно одинаково часто, иначе одни корзины переполняются, а другие пустуют. Примером неравномерной функции является сумма кодов символов: она не различает строки, составленные из одних и тех же символов в разном порядке, и все её значения сосредоточены в узком диапазоне. Хеширование применяется и за пределами таблиц — для проверки целостности файлов, подлинности сообщений и хранения паролей, — и там к четырём свойствам добавляются ещё два: лавинность, то есть сильное изменение хеша при малом изменении входа, и необратимость — невозможность восстановить вход по хешу. Хеш-функции словаря эти свойства не обязательны, а криптографическим хешам необходимы.

Важно

Алгоритм, перебирающий set строк, недетерминирован: ответ решения 2 из лекции 17 зависит от запуска.

Изложение. Встроенная функция hash() вычисляет хеш для словаря и множества и устроена по-разному для разных типов. Для целых чисел хеш равен самому числу, взятому по модулю простого числа Мерсенна 2⁶¹ − 1, без какой-либо случайности: hash(42) равно 42, hash(2**61) — единице, а hash(−1) равно −2, поскольку значение −1 в C-интерфейсе интерпретатора обозначает ошибку. Для строк и байтов применяется функция SipHash со случайной солью, которая выбирается при запуске интерпретатора (PEP 456); начиная с Python 3.11 по умолчанию используется вариант SipHash-1-3, до этого — SipHash-2-4, что показывает sys.hash_info.algorithm. Соль защищает сервер от атаки, при которой ему присылают ключи, подобранные под одну корзину, и словарь вырождается в список; внутри одного процесса хеш строки неизменен, поэтому работа словаря от соли не зависит. Переменная окружения PYTHONHASHSEED позволяет зафиксировать соль, например для воспроизведения ошибки. Ключом может служить хешируемый объект, то есть объект, хеш которого не меняется за время его жизни. Изменяемые контейнеры list, dict и set не хешируются: изменение списка, уже лежащего ключом в словаре, изменило бы его хеш, и ключ стал бы ненаходимым, поэтому hash([1, 2]) возбуждает TypeError. Хешируемость при этом не совпадает с неизменяемостью: кортеж хешируется, только если хешируемы все его элементы, и hash((1, [2])) тоже возбуждает TypeError, а экземпляры собственных классов по умолчанию хешируются по идентичности, хотя их атрибуты можно менять. Начиная с Python 3.7 словарь гарантированно хранит порядок вставки, а порядок обхода множества не определён и для строк меняется от запуска к запуску. Отсюда практическое следствие: алгоритм, перебирающий множество строк и выбирающий первый из равных, недетерминирован. Именно так устроено решение 2 задачи о самом частом символе из лекции 17: при равных частотах ответ зависит от соли, и для детерминированного ответа необходимо перебирать sorted(set(s)).

Изложение. Криптографические хеш-функции, например SHA-256 из модуля hashlib, помимо четырёх свойств хеш-функции таблицы обладают лавинностью и необратимостью: изменение одного бита входа меняет в среднем половину битов хеша, а найти вход по хешу или два входа с одинаковым хешем вычислительно невозможно. Это позволяет решать несколько задач. Контрольная сумма файла данных, опубликованная рядом с файлом, позволяет обнаружить повреждение при передаче или хранении: случайное совпадение 256-битных хешей практически исключено. Подлинность сообщения в сети проверяется кодом аутентификации HMAC, вычисляемым хешем от сообщения и секретного ключа, или электронной подписью. Функции MD5 и SHA-1, встречающиеся в старых программах, для проверки подлинности непригодны: для них построены коллизии, для SHA-1 — в 2017 году, поэтому применяют SHA-256 и более новые функции. Отметим, что хеш-функция не шифрует сообщения: зашифрованное сообщение расшифровывается обратно, а хеш необратим по определению; шифрование выполняют отдельные алгоритмы, например AES. Хранение паролей также требует большего, чем однократное применение хеш-функции. Быструю функцию злоумышленник, получивший базу, перебирает со скоростью миллиардов паролей в секунду на графическом процессоре, а одинаковые пароли дают одинаковые хеши. Поэтому к паролю приписывают случайную соль, хранимую рядом с хешем, и применяют намеренно медленную функцию — PBKDF2 с сотнями тысяч итераций, scrypt или Argon2, требующие ещё и памяти. В стандартной библиотеке Python для этого предназначены hashlib.pbkdf2_hmac и hashlib.scrypt; рекомендуемые на текущий момент параметры приводит OWASP Password Storage Cheat Sheet.

Для физика

Каталоги файловой системы, группы HDF5, объёмы Geant4, дерево вызовов профилировщика.

Изложение. Деревом называется набор узлов, соединённых рёбрами, в котором выполнены три условия: выделен один узел, корень; у каждого узла, кроме корня, ровно один родитель; от корня до любого узла ведёт единственный путь. В терминах шестой части дерево представляет собой связный граф без циклов. Узлы, родителем которых служит некоторый узел, называются его потомками; узел без потомков называется листом, узел хотя бы с одним потомком — внутренним. Узел вместе со всеми потомками, их потомками и так далее образует поддерево, как поддерево с корнем B на рисунке. Глубина узла равна числу рёбер на пути от корня, у корня она равна нулю; узлы одной глубины составляют уровень, а высота дерева равна наибольшей глубине — на рисунке трём. Глубину и высоту иногда считают в узлах, и тогда все числа на единицу больше; в задачах необходимо уточнять, какое соглашение принято. Главное свойство дерева — рекурсивность: дерево складывается из корня и поддеревьев, каждое из которых само является деревом, поэтому алгоритмы на деревьях почти всегда записываются рекурсивно, а базовым случаем служит пустое дерево. Иерархии встречаются в физических программах постоянно: каталоги файловой системы, группы и датасеты файла HDF5, геометрия детектора в Geant4 из вложенных объёмов, дерево вызовов, собранное профилировщиком. Отметим оговорку для HDF5: жёсткие ссылки позволяют включить один объект в несколько групп, поэтому, строго говоря, структура такого файла является ориентированным графом с корнем, а не деревом.

Пояснение

Любое дерево сводится к двоичному: левая ссылка — первый потомок, правая — следующий узел того же родителя.

Изложение. Двоичным называется дерево, в котором у каждого узла не больше двух потомков, различаемых как левый и правый. На двоичных деревьях построены деревья поиска и кучи, а дерево общего вида сводится к двоичному: левая ссылка указывает на первого потомка, правая — на следующий узел того же родителя. В Python узел описывается классом с двумя ссылками, как элемент связного списка из лекции 17, только ссылок теперь две. Дерево с рисунка записывается одной строкой: корень 5 с левым поддеревом 3, у которого потомки 1 и 4, и правым листом 8. Для работы со всем деревом достаточно одной ссылки на корень, от которого достижим любой узел, а пустое дерево представлено значением None. Поэтому функции, работающие с деревьями, принимают корень и первым делом проверяют, не равен ли он None: это и есть базовый случай рекурсии.

Пояснение

Время O(n); память O(h) на стек рекурсии у DFS и до O(n) на очередь у BFS.

Изложение. Обход дерева представляет собой посещение каждого узла ровно по одному разу. Обходы делятся на два семейства. Обход в глубину уходит по ветви до листа и только затем возвращается; три его классических варианта различаются моментом обработки узла относительно поддеревьев. Прямой обход обрабатывает узел до потомков и для дерева с предыдущего слайда выдаёт 5 3 1 4 8, центрированный — между левым и правым поддеревом, 1 3 4 5 8, обратный — после потомков, 1 4 3 8 5. Обход в ширину идёт по уровням: корень, затем все узлы глубины 1, затем глубины 2, — и выдаёт 5 3 8 1 4. Естественной реализацией обхода в ширину служит очередь: узел снимается с её начала, а его потомки ставятся в конец; рекурсивная запись также возможна — обходом в глубину, раскладывающим узлы по спискам уровней, — но очередь проще. Любой обход посещает каждый узел один раз и требует O(n) времени. Дополнительная память различается: обход в глубину хранит стек рекурсии глубиной до высоты дерева h, обход в ширину — очередь, вмещающую самый широкий уровень, до O(n) узлов. Назначение обходов определяется порядком. Прямой обход позволяет копировать и сериализовать дерево сверху вниз: узел создаётся раньше потомков. Обратный обход позволяет вычислять снизу вверх величины, зависящие от поддеревьев, — высоту, размер, значение выражения. Центрированный обход дерева поиска выдаёт ключи по возрастанию, а обход в ширину — узлы по уровням.

Пояснение

Отсортированный массив медленно вставляет, хеш-таблица не хранит порядка; дерево поиска обеспечивает и то и другое.

Изложение. Двоичным деревом поиска называется двоичное дерево, в каждом узле которого выполняется свойство порядка: все ключи левого поддерева строго меньше ключа узла, а все ключи правого — строго больше. Свойство порядка превращает поиск в аналог двоичного поиска по отсортированному массиву: искомый ключ сравнивается с корнем, и если он меньше, спуск продолжается налево, если больше — направо; каждый шаг отбрасывает целое поддерево, заведомо не содержащее ключа. Вставка выполняет тот же спуск, а новый узел подвешивается там, где спуск дошёл до None; рекурсивная запись главы возвращает корень поддерева, чтобы родитель мог переприсвоить ссылку. Поиск, вставка и удаление проходят один путь от корня вниз и требуют O(h) операций, где h — высота дерева. Центрированный обход выдаёт ключи по возрастанию: сначала всё меньшее, затем узел, затем всё большее. Таким образом, дерево поиска обеспечивает одновременно быстрый поиск, быструю вставку и перебор по порядку, а также поиск минимума, максимума и ближайшего ключа. Ни отсортированный массив, у которого вставка требует сдвига элементов, ни хеш-таблица, не хранящая порядка ключей, этого не обеспечивают. К рекурсивной вставке вернёмся на слайде о сбалансированности.

def is_bst(root, low=-inf, high=inf):
    if root is None:
        return True
    if not low < root.value < high:
        return False
    return (is_bst(root.left, low, root.value)
            and is_bst(root.right, root.value, high))

Изложение. Удаление узла из дерева поиска разбирается в задаче 5 главы и сводится к трём случаям. Сначала узел находится обычным спуском. Если у него нет потомков, он просто убирается, и ссылка родителя становится равной None. Если потомок один, он подвешивается на место удаляемого узла. Если потомков два, находится преемник — узел с наименьшим ключом в правом поддереве: шаг направо, затем налево, пока есть левый потомок. Преемник больше всех ключей левого поддерева и меньше остальных ключей правого, поэтому может занять место удаляемого узла; левого потомка у него нет, и вырезается он по первому или второму случаю. Спуск к узлу и спуск к преемнику вместе образуют один путь, поэтому удаление требует O(h). Задача 3 главы — проверка, является ли двоичное дерево деревом поиска, — позволяет разобрать характерную ошибку. Проверять только соседние узлы, то есть что левый потомок меньше узла, а правый больше, недостаточно. Рассмотрим правое дерево на рисунке: узел 6 больше своего родителя 3, и локально условие выполнено, однако он лежит в левом поддереве корня 5 и обязан быть меньше 5. Условие порядка глобально: каждый узел ограничен всеми предками. Поэтому функция is_bst передаёт вниз интервал допустимых значений (low, high): при переходе налево верхней границей становится ключ узла, при переходе направо — нижней. Альтернативный критерий — центрированный обход должен выдавать строго возрастающую последовательность. Обе проверки требуют O(n) времени.

Изложение. Цена любой операции дерева поиска определяется его высотой h, а высота зависит от порядка вставки. Если ключи поступают в случайном порядке, высота растёт логарифмически, но с множителем, заметно большим единицы. Если же вставить ключи 1, 2, 3, …, n по порядку, каждый новый ключ больше всех прежних и уходит направо: дерево вырождается в цепочку высоты n − 1, и все операции становятся линейными. В этом же вырожденном случае рекурсивная вставка главы делает по вызову на каждый уровень и уже на тысяче ключей исчерпывает предел глубины рекурсии Python; для таких деревьев вставку записывают циклом. Дерево называется сбалансированным, если его высота составляет O(log n) при любом порядке операций. Строгий вариант — условие АВЛ-дерева: у каждого узла высоты поддеревьев отличаются не больше чем на единицу, что даёт высоту не более примерно 1,44·log₂ n. Красно-чёрное дерево поддерживает более слабое условие и гарантирует h ≤ 2·log₂(n + 1). Оба дерева восстанавливают баланс после каждой вставки и удаления локальными перестройками — поворотами — за O(log n). К сбалансированным относятся и B-деревья индексов баз данных из лекции 13: узел-страница содержит сотни ключей, и миллиону строк достаточно трёх-четырёх уровней. На красно-чёрных деревьях построены TreeMap в Java и std::map в распространённых реализациях стандартной библиотеки C++. Изложение. Задача 4 главы спрашивает, сколько различных деревьев поиска можно построить из чисел от 1 до n. Выберем корнем число k. Тогда числа от 1 до k − 1 обязаны оказаться в левом поддереве, а от k + 1 до n — в правом, и каждое поддерево само является деревом поиска. Число деревьев из m последовательных чисел зависит только от m, поэтому получим рекуррентность C_n = Σ C_(k−1)·C_(n−k) по k от 1 до n с C_0 = 1: пустое дерево одно. Решением рекуррентности являются числа Каталана: 1, 1, 2, 5, 14, 42, … Они также считают правильные скобочные последовательности из n пар скобок и блуждания из 2n шагов ±1, которые не опускаются ниже нуля и заканчиваются в нуле, — пути Дика; без условия возврата в ноль получилось бы другое число, C(2n, n). Рекуррентность решается динамическим программированием за O(n²) операций и O(n) памяти, а замкнутая формула C(2n, n)/(n + 1) — за O(n) умножений; при n = 20 ответ равен 6 564 120 420. Вычисления необходимо вести в целых числах: функция math.comb и целочисленное деление // точны при любом n. Наивная формула через факториалы и деление / возвращает float с 53 битами мантиссы, и демонстрация покажет, при каком n это приводит к ошибке и в чём её причина.

Пояснение

Между левым и правым поддеревьями порядка нет: куча — не дерево поиска.

Изложение. Куча представляет собой структуру данных для задач, в которых требуется быстро находить максимум или минимум набора, меняющегося в процессе работы. В невозрастающей куче, max-heap, выполняется свойство кучи: ключ любого узла не меньше ключей его потомков, поэтому в корне всегда находится максимум; в min-heap, наоборот, в корне минимум. В отличие от дерева поиска, куча не упорядочивает элементы полностью: между левым и правым поддеревьями порядка нет. Взамен куча всегда остаётся почти полным двоичным деревом — все уровни, кроме последнего, заполнены целиком, а последний заполняется слева направо, — поэтому она не вырождается, и её высота равна ⌊log₂ n⌋. Почти полное дерево хранится без ссылок, в обычном массиве, с узлами, выписанными по уровням: у узла с индексом i потомки находятся в ячейках 2i + 1 и 2i + 2, а родитель — в ячейке ⌊(i − 1)/2⌋, так что для переходов по дереву достаточно арифметики индексов. Куча с рисунка, корень 9 с потомками 7 и 8, записывается массивом [9, 7, 8, 3, 1, 4]. Свойство кучи восстанавливают две операции просеивания. Просеивание вверх меняет элемент, дописанный в конец массива, местами с родителем, пока он больше родителя. Просеивание вниз меняет корень, ставший меньше потомков, местами с большим из них, пока свойство не восстановится. Обе операции проходят не больше одного пути от корня до листа и требуют O(log n).

Изложение. Приоритетная очередь, построенная на просеиваниях, представляет собой структуру, из которой элементы извлекаются в порядке приоритета, а не поступления: добавление требует O(log n), просмотр минимума — O(1), извлечение минимума, при котором последний элемент переставляется в корень и просеивается вниз, — O(log n). В Python куча реализована модулем heapq как min-heap над обычным списком: функции модуля принимают список и поддерживают в нём свойство кучи, а минимум всегда лежит в h[0]. Функция heapify превращает произвольный список в кучу за O(n), а не за O(n log n): она просеивает вниз внутренние узлы, начиная с последнего, и большинство узлов, лежащих у самого дна, опускаются лишь на один-два уровня. Если требуется куча на максимум, в версиях Python до 3.13 включительно в неё помещают ключи со знаком минус; начиная с Python 3.14 модуль содержит и функции для max-heap — heapify_max, heappush_max, heappop_max и другие. Функции nlargest и nsmallest отбирают k наибольших или наименьших элементов, поддерживая кучу из k элементов: каждый новый элемент сравнивается с корнем и при необходимости заменяет его, что требует O(n log k) времени и O(k) памяти вместо O(n log n) и O(n) у полной сортировки. Для физика это типичная операция: отбор десяти самых энергичных событий из миллиона, лучших кандидатов при реконструкции, ближайших соседей.

Пояснение

На практике медленнее быстрой сортировки: просеивание обращается к далёким ячейкам массива.

Изложение. Куча даёт ещё один способ сортировки за O(n log n) — пирамидальную сортировку. Она состоит из двух этапов. На первом массив превращается в max-heap: внутренние узлы просеиваются вниз, начиная с последнего и заканчивая корнем, что требует O(n). На втором n − 1 раз повторяется одно и то же: корень, текущий максимум, меняется местами с последним элементом неотсортированной части и встаёт на окончательное место, а новый корень просеивается вниз в укоротившейся куче. Каждое просеивание требует O(log n), поэтому сортировка выполняется за O(n log n) на любом входе — неудачных входов, как у быстрой сортировки, у неё нет, — и не требует дополнительной памяти, в отличие от сортировки слиянием. Платой служат неустойчивость, рассмотренная в лекции 17, и константа: просеивание обращается к далеко отстоящим ячейкам массива, кеш процессора используется хуже, и на массивах из 10⁵–10⁷ чисел пирамидальная сортировка в 2–5 раз медленнее std::sort. Изложение. Граф G = (V, E) состоит из множества вершин V и множества рёбер E, каждое из которых соединяет пару вершин; число вершин обозначим n, число рёбер — m. В неориентированном графе ребро не имеет направления: если из u можно попасть в v, то и обратно, как по дороге с двусторонним движением. В ориентированном графе ребро (u, v) не означает существования ребра (v, u): так устроены односторонние улицы, ссылки между веб-страницами и зависимости задач. Взвешенный граф приписывает каждому ребру число — длину пути, сопротивление проводника, пропускную способность канала, энергию связи. Вершины, соединённые ребром, называются смежными, а число рёбер, инцидентных вершине, — её степенью; в ориентированном графе различают входящую и исходящую степени. Путь представляет собой последовательность вершин, в которой соседние соединены рёбрами, а цикл — путь, начинающийся и заканчивающийся в одной вершине. Петля соединяет вершину с ней самой, а кратные рёбра — несколько рёбер между одной парой вершин. Дерево с этой точки зрения является связным неориентированным графом без циклов, у которого рёбер на одно меньше, чем вершин, а граф без циклов, не обязательно связный, называется лесом. Для физика

Реальные графы разрежены: у атома в молекуле единицы связей, у пикселя не больше восьми соседей.

Изложение. От способа хранения графа зависят объём памяти и цена операций. Матрица смежности представляет собой квадратную таблицу n × n, в которой на пересечении строки i и столбца j записана единица или вес ребра, если ребро из i в j существует, и ноль в противном случае; у неориентированного графа она симметрична. Матрица позволяет проверить наличие ребра за O(1), но требует O(n²) памяти независимо от числа рёбер, а перебор соседей вершины требует просмотра всей строки, O(n). Создавать её необходимо генератором списков: запись [[0] * n] * n даёт n ссылок на один и тот же список, и запись в одну строку изменит все строки одновременно. Список смежности хранит для каждой вершины список её соседей: памяти требуется O(n + m), перебор соседей занимает время, пропорциональное их числу, а платой служит проверка конкретного ребра за O(deg u). Третий способ — список рёбер, перечень пар вершин с весами: для обходов он неудобен, но подходит алгоритмам, перебирающим рёбра целиком, например алгоритму Краскала, и в таком виде граф обычно поступает на вход. Для плотного графа, где число рёбер сравнимо с n², применяют матрицу, для разреженного — списки. Реальные графы почти всегда разрежены: у атома в молекуле единицы связей, у пикселя детектора не больше восьми соседей, — поэтому по умолчанию выбирают списки смежности.

Сложность

O(n + m): вершины и рёбра — по одному разу

Пояснение

Компоненты связности — обход из каждой ещё не посещённой вершины.

Изложение. Обход графа представляет собой систематическое посещение всех вершин, достижимых из стартовой. В отличие от дерева, у графа есть циклы, поэтому обязательным элементом обхода становится множество посещённых вершин: без него обход зациклится. Поиск в глубину уходит из текущей вершины как можно дальше и, когда идти некуда, возвращается к последней развилке. Рекурсивная запись удобна, но на пути длиннее примерно тысячи вершин, например на цепочке из ста тысяч вершин, исчерпает предел рекурсии Python, поэтому DFS реализуют явным стеком. Одна и та же вершина попадает в стек несколько раз — от разных соседей, — и отсеивать её необходимо в момент снятия со стека, а не только перед добавлением. Соседей кладут в стек в обратном порядке, чтобы первым снимался первый из них: тогда явный стек обходит вершины в том же порядке, что и рекурсивная запись, — на графе со слайда определений с соседями по возрастанию это порядок 1 2 4 3 6 5, а без разворота получился бы порядок 1 3 6 5 4 2. Поиск в ширину использует очередь и посещает вершины по расходящимся кругам: сначала соседей старта, затем соседей соседей. Здесь вершину помечают в момент постановки в очередь, иначе она успеет попасть туда несколько раз. Таким образом, два обхода различаются контейнером — стеком или очередью — и моментом пометки вершины. Оба требуют O(n + m) времени: каждая вершина обрабатывается один раз, а каждое ребро просматривается один раз в ориентированном графе и дважды в неориентированном. Обход в ширину посещает вершины в порядке возрастания расстояния от старта и потому находит кратчайшие пути по числу рёбер. Компоненты связности находятся обходом из каждой ещё не посещённой вершины: всё, что собрал один запуск, составляет одну компоненту, а внешний цикл по вершинам лишь ищет стартовые точки и не делает алгоритм квадратичным.

Состояния системы и вероятности переходов между ними образуют взвешенный ориентированный граф марковской цепи. Разводка кабелей на установке, маршрут манипулятора, план эксперимента сводятся к задачам о кратчайшем пути и остовном дереве. def dijkstra(graph, start):     # веса w ≥ 0
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, v = heapq.heappop(heap)
        if d > dist[v]:
            continue            # устаревшая запись
        for u, w in graph[v]:
            if d + w < dist.get(u, inf):
                dist[u] = d + w     # релаксация
                heapq.heappush(heap, (d + w, u))
    return dist

Важно

Веса неотрицательны; при отрицательных — алгоритм Беллмана — Форда.

Изложение. В невзвешенном графе кратчайший путь по числу рёбер находит обход в ширину: он посещает вершины в порядке удаления от старта и, запоминая для каждой вершины расстояние и предка, позволяет восстановить путь проходом от конечной вершины по ссылкам на предков с последующим разворотом. Во взвешенном графе обход в ширину неприменим: путь из трёх лёгких рёбер может иметь меньшую суммарную длину, чем одно тяжёлое ребро. Здесь используется алгоритм Дейкстры, являющийся жадным. Алгоритм поддерживает оценки расстояний от старта и на каждом шаге выбирает ещё не обработанную вершину с наименьшей оценкой; при неотрицательных весах эта оценка уже окончательна, поскольку любой обходной путь через другие вершины не может оказаться меньше. Затем алгоритм пытается улучшить оценки соседей: если d(v) + w меньше текущей оценки соседа u, оценка уменьшается — эта операция называется релаксацией. Выбор вершины с наименьшей оценкой обеспечивает куча, и общая сложность составляет O(m log n). Реализация главы не уменьшает ключ записи, уже лежащей в куче, а при улучшении оценки кладёт в кучу новую запись и оставляет старую; при извлечении устаревшая запись, у которой расстояние больше текущей оценки, пропускается. Необходимо, чтобы веса были неотрицательными: иначе вершина, уже снятая с кучи, может получить лучшую оценку, и обоснование алгоритма вместе с оценкой сложности перестаёт выполняться. Для графов с отрицательными рёбрами применяют алгоритм Беллмана — Форда, который требует O(n·m) и обнаруживает циклы отрицательного веса.

def kahn(graph):                # {u: [v, ...]}
    indeg = {v: 0 for v in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] += 1
    queue = deque(v for v in graph if indeg[v] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                queue.append(v)
    if len(order) < len(graph):
        raise ValueError('цикл в зависимостях')
    return order

Изложение. Пусть ориентированный граф описывает зависимости: ребро u → v означает, что этап u необходимо выполнить раньше v. Компиляция модулей, установка пакетов, этапы обработки данных эксперимента ставят одну задачу — выстроить вершины в линию так, чтобы все рёбра шли слева направо. Такое упорядочение называется топологической сортировкой и существует тогда и только тогда, когда в графе нет циклов, то есть граф является ориентированным ациклическим (DAG). Первый способ основан на обходе в глубину: вершина добавляется в список после того, как обработаны все её потомки, а в конце список разворачивается. В таком виде он цикл не обнаруживает: на графе с циклом он без ошибки возвращает порядок, нарушающий одно из рёбер. Для проверки в обходе в глубину необходимо различать три цвета вершин: вершина, встреченная повторно, пока она ещё находится в обработке, означает цикл. Второй способ — алгоритм Кана — подсчитывает для каждой вершины число входящих рёбер, ставит в очередь вершины без входящих рёбер и, снимая вершину, уменьшает счётчики её соседей; соседи, чей счётчик обнулился, встают в очередь. Если в графе есть цикл, его вершины так и не получат нулевого счётчика, и упорядоченными окажутся не все вершины, — так алгоритм обнаруживает цикл без дополнительных средств. Оба способа требуют O(n + m). В стандартной библиотеке начиная с Python 3.9 есть класс graphlib.TopologicalSorter, который при цикле возбуждает исключение CycleError и сообщает вершины цикла. Отметим, что словарь, передаваемый TopologicalSorter, сопоставляет вершине её предшественников, то есть записывает рёбра в обратную сторону по сравнению со списками смежности функции kahn: тот же словарь без разворота дал бы обратный порядок без какой-либо ошибки.

Обход в глубину из главы, различающий три цвета вершин, выдаёт порядок от геометрии и выравнивания через сырые данные, пьедесталы и калибровку к кластерам, трекам, событиям, гистограммам и отчёту; проверка всех рёбер показывает ноль нарушенных зависимостей, и порядок graphlib также корректен. Затем в граф добавляется ошибочная зависимость треки → выравнивание: выравнивание детектора по трекам требует уже восстановленных треков, а восстановление треков — выполненного выравнивания, и образуется цикл. Обход в глубину без проверки цикла, то есть без трёх цветов, без какой-либо ошибки возвращает порядок из всех десяти этапов, в котором нарушено ребро выравнивание → треки: программа, выполняющая этапы в этом порядке, запустила бы восстановление треков без выравнивания. Обход главы с тремя цветами встречает вершину «треки», пока она ещё находится в обработке, и возбуждает исключение ValueError. Алгоритм Кана упорядочивает пять этапов из десяти и оставляет выравнивание, треки, события, гистограммы и отчёт — этапы, лежащие в цикле или зависящие от него. Класс graphlib.TopologicalSorter возбуждает исключение CycleError и называет цикл треки → выравнивание → треки. Таким образом, топологическая сортировка обязана проверять ацикличность графа, иначе противоречивые зависимости проходят незамеченными.

def kruskal(n, edges):           # edges: [(w, u, v)]
    parent = list(range(n))
    def find(x):                 # корень множества
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    total = 0
    for w, u, v in sorted(edges):    # по весу
        ru, rv = find(u), find(v)
        if ru != rv:             # не замыкает цикл
            parent[ru] = rv
            total += w
    return total

Для физика

В цепи m − n + 1 независимых контуров — столько ветвей остаётся вне остова.

Изложение. Остовным деревом связного графа называется подмножество рёбер, связывающее все n вершин и не содержащее циклов, то есть дерево из n − 1 рёбер. Минимальным называется остовное дерево с наименьшим суммарным весом; классическая постановка — соединить все узлы сети кабелем наименьшей длины. Два классических алгоритма жадные. Алгоритм Прима наращивает дерево из одной вершины: на каждом шаге добавляется самое лёгкое ребро, ведущее из построенной части наружу; с кучей он требует O(m log n) и по устройству совпадает с алгоритмом Дейкстры, только минимизируется вес одного ребра, а не расстояние от старта. Алгоритм Краскала сортирует все рёбра по весу и добавляет их по очереди, пропуская те, что замкнули бы цикл. Проверку на цикл выполняет система непересекающихся множеств (DSU): каждая вершина указывает на представителя своего множества, функция find поднимается к корню и попутно сокращает путь, а ребро соединяет две разные компоненты, только если корни его концов различны. Если вдобавок подвешивать меньшее дерево к большему (объединение по рангу или размеру), операции DSU выполняются амортизированно за O(α(n)), где α(n) — обратная функция Аккермана, не превышающая 4 при любом практически встречающемся n. Сложность определяется сортировкой рёбер, O(m log m). Если вес каждого ребра взять со знаком минус, тот же алгоритм найдёт максимальное остовное дерево; так решается задача 6 главы. Если граф несвязен, остовного дерева нет, и алгоритм Прима обнаруживает это по тому, что в дерево вошли не все вершины. Для физика остовное дерево связано с законами Кирхгофа: в цепи из n узлов и m ветвей рёбра остова образуют дерево без контуров, а каждая из m − n + 1 оставшихся ветвей замыкает ровно один независимый контур.

Изложение. Подведём итоги. Хеш-таблица обеспечивает поиск, вставку и удаление в среднем за O(1) при двух условиях: хеш-функция распределяет ключи равномерно, а коэффициент заполнения ограничен константой, что поддерживает перехеширование с амортизированной ценой O(1). Равномерность нарушается закономерностями в ключах — при остатке от деления на число, имеющее общие делители с шагом ключей, — и неудачным основанием полиномиального хеша: при q = 256 и R = 2³² хеш зависит лишь от четырёх последних символов. Встроенная функция hash() подмешивает к хешам строк случайную соль, поэтому порядок обхода множества строк меняется от запуска к запуску, и алгоритм, опирающийся на этот порядок, недетерминирован. Дерево поиска выполняет операции за O(h), а высота зависит от порядка вставки: при случайном порядке она логарифмическая с множителем 2–3, при упорядоченных ключах дерево вырождается в цепочку, и гарантию O(log n) дают только сбалансированные деревья. Куча выдаёт минимум за O(1) и позволяет отобрать k лучших элементов из n за O(n log k) с памятью O(k). Граф хранится списками смежности, а обходы в глубину и в ширину требуют O(n + m). Наконец, кратчайшие пути, топологический порядок и минимальное остовное дерево сводятся к обходам, дополненным кучей или системой непересекающихся множеств, причём топологическая сортировка обязана обнаруживать циклы.
