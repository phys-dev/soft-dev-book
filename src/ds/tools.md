# Инструменты: scikit-learn

Теорию разобрали — посмотрим, как всё перечисленное выглядит в коде. Практически всё классическое машинное обучение в Python делается одной библиотекой, устроенной вокруг единственного интерфейса.

[scikit-learn.org](https://scikit-learn.org/stable/)

Стандарт де-факто для классического машинного обучения в Python — библиотека **scikit-learn** (`sklearn`). Она построена поверх уже знакомых тебе NumPy, SciPy и Pandas и закрывает весь конвейер работы с данными:

```
датасет → разбиение → предобработка → обучение → метрики → подбор гиперпараметров → сохранение модели
```

Про сами NumPy и Pandas мы подробно говорили в главе [NumPy и pandas](../dev/python/numpy-and-pandas.md), а про построение графиков — в главе [Визуализация данных](../dev/python/visualization/practice.md), поэтому здесь займёмся собственно scikit-learn. Пройдём весь конвейер по шагам на одном сквозном примере — классификации сортов вина по химическому составу.

## Единый API: fit / predict / transform

Главная причина популярности scikit-learn — единообразный интерфейс. Все объекты библиотеки делятся на два типа:

* **Модели (estimators)** — то, что учится предсказывать: `KNeighborsClassifier`, `LinearRegression`, `RandomForestClassifier`, `MLPClassifier`...
* **Преобразователи (transformers)** — то, что преобразует данные: `StandardScaler`, `OneHotEncoder`, `PCA`...

И у тех, и у других одни и те же методы:

* `fit(X, y)` — обучение: модель подбирает параметры, преобразователь запоминает статистики (например, среднее и дисперсию каждого признака);
* `predict(X)` — предсказание меток для новых объектов (у моделей);
* `predict_proba(X)` — предсказание вероятностей классов (у классификаторов);
* `transform(X)` — преобразование данных (у преобразователей);
* `fit_transform(X)` — обучение и преобразование одним вызовом.

Благодаря этому замена одного алгоритма на другой — замена одной строки кода. kNN, случайный лес и нейронная сеть обучаются и вызываются совершенно одинаково. Все алгоритмы из [предыдущих](./ml.md) [глав](./nn.md) уже реализованы в scikit-learn, и наша задача — научиться их запускать.

## Используемые библиотеки

## Датасеты

В `sklearn.datasets` есть три семейства функций:

* `load_*` — маленькие учебные датасеты, встроенные в библиотеку: `load_iris`, `load_wine`, `load_breast_cancer`, `load_digits`;
* `fetch_*` — большие датасеты, которые скачиваются из интернета при первом обращении: `fetch_california_housing`, `fetch_openml`;
* `make_*` — генераторы синтетических данных для экспериментов: `make_classification`, `make_regression`, `make_blobs`.

Возьмём датасет **Wine** — 178 образцов вина трёх сортов (три класса), каждый описан 13 числовыми признаками химического состава: содержание алкоголя, яблочной кислоты, магния, фенолов, интенсивность цвета и так далее. Задача — по химическому анализу определить сорт винограда.

```python
# as_frame=True возвращает данные в виде pandas.DataFrame
wine = load_wine(as_frame=True)

data = wine.frame          # признаки + целевая переменная в одной таблице
X = wine.data              # матрица объекты-признаки, shape (178, 13)
y = wine.target            # метки классов: 0, 1, 2

print(data.shape)          # размерность
print(wine.target_names)   # названия сортов
data.head()                # первые пять строк — всегда смотри на данные глазами
```

## Разбиение выборки: train_test_split

Качество модели нельзя оценивать на тех же данных, на которых она обучалась, иначе мы измерим способность запоминать, а не обобщать. Поэтому первым делом откладываем тестовую выборку:

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,       # 20% объектов — в тест
    random_state=42,     # фиксируем случайность для воспроизводимости
    stratify=y,          # сохраняем соотношение классов в обеих частях
)
```

Параметр `stratify=y` важен при дисбалансе классов — он гарантирует, что доли классов в обучающей и тестовой выборках совпадают. Тестовую выборку до самого конца не трогаем, она изображает «новые» данные.

## Предобработка

### Масштабирование признаков

Как мы видели в главе про [классические алгоритмы](./ml.md), методы, основанные на расстояниях (kNN, k-means) и на градиентном спуске (линейные модели, нейронные сети), чувствительны к масштабу признаков. В датасете Wine магний измеряется десятками, а фенолы — единицами, поэтому признаки нужно стандартизировать:

```python
scaler = StandardScaler()

# обучаем scaler ТОЛЬКО на обучающей выборке...
X_train_scaled = scaler.fit_transform(X_train)

# ...а тест лишь преобразуем уже выученными статистиками
X_test_scaled = scaler.transform(X_test)
```

`StandardScaler` приводит каждый признак к нулевому среднему и единичной дисперсии. Есть и альтернативы: `MinMaxScaler` (минимакс-нормализация в диапазон [0, 1]), `RobustScaler` (устойчив к выбросам).

Важная деталь: `fit` вызывается только на train. Если обучить scaler на всей выборке, статистики теста «протекут» в обучение — это называется **утечкой данных** (data leakage) и приводит к завышенным оценкам качества.

### Кодирование категориальных признаков

В Wine все признаки числовые, но в реальных данных часто встречаются категориальные (тип детектора, режим установки). Модели работают с числами, поэтому категории нужно закодировать:

```python
from sklearn.preprocessing import OneHotEncoder, OrdinalEncoder

# OneHotEncoder: каждая категория -> отдельный бинарный признак
# подходит для номинальных признаков без порядка
encoder = OneHotEncoder(handle_unknown="ignore")

# OrdinalEncoder: категории -> целые числа 0, 1, 2, ...
# подходит для порядковых признаков (плохо/хорошо/отлично)
ordinal = OrdinalEncoder()
```

Чтобы применять разные преобразования к разным столбцам (числовые — масштабировать, категориальные — кодировать), используется `ColumnTransformer` из `sklearn.compose`.

## Обучение модели

Обучим два классификатора из [главы про классические алгоритмы](./ml.md) — метод ближайших соседей и случайный лес:

```python
# kNN: голосование K ближайших соседей, требует масштабирования
knn = KNeighborsClassifier(n_neighbors=5)
knn.fit(X_train_scaled, y_train)

# случайный лес: ансамбль деревьев, к масштабу нечувствителен
forest = RandomForestClassifier(n_estimators=200, random_state=42)
forest.fit(X_train, y_train)

# предсказания на тестовой выборке
y_pred_knn = knn.predict(X_test_scaled)
y_pred_forest = forest.predict(X_test)
```

Вся «магия» обучения — один вызов `fit`. Гиперпараметры модели (число соседей `n_neighbors`, число деревьев `n_estimators`) задаются в конструкторе.

## Pipeline

Пара `scaler + модель` — настолько частая связка, что для неё есть отдельный класс. `Pipeline` склеивает цепочку преобразований и финальную модель в один объект с тем же самым API:

```python
model = Pipeline(steps=[
    ("scaler", StandardScaler()),          # шаг 1: стандартизация
    ("knn", KNeighborsClassifier(n_neighbors=5)),  # шаг 2: классификатор
])

# fit сам обучит scaler на train и передаст преобразованные данные в kNN
model.fit(X_train, y_train)

# predict сам преобразует тест выученным scaler'ом и предскажет
y_pred = model.predict(X_test)
```

Pipeline решает сразу три задачи:

* код становится короче и его сложнее сломать;
* исключается утечка данных: преобразователи всегда обучаются только на train;
* весь конвейер можно передать в кросс-валидацию и подбор гиперпараметров как единое целое, а потом сохранить одним файлом.

## Метрики качества

### Классификация

Теорию метрик мы разбирали в [разделе про логистическую регрессию](./ml.md) — здесь просто вызываем готовые функции:

```python
print(f"Accuracy:  {accuracy_score(y_test, y_pred):.3f}")

# у нас три класса, поэтому указываем способ усреднения:
# average="macro" — среднее по классам без учёта их размера
print(f"Precision: {precision_score(y_test, y_pred, average='macro'):.3f}")
print(f"Recall:    {recall_score(y_test, y_pred, average='macro'):.3f}")
print(f"F1:        {f1_score(y_test, y_pred, average='macro'):.3f}")

# матрица ошибок: строки — истинные классы, столбцы — предсказанные
print(confusion_matrix(y_test, y_pred))

# сводный отчёт по всем метрикам для каждого класса
print(classification_report(y_test, y_pred, target_names=wine.target_names))
```

Напомню смысл метрик:

* **Accuracy** — доля правильных ответов; обманчива при дисбалансе классов;
* **Precision** — какая доля объектов, названных положительными, действительно положительная;
* **Recall** — какую долю реальных положительных объектов модель нашла;
* **F1** — гармоническое среднее Precision и Recall;
* **ROC-AUC** — площадь под ROC-кривой, качество ранжирования по вероятностям.

ROC-AUC считается по предсказанным вероятностям, а не по меткам; для многоклассовой задачи указывается стратегия «один против остальных»:

```python
y_proba = model.predict_proba(X_test)   # вероятности классов, shape (n, 3)
print(f"ROC-AUC: {roc_auc_score(y_test, y_proba, multi_class='ovr'):.3f}")
```

### Регрессия

Для задач регрессии функции те же по духу — сравниваем предсказанные числа с истинными. Классификация вина здесь не подойдёт, поэтому возьмём другой встроенный набор. По медицинским показателям пациента модель предсказывает, насколько заболевание продвинется за год.

```python
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import Ridge
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

# отдельные имена, чтобы не затереть сквозной пример с вином
X_reg, y_reg = load_diabetes(return_X_y=True)
X_reg_tr, X_reg_te, y_reg_tr, y_reg_te = train_test_split(
    X_reg, y_reg, test_size=0.2, random_state=42)

regressor = Ridge(alpha=1.0).fit(X_reg_tr, y_reg_tr)
y_pred = regressor.predict(X_reg_te)

mae = mean_absolute_error(y_reg_te, y_pred)   # средняя абсолютная ошибка
mse = mean_squared_error(y_reg_te, y_pred)    # среднеквадратичная ошибка
rmse = np.sqrt(mse)                       # корень из MSE, в единицах величины
r2 = r2_score(y_reg_te, y_pred)               # коэффициент детерминации R^2

print(f"MAE:  {mae:.1f}")
print(f"RMSE: {rmse:.1f}")
print(f"R^2:  {r2:.3f}")
```

    MAE:  46.1
    RMSE: 55.5
    R^2:  0.419

* **MAE** устойчивее к выбросам и измеряется в тех же единицах, что и целевая величина;
* **MSE** сильнее штрафует большие ошибки (квадратичный штраф);
* **R²** показывает, какую долю дисперсии данных объясняет модель: 1 — идеально, 0 — не лучше предсказания средним, меньше 0 — хуже среднего.

## Кросс-валидация

Одно разбиение train/test — одна случайная оценка качества. Надёжнее **кросс-валидация**. Выборка делится на \\(k\\) частей (фолдов), модель \\(k\\) раз обучается на \\(k-1\\) частях и проверяется на оставшейся, оценки усредняются.

```python
# стратифицированные фолды сохраняют соотношение классов
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# передаём Pipeline целиком — предобработка честно обучается внутри каждого фолда
scores = cross_val_score(model, X_train, y_train, cv=cv, scoring="f1_macro")

print(f"F1 по фолдам: {scores}")
print(f"Среднее: {scores.mean():.3f} +- {scores.std():.3f}")
```

    F1 по фолдам: [0.89355742 1.         0.96658312 0.92951496 0.96658312]
    Среднее: 0.951 +- 0.036


Разброс оценок по фолдам не менее важен, чем среднее. Большая дисперсия — признак нестабильной модели или слишком маленькой выборки.

## Подбор гиперпараметров: GridSearchCV

Гиперпараметры (число соседей \\(K\\), глубина деревьев, коэффициент регуляризации) модель не выучивает — их подбираем мы. `GridSearchCV` перебирает все комбинации из заданной сетки, оценивая каждую кросс-валидацией:

```python
param_grid = {
    "knn__n_neighbors": [1, 3, 5, 7, 9, 15],   # имя шага в Pipeline + "__" + имя параметра
    "knn__weights": ["uniform", "distance"],   # обычное или взвешенное голосование
}

search = GridSearchCV(
    model,                  # наш Pipeline: scaler + kNN
    param_grid,
    cv=cv,                  # схема кросс-валидации
    scoring="f1_macro",     # метрика для сравнения комбинаций
    n_jobs=-1,              # задействовать все ядра процессора
)

search.fit(X_train, y_train)

print(f"Лучшие параметры: {search.best_params_}")
print(f"Лучший CV F1: {search.best_score_:.3f}")

# лучшая модель уже переобучена на всём train — финальная проверка на тесте
best_model = search.best_estimator_
y_pred = best_model.predict(X_test)
print(f"F1 на тесте: {f1_score(y_test, y_pred, average='macro'):.3f}")
```

    Лучшие параметры: {'knn__n_neighbors': 15, 'knn__weights': 'uniform'}
    Лучший CV F1: 0.959
    F1 на тесте: 1.000


Тестовая выборка не участвовала ни в обучении, ни в подборе гиперпараметров — только в финальной оценке. Так и должен выглядеть протокол эксперимента. Если сетка большая, вместо полного перебора можно взять `RandomizedSearchCV` — случайный поиск по тем же параметрам.

## Сохранение модели: joblib

Обученную модель не нужно переобучать при каждом запуске — её сохраняют на диск. Для sklearn-моделей рекомендуют `joblib` (эффективнее pickle для объектов с большими NumPy-массивами внутри):

```python
import joblib

# сохраняем весь Pipeline: и scaler, и модель, одним файлом
joblib.dump(best_model, "wine_knn.joblib")

# ... позже, в другом скрипте или сервисе
loaded = joblib.load("wine_knn.joblib")
prediction = loaded.predict(X_test)   # сырые признаки — предобработка внутри
```

Загружай модели только из доверенных источников — как и pickle, joblib-файл при загрузке может выполнить произвольный код. И фиксируй версию scikit-learn в [requirements](../dev/python/requirements.md) — модель, сохранённая одной версией библиотеки, не обязана загружаться другой.
