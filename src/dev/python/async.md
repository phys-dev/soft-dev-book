# Итераторы, генераторы и корутины

Эта глава посвящена трём родственным механизмам языка, связанным одной идеей, которая состоит в том, чтобы **не вычислять всё сразу**. Итератор выдаёт элементы по одному, генератор умеет приостанавливать выполнение функции и возвращаться в неё, а корутина вдобавок умеет принимать значения снаружи.

Механизмы полезны сами по себе, поскольку позволяют обрабатывать файлы, не помещающиеся в память, и описывать бесконечные последовательности. Но главное в том, что на генераторах построена вся асинхронность Python. Разобравшись здесь, ты без труда поймёшь `asyncio` в главе про [асинхронность](../../perf/async.md).


## Итераторы

Итераторы относятся к фундаментальным концепциям Python, используемым ежедневно, часто без раздумий о том, как они работают. Любая коллекция в Python (списки, словари, множества, строки, файлы) итерируема.

Формально итератор — это объект с методом `__next__`, который на каждом вызове отдаёт следующий элемент, а когда элементы кончились, возбуждает `StopIteration`. Отдельно существует *итерируемый* объект, обладающий методом `__iter__`, возвращающим итератор. Разделение не формальность: список итерируем, но не является итератором, поэтому по нему можно пройти дважды, а по итератору лишь один раз.

Соберём свой аналог `range`, чтобы увидеть обе роли явно. Контейнер `Range` умеет только выдать итератор, а сам обход делает `RangeIterator`.

```python
class Range:
    def __init__(self, stop_value: int):
        self.stop_value = stop_value - 1

    def __iter__(self):
        return RangeIterator(self)

class RangeIterator:
    def __init__(self, container):
        self.container = container
        self.current = -1          # состояние обхода живёт здесь

    def __iter__(self):
        return self                # итератор обязан быть итерируемым

    def __next__(self):
        if self.current < self.container.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

Существенно, где лежит `current`: он в итераторе, а не в контейнере, и
поэтому каждый новый `for` начинает счёт заново, и по одному `Range(5)` можно
пройти сколько угодно раз. Положи счётчик в контейнер, и второй проход окажется
пустым, хотя выглядеть код будет почти так же. Метод `__iter__` у самого
итератора тоже не формальность, поскольку без него объект не итерируем, и `for` по нему
не пойдёт.

Чаще, впрочем, обе роли совмещают в одном классе, где `__iter__` возвращает `self`, и кода тогда меньше, но второй проход по такому объекту начнётся там, где закончился первый.

```python
class Range2:
    def __init__(self, stop_value: int):
        self.current = -1
        self.stop_value = stop_value - 1
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if self.current < self.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

Теперь видно, что делает обычный `for`, который берёт итератор через `iter`, дёргает `next` в цикле и ловит `StopIteration`, чтобы остановиться. Вот что разворачивается за привычной строчкой.

```python
iterable = Range2(5)
iterator = iter(iterable)

while True:
    try:
        value = next(iterator)
        print(value)
    except StopIteration:
        break
```

## Генераторы

Генераторы работают на принципе запоминания контекста выполнения функции с помощью ключевого слова `yield`.

Писать два класса ради простого перебора утомительно, и в языке есть короткий путь. Стоит поставить в функцию `yield`, и она перестаёт быть обычной функцией, и при вызове её тело не выполняется вовсе, вместо него возвращается генератор. Тело оживает только при `next`, доходит до ближайшего `yield`, отдаёт значение и **замирает**, сохранив все локальные переменные и место остановки.

В примере ниже это видно по трём вызовам, из которых первые два отдают значения, а третий натыкается на `return` и возбуждает `StopIteration`, положив в неё возвращённое значение.

```python
def simple_generator():
    yield 1
    yield 2
    return 3

gen = simple_generator()
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # StopIteration: 3
```

Есть и совсем краткая форма — генераторное выражение, которое отличается от списочной сборки круглыми скобками вместо квадратных, и разница принципиальна. Список из ста тысяч элементов, построенный целиком, займёт память, а генератор не вычислит ни одного элемента, пока его не попросят. В памяти это 800 килобайт против 200 байт.

```python
gen_exp = (x for x in range(100000))
print(gen_exp)  # <generator object <genexpr> at 0x...>
```

Когда генератор просто пересказывает элементы другого источника, цикл с `yield` записывают короче через `yield from`. Это не только сахар, так как конструкция пробрасывает наружу и отправляемые внутрь значения, что понадобится, как только генераторы начнут вкладываться друг в друга.

```python
numbers = [1, 2, 3]

# Стандартный подход
def func():
    for item in numbers:
        yield item

# Упрощенный подход
def func():
    yield from numbers
```

## Корутины

Корутины служат основными строительными блоками асинхронного программирования. Выросли они из генераторов и решают задачу не параллельного счёта, а ожидания, позволяя одному потоку заняться другим делом, пока текущая задача ждёт ответа от сети или диска.

Корутина переворачивает картину, ведь генератор только отдаёт значения наружу, а корутина умеет и **принимать** их. Выражение `deposit = (yield)` приостанавливает функцию и ждёт, пока снаружи вызовут `send`. Выходит диалог с функцией, сохраняющей между вопросами своё состояние.

Разберём на счёте сложных процентов. Коэффициент роста считается один раз при создании корутины, а дальше в неё можно бесконечно слать суммы вклада.

```python
import math
from typing import Generator

def cash_return_coro(percent: float,
                     years: int) -> Generator[float | None, float, None]:
    value = math.pow(1 + percent / 100, years)
    while True:
        try:
            deposit = (yield)
            yield round(deposit * value, 2)
        except GeneratorExit:
            print('Выход из корутины')
            raise

# Использование
coro = cash_return_coro(5, 5)
next(coro)
values = [1000, 2000, 5000, 10000, 100000]
for item in values:
    print(coro.send(item))
    next(coro)
coro.close()
```

## Что дальше

Мы разобрали механику. Итератор отдаёт элементы по одному, генератор приостанавливает функцию на `yield` и продолжает с того же места, корутина умеет ещё и принимать значения через `send()`.

На данном фундаменте и построена асинхронность в Python. Цикл событий представляет собой планировщик, переключающийся между приостановленными генераторами и отдающий процессорное время тому, кто готов работать, пока остальные ждут ответа от сети или диска. Как это устроено внутри и как этим пользоваться через `asyncio`, разбирается в главе про асинхронность в разделе «Ускоряем код».
