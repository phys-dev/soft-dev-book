# Объекты, память и управляющие конструкции в Python

Эта глава — о том, что происходит за именем переменной. Мы разберём, чем изменяемые объекты отличаются от неизменяемых и почему это различие всплывает в самых неожиданных местах, а заодно приведём в порядок условные конструкции и циклы. Многое здесь выглядит мелочью. Ровно до того дня, когда мелочь съест полдня отладки.

## Объекты в памяти

В Python **всё — объект**: и число, и строка, и функция, и сам класс. У любого объекта есть три вещи. Тип определяет, что с объектом можно делать (`int`, `str`, `list`). Значение — то, что в нём лежит (`42`, `"hello"`). И наконец, идентификатор — число, уникальное на всё время жизни объекта; в CPython это адрес объекта в памяти, а получить его можно функцией `id()`:

```python
s = "hello"
print(id(s))  # Выведет что-то вроде 4390213040
```

### Ссылки, а не копии

Переменная в Python не «содержит» объект — она на него ссылается. Поэтому присваивание одной переменной другой заводит второе имя для того же объекта, а данные остаются на месте. Изменив объект через одно имя, ты увидишь изменение и через второе:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)  # [1, 2, 3, 4] — изменился и a!
```

### Сравнение: `is` и `==`

Из этой картины следуют два разных вопроса, которые новички постоянно путают. `is` спрашивает, **один ли это объект**. `==` — **равны ли значения**. Два списка могут быть равны поэлементно и при этом оставаться разными объектами в памяти:

```python
x = [1, 2]
y = [1, 2]
print(x == y)  # True
print(x is y)  # False
```

#### Неочевидное поведение: кеширование целых чисел

При запуске интерпретатор заранее создаёт объекты для небольших целых чисел — в CPython это диапазон от −5 до 256. Все переменные с такими значениями ссылаются на один и тот же объект:

```python
a = 256
b = 256
print(a is b)  # True — это один и тот же закэшированный объект
```

Казалось бы, для 257 должно быть `False`. Но проверь сам — и результат зависит от того, **как** ты запускаешь код:

```python
c = 257
d = 257
print(c is d)
```

Запусти это файлом — получишь `True`. Введи те же три строки в интерактивной оболочке — получишь `False`.

Дело тут не в кеше чисел. Работает компилятор: Python компилирует файл целиком, складывает все константы блока в общую таблицу и одинаковые значения хранит в ней один раз, поэтому `c` и `d` получают ссылку на одну и ту же константу. В интерактивной оболочке каждая строка компилируется отдельно, общей таблицы нет, и создаются два разных объекта.

Сама история — курьёз, а вот следствие из неё серьёзное. **Тождественность объектов — деталь реализации, на которую нельзя опираться.** Она зависит от версии интерпретатора, от способа запуска и даже от того, лежат ли строки в одной функции.

> 💡 **Золотое правило**: используй `==` для сравнения значений, а `is` — только для проверки на `None`, `True` и `False`.

## Изменяемые и неизменяемые объекты

Это главное деление в мире объектов Python, и запомнить его придётся наизусть.

### Неизменяемые (immutable)

К неизменяемым относятся `int`, `float`, `str`, `tuple`, `bytes` и `bool`. Однажды созданные, они остаются такими навсегда. Любая «модификация» на самом деле создаёт новый объект, а старое имя переставляют на него. Проще всего убедиться по идентификатору — после `+=` он другой:

```python
s = "hello"
print(id(s))
s += "!"
print(id(s))  # ID изменился — это новый объект!
```

### Изменяемые (mutable)

`list`, `dict` и `set`, наоборот, меняются на месте. Список после `append` остаётся тем же самым объектом, у него лишь стало на один элемент больше, и все, кто на него ссылался, увидят добавленный элемент:

```python
lst = [1, 2]
print(id(lst))
lst.append(3)
print(id(lst))  # ID остался прежним
```

### Неочевидный нюанс: кортежи с изменяемыми элементами

Неизменяемость кортежа распространяется только на него самого. Кортеж хранит ссылки, и неизменны как раз они — подставить в ячейку другой объект нельзя. А сам объект, на который ссылка ведёт, о запрете ничего не знает:

```python
t = ([1, 2], [3, 4])
t[0].append(3)
print(t)  # ([1, 2, 3], [3, 4]) — это допустимо!
```

Отсюда практическое ограничение. Такой кортеж нельзя положить в множество или использовать как ключ словаря: хеш кортежа складывается из хешей его элементов, а у списка хеша нет. Попытка кончится `TypeError: unhashable type: 'list'`.

## Строки и байты

Два неизменяемых типа, которые постоянно путают между собой. Развести их надо сразу и раз навсегда.

### Строки (str)

`str` хранит текст — последовательность символов Unicode. Длина строки измеряется в символах, а не в байтах, и один символ может быть каким угодно: латинской буквой, кириллической, иероглифом, значком эмодзи. Как эти символы разложены в памяти, тебя не касается — это забота интерпретатора.

### Байты (bytes)

`bytes` хранит сырые данные, то есть последовательность чисел от 0 до 255. То самое, что лежит в файле, приходит по сети или считывается с прибора. Никакого понятия «символ» здесь нет, только числа. Тип тоже неизменяемый; изменяемый его вариант называется `bytearray`.

Между этими двумя мирами нет автоматического перехода — нужна кодировка, которая говорит, каким набором байтов записан каждый символ. Отсюда пара методов. `encode` превращает текст в байты, `decode` — обратно:

```python
text = "привет"
encoded = text.encode('utf-8')  # str -> bytes
decoded = encoded.decode('utf-8')  # bytes -> str
```

Кириллица в UTF-8 занимает по два байта на символ, так что `len(text)` даст 6, а `len(encoded)` — 12. Почти все `UnicodeDecodeError` растут отсюда — байты читают не в той кодировке, в которой записали.

## Условные конструкции

### Базовый синтаксис

Ветвление в Python обходится без скобок и фигурных скобок: условие, двоеточие, блок с отступом.

```python
temperature = 15
if temperature > 20:
    print("Наденьте футболку")
else:
    print("Лучше взять куртку")
```

### Элегантные проверки

В условии не обязательно писать явное сравнение — любой объект сам по себе истинен или ложен. Пустая строка, пустой список, ноль и `None` ложны, всё остальное истинно. Поэтому `if name:` читается как «если имя вообще есть» и заменяет громоздкое `if name != "":`

```python
name = input("Введите имя: ")
if name:  # False, если строка пустая
    print(f"Привет, {name}!")
else:
    print("Привет, незнакомец!")
```

### Современный `match` (Python 3.10+)

Когда одну переменную нужно сравнить с десятком значений, лестница из `elif` становится нечитаемой. На такой случай есть `match` — аналог `switch` из других языков. Ветви перебираются сверху вниз, вертикальная черта объединяет несколько вариантов в один случай, а `case _` ловит всё остальное:

```python
http_status = 404
match http_status:
    case 200 | 201:
        print("Успех")
    case 401 | 403 | 404:
        print("Ошибка клиента")
    case 500 | 503:
        print("Ошибка сервера")
    case _:
        print("Неизвестный статус")
```

> 💡 **Совет**: бери `match`, когда сравниваешь одну переменную с несколькими значениями. Для сложных условий оставайся с `if/elif/else`.

## Циклы

### `while`

`while` повторяет тело, пока условие истинно. Он нужен там, где число итераций заранее неизвестно, — например, пока значение не выйдет за границу:

```python
i = 1
while i < 1000:
    print(i)
    i *= 2
```

### `for` и `range`

`for` в Python перебирает не индексы, а элементы. Чтобы получить привычный счётчик, элементы ему поставляет `range`: с одним аргументом он отсчитывает от нуля, с тремя — задаёт начало, границу и шаг. Правая граница в `range` не входит в диапазон:

```python
for i in range(5):      # 0, 1, 2, 3, 4
    print(i)

for i in range(1, 10, 2):  # 1, 3, 5, 7, 9
    print(i)
```

### `enumerate` для получения индекса

Когда вместе с элементом нужен и его номер, заводить отдельную переменную-счётчик не надо: `enumerate` выдаёт пары «индекс, элемент», которые распаковываются прямо в заголовке цикла.

```python
for idx, char in enumerate("abc"):
    print(f"Индекс: {idx}, Символ: {char}")
```

### Неочевидный трюк: `else` в циклах

У циклов в Python есть ветка `else`, которой нет почти нигде больше. Она выполняется, если цикл завершился **естественно** — то есть перебрал всё до конца и ни разу не наткнулся на `break`. Готовый каркас для поиска: в теле цикла ищешь и выходишь по `break`, а в `else` пишешь ветку «не нашли».

```python
for i in range(5):
    if i == 10:
        break
else:
    print("Цикл завершился без break")
```

## Производительность при работе со строками

Теперь вернёмся к неизменяемости строк и посмотрим, во что она обходится на практике.

Каждое `+=` для строки создаёт новый объект и копирует в него всё, что было накоплено раньше. На сотой итерации копируется сто символов, на стотысячной — сто тысяч; в сумме получается квадратичное время вместо линейного:

```python
result = ""
for _ in range(100000):
    result += "a"  # Создаёт новый объект на каждой итерации!
```

Правильно — копить куски в списке и склеить их один раз. Список изменяем, `append` ничего не копирует, а `join` заранее считает итоговую длину, выделяет память один раз и переносит туда все части:

```python
parts = []
for _ in range(100000):
    parts.append("a")
result = "".join(parts)  # Быстрое объединение
```

> 💡 **Совет**: для частых операций конкатенации используй `list` + `join()` для строк или `bytearray` для байтов.

## Сборка мусора

Память в Python освобождается сама, и делают это два механизма.

Основной — **подсчёт ссылок**. У каждого объекта есть счётчик: сколько имён и контейнеров на него смотрят. Как только счётчик падает до нуля, объект уничтожается немедленно. Быстро, предсказуемо, и в большинстве программ ничего сверх этого не нужно.

У подсчёта ссылок есть слепое пятно — циклы. Если объекты ссылаются друг на друга, их счётчики никогда не обнулятся, даже когда до них уже нельзя добраться из программы:

```python
a = []
b = [a]
a.append(b)  # Теперь a и b ссылаются друг на друга
del a, b     # Объекты недостижимы, но ссылки остались
```

Для таких случаев есть второй механизм — **поколенческий сборщик мусора**. Он запускается периодически, находит «острова» из взаимно ссылающихся объектов, до которых больше не дотянуться, и удаляет их целиком. Поколенческий он потому, что молодые объекты проверяет часто, а пережившие несколько проверок — редко: статистика говорит, что долгоживущий объект скорее всего проживёт ещё.

## Неочевидные особенности Python

### 1. Изменяемые аргументы по умолчанию

Самая известная ловушка языка, и растёт она прямо из деления объектов на изменяемые и неизменяемые. Значение по умолчанию считается **один раз**, когда интерпретатор доходит до строчки `def`. Дальше список живёт между вызовами и копит всё, что в него положили:

```python
def append_to(element, target=[]):  # так делать нельзя!
    target.append(element)
    return target

print(append_to(1))  # [1]
print(append_to(2))  # [1, 2] — тот же список!
```

Лекарство одно. По умолчанию ставят `None`, а настоящий пустой список заводят уже внутри функции — заново на каждом вызове.

```python
def append_to(element, target=None):
    if target is None:
        target = []
    target.append(element)
    return target
```

### 2. Ленивые логические операторы

`and` и `or` вычисляют правую часть только тогда, когда без неё не обойтись. Если левый операнд `and` ложен, результат уже известен, и правая часть не вычисляется вовсе. Отсюда идиома «сначала проверь, потом лезь». Строчка `if xs and xs[0] > 0` не упадёт на пустом списке.

```python
def expensive_call():
    print("Вызов выполнен!")
    return True

# expensive_call() не будет вызвана, т.к. первое условие False
if False and expensive_call():
    pass
```

### 3. Атрибуты функций

Раз всё в Python — объект, то и функция тоже объект, которому можно приписать произвольный атрибут. Выглядит как забава, а на этом держатся декораторы, которые считают вызовы или кешируют результат прямо на себе:

```python
def my_func():
    pass

my_func.custom_attr = 42
print(my_func.custom_attr)  # 42
```

## Заключение

Вся глава держится на одной фразе. Переменная — имя, привязанное к объекту, а не коробка со значением. Отсюда и общий список после двух присваиваний, и накопительный аргумент по умолчанию, и квадратичное время сборки строки через `+=`.

Четыре правила придётся выучить наизусть:

- `is` — только для `None`, `True` и `False`; во всех остальных случаях `==`.
- Строки собирай через `join`, а не через `+=` в цикле.
- Значение по умолчанию не должно быть изменяемым объектом — ставь `None`.
- Прежде чем передать объект в чужую функцию, спроси себя, изменяем он или нет.
