# Функции в Python

Функция — первый инструмент борьбы со сложностью: она позволяет спрятать кусок логики за именем и дальше о нём не думать. Синтаксис `def` ты наверняка уже знаешь, поэтому здесь мы пойдём глубже.

Разберём, как Python обходится с аргументами (а он умеет заметно больше, чем «передать по порядку»), где живут переменные и по какому правилу интерпретатор их ищет, чем распаковка отличается от обычного присваивания и какие ловушки подстерегают в значениях по умолчанию.

## Синтаксис объявления функций

### Базовый синтаксис

Имя функции в Python может содержать буквы, цифры и символ подчёркивания `_`, но не может начинаться с цифры:

```python
def foo():
    return 42

foo()  # возвращает 42
```

**Важно:** оператор `return` не обязателен. Если его нет, функция возвращает `None`:

```python
def foo():
    42

print(foo())  # выводит None
```

### Документирование функций

Для документирования используются строковые литералы (docstring):

```python
def foo():
    """I return 42."""
    return 42
```

Документация доступна через атрибут `__doc__` или функцию `help()`:

```python
print(foo.__doc__)  # 'I return 42.'
help(foo)           # показывает документацию
```

## Работа с аргументами

### Позиционные и именованные аргументы

Аргументы можно передавать двумя способами, и они свободно смешиваются. Позиционные разбираются по порядку, именованные — по имени параметра, поэтому для них порядок роли не играет:

```python
def min(x, y):
    return x if x < y else y

min(-5, 12)        # -5
min(x=-5, y=12)    # -5
min(y=12, x=-5)    # -5 (порядок не важен)
```

Правило одно: позиционные аргументы идут первыми. Написать `min(x=-5, 12)` не получится — интерпретатор не поймёт, к какому параметру относится `12`.

### Упаковка позиционных аргументов

Для работы с произвольным количеством аргументов используется `*args`. Звёздочка перед именем параметра означает: собери все лишние позиционные аргументы в кортеж и передай его под этим именем.

```python
def min(*args):
    res = float("inf")
    for arg in args:
        if arg < res:
            res = arg
    return res

min(-5, 12, 13)  # -5
min()            # inf
```

Обрати внимание на вызов без аргументов: `args` оказывается пустым кортежем, цикл не выполняется ни разу, и функция возвращает начальное значение. Часто это не то, чего хочется: минимума у пустого набора нет. Чтобы гарантировать хотя бы один аргумент, его выносят в отдельный обязательный параметр перед `*args`:

```python
def min(first, *args):
    res = first
    for arg in args:
        if arg < res:
            res = arg
    return res

min()  # TypeError: missing required argument 'first'
```

### Распаковка аргументов

Звёздочка работает и в обратную сторону: в месте вызова она разбирает готовую последовательность на отдельные аргументы. Годится любой итерируемый объект — список, кортеж, множество, генератор:

```python
xs = {-5, 12, 13}
min(*xs)           # -5
min(*[-5, 12, 13]) # -5
min(*(-5, 12, 13)) # -5
```

### Ключевые аргументы и значения по умолчанию

Всё, что записано в объявлении **после** `*args`, можно передать только по имени — позиции для этих параметров уже кончились. Так делают необязательные настройки: у них есть разумное значение по умолчанию, а если вызывающий его меняет, то делает это явно и читаемо.

```python
def bounded_min(first, *args, lo=float("-inf"), hi=float("inf")):
    res = hi
    for arg in (first,) + args:
        if arg < res and lo < arg < hi:
            res = arg
    return max(res, lo)

bounded_min(-5, 12, 13, lo=0, hi=255)  # 12
```

Из трёх чисел в границы `[0, 255]` попадают 12 и 13, минимальное из них — 12; значение −5 отброшено как выходящее за нижнюю границу.

### Опасность изменяемых значений по умолчанию

Значение по умолчанию вычисляется один раз, когда интерпретатор читает строку `def`, а не при каждом вызове. Для числа или строки это незаметно, но изменяемый объект окажется общим для всех вызовов и будет копить состояние между ними:

```python
def unique(iterable, seen=set()):
    acc = []
    for item in iterable:
        if item not in seen:
            seen.add(item)
            acc.append(item)
    return acc

xs = [1, 1, 2, 3]
unique(xs)  # [1, 2, 3]
unique(xs)  # [] 😱
```

Второй вызов на тех же данных возвращает пустой список: множество `seen` уже содержит все числа с прошлого раза. Лечится это всегда одинаково — в объявлении ставят `None`, а настоящее пустое множество создают внутри функции, то есть заново на каждом вызове:

```python
def unique(iterable, seen=None):
    seen = set(seen or [])  # None - falsy значение
    acc = []
    for item in iterable:
        if item not in seen:
            seen.add(item)
            acc.append(item)
    return acc

xs = [1, 1, 2, 3]
unique(xs)  # [1, 2, 3]
unique(xs)  # [1, 2, 3] ✅
```

### Только ключевые аргументы

Можно требовать, чтобы некоторые аргументы передавались только по имени:

```python
def flatten(xs, *, depth=None):
    pass

flatten([1, [2], 3], depth=1)  # ✅
flatten([1, [2], 3], 1)        # TypeError
```

### Упаковка ключевых аргументов

Две звёздочки делают с именованными аргументами то же, что одна с позиционными: собирают все неопознанные в словарь. Точно так же они работают и в вызове, раскладывая словарь по именам параметров. Поэтому набор настроек удобно хранить отдельно и передавать целиком:

```python
def runner(cmd, **kwargs):
    if kwargs.get("verbose", True):
        print("Logging enabled")

runner("mysqld", limit=42)                    # ✅
runner("mysqld", **{"verbose": False})        # ✅
options = {"verbose": False}
runner("mysqld", **options)                   # ✅
```

## Распаковка и присваивание

### Базовая распаковка

Распаковка не привязана к функциям — она работает в любом присваивании. Слева пишут структуру из имён, справа — итерируемый объект, и Python раскладывает второе по первому. Форма слева может повторять вложенность справа:

```python
x, y, z = [1, 2, 3]           # ✅
x, y, z = {1, 2, 3}           # ✅ (но порядок не гарантирован!)
x, y, z = "xyz"               # ✅

# Распаковка вложенных структур
rectangle = (0, 0), (4, 4)
(x1, y1), (x2, y2) = rectangle
```

Случай с множеством стоит отметить особо: код отработает, но какое число попадёт в `x`, не определено — порядка у множества нет. Так писать нельзя.

### Расширенная распаковка (Python 3.0+)

Звёздочка слева от знака равенства собирает «всё остальное» в список. Помеченное имя может стоять в любом месте — в начале, в конце или в середине; Python сначала раздаёт значения обычным именам, а что осталось, отдаёт звёздочке:

```python
first, *rest = range(1, 5)           # first=1, rest=[2, 3, 4]
first, *rest, last = range(1, 5)     # first=1, rest=[2, 3], last=4

# Можно использовать в любом месте
*_, (first, *rest) = [range(1, 5)] * 5
```

Помеченное имя может получить и пустой список, а вот обычные имена должны получить по значению. Если значений не хватает даже на них, будет ошибка:

```python
first, *rest, last = [42]  # ValueError
```

### Распаковка в цикле for

Заголовок цикла — тоже присваивание, поэтому распаковка работает и там. Элементы могут быть разной длины: обычные имена возьмут своё, звёздочка подберёт остаток.

```python
for a, *b in [range(4), range(2)]:
    print(b)
# Вывод:
# [1, 2, 3]
# [1]
```

## Области видимости (Scopes)

### Функции внутри функций

Функции в Python — объекты первого класса: их можно определять внутри других функций, передавать в аргументах и возвращать как результат. Ничего особенного в `def` внутри `def` нет — это обычное присваивание, просто локальное:

```python
def wrapper():
    def identity(x):
        return x
    return identity

f = wrapper()
f(42)  # 42
```

### Правило LEGB

Раз области видимости вкладываются друг в друга, нужно правило, по какому имени какая победит. Интерпретатор ищет имя в четырёх областях по порядку и останавливается на первой найденной:

- **L**ocal (локальная) — имена внутри самой функции.
- **E**nclosing (объемлющая) — имена объемлющей функции, если эта вложена в другую.
- **G**lobal (глобальная) — имена уровня модуля.
- **B**uilt-in (встроенная) — то, что доступно всегда: `len`, `print`, `min`.

```python
min = 42  # global

def f(*args):
    min = 2  # enclosing
    def g():
        min = 4  # local
        print(min)
```

Здесь три разных `min`, и они не конфликтуют: `g` печатает свой, локальный. Убери из `g` строку с присваиванием, и печататься начнёт `min` из `f`; убери её и оттуда — доберёмся до глобальной 42. Пример заодно показывает, почему переменные не стоит называть именами встроенных функций: последнее звено цепочки, встроенный `min`, оказывается недоступным.

### Замыкания и позднее связывание

Имя, которое функция не определяет сама, разрешается не в момент объявления функции, а **в момент вызова**. Это называется поздним связыванием, и вот его прямое следствие: `f` ниже вообще не знает, откуда возьмётся `i` — просто на каждом вызове смотрит, что лежит под этим именем сейчас.

```python
def f():
    print(i)

for i in range(4):
    f()
# Вывод:
# 0
# 1
# 2
# 3
```

Здесь никакого замыкания ещё нет: `i` — обычное глобальное имя. **Замыкание** возникает, когда вложенная функция пользуется именем из объемлющей и продолжает пользоваться им после того, как та завершилась:

```python
def make_adder(step):
    def add(x):
        return x + step      # step взят из объемлющей функции
    return add

add5 = make_adder(5)
print(add5(10))                          # 15
print(add5.__closure__[0].cell_contents) # 5 — значение живёт в замыкании
```

Функция `make_adder` давно вернулась, её локальные переменные должны были исчезнуть, но `step` жив, потому что на него ссылается `add`. Именно на этом механизме построены декораторы из следующей главы.

Позднее связывание и замыкания вместе дают классическую ловушку. Функции, созданные в цикле, захватывают **переменную**, а не её значение, и после цикла все разом видят последнее:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])          # [2, 2, 2], а не [0, 1, 2]

funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])          # [0, 1, 2]
```

Во второй строке значение фиксируется аргументом по умолчанию: он, в отличие от тела функции, вычисляется сразу при её создании.

### Присваивание и области видимости

Есть важная асимметрия: читать имя можно из любой внешней области, а вот присваивание всегда создаёт **локальную** переменную. Причём решение принимается при компиляции функции и распространяется на всё её тело — поэтому `min += 1` падает не на присваивании, а на попытке прочитать локальную `min`, которой ещё не присвоили значения:

```python
min = 42

def f():
    min += 1  # UnboundLocalError!
    return min
```

### Оператор global

Чтобы менять глобальную переменную, а не заводить одноимённую локальную, о намерении надо заявить явно:

```python
min = 42

def f():
    global min
    min += 1
    return min

f()  # 43
f()  # 44
```

Заявлять приходится нарочно и многословно, и это сделано специально. Функция, которая правит глобальное состояние, тем самым перестаёт быть предсказуемой: её результат зависит от того, сколько раз её звали раньше. Пользуйся `global` только там, где без него никак.

### Оператор nonlocal (Python 3+)

`nonlocal` делает то же самое, но для объемлющей функции, а не для модуля. Это единственный способ дать вложенной функции менять переменную той, в которую она вложена, и на нём держатся счётчики и накопители внутри декораторов:

```python
def cell(value=None):
    def get():
        return value
    def set(update):
        nonlocal value
        value = update
    return get, set

get, set = cell()
set(42)
get()  # 42
```

Получилась ячейка памяти: две функции разделяют одну переменную `value`, которая живёт ровно столько, сколько живут они сами. Снаружи до неё не добраться никак — только через `get` и `set`. По сути это объект с приватным полем, собранный из одних функций.

## Функциональное программирование

### Анонимные функции (lambda)

Иногда функция нужна ровно на одну строчку — передать в `sorted` или в `map`, и придумывать ей имя незачем. Для таких случаев есть `lambda`: она задаёт функцию выражением, а не блоком. Тело у неё всегда одно выражение, и его значение и становится результатом, без всякого `return`:

```python
lambda arguments: expression

# Эквивалентно:
def <lambda>(arguments):
    return expression
```

Список параметров у лямбды такой же богатый, как у обычной функции, — со звёздочками и значениями по умолчанию:

```python
lambda x: x ** 2
lambda foo, *args, bar=None, **kwargs: 42
```

Ограничение в одно выражение поставлено намеренно. Как только логика перестаёт помещаться в строку, это уже не деталь вызова, а самостоятельный кусок программы — ему пора дать имя через `def`. По этой же причине PEP 8 запрещает присваивать лямбду переменной: `f = lambda x: ...` ничем не лучше `def f(x): ...`, но теряет имя в трассировке ошибки.

### Функции map, filter, zip

Три встроенные функции покрывают три самые частые операции над последовательностью — преобразовать каждый элемент, отобрать нужные, идти по нескольким наборам одновременно. Все три ничего не вычисляют сразу: они возвращают ленивый объект, поэтому в примерах результат обёрнут в `list`.

`map` применяет функцию к каждому элементу:

```python
list(map(lambda x: x % 7, [1, 9, 16, -1, 2, 5]))  # [1, 2, 2, 6, 2, 5]
```

`filter` оставляет только те элементы, для которых функция вернула истину. У него есть особый режим: если вместо функции передать `None`, фильтр отсеет всё, что ложно само по себе, — нули, пустые коллекции, пустые строки:

```python
list(filter(lambda x: x % 2 != 0, range(10)))  # [1, 3, 5, 7, 9]

# С None - оставляет только truthy значения
xs = [0, None, [], {}, set(), "", 42]
list(filter(None, xs))  # [42]
```

`zip` идёт по нескольким последовательностям параллельно и на каждом шаге отдаёт кортеж из их элементов. Останавливается он по самой короткой — лишние элементов длинных просто теряются, и об этом стоит помнить:

```python
list(zip("abc", range(3), [42j, 42j, 42j]))
# [('a', 0, 42j), ('b', 1, 42j), ('c', 2, 42j)]
```

### Генераторы коллекций

Всё то же самое можно записать выразительнее — через генераторы. Форма читается как фраза: «взять `x ** 2` для каждого `x` из `range(10)`, если `x` нечётно». Второй пример показывает ту же операцию через `map` и `filter` — сравни, насколько он тяжелее для глаза. А два `for` подряд разворачивают вложенную структуру в плоский список; порядок их такой же, как во вложенных циклах.

```python
[x ** 2 for x in range(10) if x % 2 == 1]  # [1, 9, 25, 49, 81]

# Эквивалент с map/filter:
list(map(lambda x: x ** 2, filter(lambda x: x % 2 == 1, range(10))))

# Вложенные генераторы:
nested = [range(5), range(8, 10)]
[x for xs in nested for x in xs]  # [0, 1, 2, 3, 4, 8, 9]
```

Тот же синтаксис работает для множеств и словарей — меняются только скобки. Фигурные скобки с одним выражением дают множество (обрати внимание, как в первом примере схлопнулись одинаковые остатки), а с парой через двоеточие — словарь:

```python
{x % 7 for x in [1, 9, 16, -1, 2, 5]}  # {1, 2, 5, 6}

date = {'year': 2014, "month": "September", "day": ""}
{k: v for k, v in date.items() if v}  # {'year': 2014, 'month': 'September'}

{x: x ** 2 for x in range(4)}  # {0: 0, 1: 1, 2: 4, 3: 9}
```

Во втором примере условие `if v` отбрасывает записи с пустым значением — тот же приём с истинностью объектов, что и в `filter(None, ...)`.

## PEP 8: стиль кода

Код читают чаще, чем пишут, и общий стиль экономит время всем. PEP 8 — официальное соглашение о том, как выглядит питоновский код; его понимает любой линтер, и спорить о скобках после него не приходится.

### Базовые рекомендации

- 4 пробела для отступов
- Максимум 79 символов в строке кода
- `lower_case_with_underscores` для переменных и функций
- `UPPER_CASE_WITH_UNDERSCORES` для констант

### Выражения и операторы

Правила ниже — не вкусовщина, у каждого есть причина. Пробелы вокруг операторов расставляют по приоритету, чтобы структура выражения была видна глазом. Тело `if` всегда переносят на новую строку: однострочник тяжелее заметить при беглом чтении и невозможно поставить на нём точку останова. Сравнение пишут в естественном порядке «переменная — значение», а отрицание принадлежности — оператором `not in`, а не через `not ... in`.

```python
exp = -1.05
value = (item_value / item_count) * offset / exp

if bar:
    x += 1

if method == 'md5':
    pass

if key not in d:
    pass
```

Ниже — те же четыре конструкции, записанные так, как делать не стоит:

```python
if bar: x += 1

if 'md5' == method:
    pass

if not key in d:
    pass
```

### Функции

Отдельное соглашение есть про строки документации. Первая строка — короткое описание в одно предложение, потом пустая строка, потом при необходимости подробности. Кавычки тройные даже у однострочника: если описание разрастётся, менять их не придётся.

```python
def something_useful(arg, **options):
    """One-line summary.

    Optional longer description.
    """
    pass
```

## Резюме

- Функции принимают произвольное количество позиционных (`*args`) и ключевых (`**kwargs`) аргументов
- Синтаксис распаковки работает в вызовах функций, присваивании и циклах
- Имена ищутся по правилу LEGB: локальная, объемлющая, глобальная, встроенная область
- Присваивание создаёт локальную переменную; изменить это можно через `global` и `nonlocal`
- Значение по умолчанию вычисляется один раз, поэтому изменяемым оно быть не должно
- Python поддерживает элементы функционального программирования: lambda, map, filter, zip, генераторы коллекций
- PEP 8 описывает, как должен выглядеть читаемый код, и его проверяют линтеры
