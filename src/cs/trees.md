# Деревья

В предыдущих главах мы работали с линейными структурами данных: в массиве, связном списке, стеке и очереди элементы выстроены друг за другом, как вагоны поезда. Но далеко не все данные устроены так просто. Файловая система на твоём диске, структура HDF5-файла с результатами измерений, иерархия объёмов детектора в Geant4, дерево вызовов функций в профилировщике — всё это иерархии. Для их описания есть отдельная структура данных — дерево.

С деревьями мы уже негласно встречались. В главе про рекурсию дерево вариантов помогало понять генерацию последовательностей из нулей и единиц, а сортировку слиянием мы рисовали как дерево рекурсивных вызовов. Теперь познакомимся с деревьями как с полноценной структурой данных.

## Что такое дерево

**Дерево** — это набор узлов (вершин), соединённых рёбрами, в котором:

* есть один выделенный узел — **корень** (англ. root);
* у каждого узла, кроме корня, ровно один **родитель** (англ. parent);
* от корня до любого узла можно дойти по рёбрам, причём ровно одним способом.

Забегая в следующую главу: дерево — это связный граф без циклов. Программисты, в отличие от ботаников, рисуют деревья корнем вверх: корень наверху, ветви растут вниз.

Основная терминология:

* **потомки** (дети) узла — узлы, для которых он является родителем;
* **лист** (англ. leaf) — узел без потомков;
* **внутренний узел** — узел, у которого есть хотя бы один потомок;
* **поддерево** — узел вместе со всеми его потомками, потомками потомков и так далее; каждый узел можно рассматривать как корень собственного поддерева;
* **глубина узла** — число рёбер на пути от корня до узла (у корня глубина 0);
* **уровень** — множество узлов одной глубины;
* **высота дерева** — наибольшая глубина среди всех узлов.

Обрати внимание: глубину и высоту иногда измеряют не в рёбрах, а в узлах — тогда все значения на единицу больше. Оба соглашения встречаются в литературе, поэтому в задачах всегда уточняй, что именно считается. Ниже, в разборе задачи про максимальную глубину, мы будем считать её именно в узлах — так требует условие.

Рекурсивность — главное свойство дерева. Дерево состоит из корня и поддеревьев, каждое из которых само является деревом. Поэтому почти все алгоритмы на деревьях естественно записываются рекурсивно: обработай корень и рекурсивно обработай его поддеревья. Базовый случай — пустое дерево. Всё, что мы обсуждали в главе про рекурсию, здесь заработает в полную силу.

## Двоичные деревья и класс Node

**Двоичное (бинарное) дерево** — дерево, в котором у каждого узла не больше двух потомков, причём они различаются: **левый** и **правый**. Двоичные деревья особенно важны: на них строятся деревья поиска и кучи, а любое дерево общего вида можно свести к двоичному.

В Python узел дерева удобно описывать классом со ссылками на потомков — так же, как мы описывали элемент связного списка, только ссылок теперь две:

```python
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value  # данные, хранящиеся в узле
        self.left = left    # ссылка на левого потомка (или None)
        self.right = right  # ссылка на правого потомка (или None)
```

Соберём небольшое дерево:

```
      5
     / \
    3   8
   / \
  1   4
```

```python
root = Node(5, Node(3, Node(1), Node(4)), Node(8))
```

Всё дерево представлено одной ссылкой на корень: зная корень, можно добраться до любого узла. Пустое дерево — это просто `None`. Именно поэтому функции, работающие с деревьями, принимают корень и первым делом проверяют, не равен ли он `None`, — это и есть базовый случай рекурсии.

## Обходы дерева

Обойти дерево — значит побывать в каждом узле ровно один раз. В отличие от массива, где порядок обхода очевиден, у дерева есть несколько естественных порядков. Все они делятся на два семейства: обходы в глубину (DFS, англ. depth-first search) и обход в ширину (BFS, англ. breadth-first search).

### Обходы в глубину

Обход в глубину сначала уходит по ветке до самого низа и только потом возвращается. Рекурсивная реализация тривиальна, а три классических варианта отличаются лишь моментом, когда мы обрабатываем сам узел относительно его поддеревьев:

```python
def preorder(root):        # корень -> левое -> правое
    if root is None:
        return
    print(root.value)      # обрабатываем узел до потомков
    preorder(root.left)
    preorder(root.right)


def inorder(root):         # левое -> корень -> правое
    if root is None:
        return
    inorder(root.left)
    print(root.value)      # обрабатываем узел между потомками
    inorder(root.right)


def postorder(root):       # левое -> правое -> корень
    if root is None:
        return
    postorder(root.left)
    postorder(root.right)
    print(root.value)      # обрабатываем узел после потомков
```

Для дерева с картинки выше `preorder` напечатает `5 3 1 4 8`, `inorder` — `1 3 4 5 8`, а `postorder` — `1 4 3 8 5`.

Каждый вариант полезен по-своему. Pre-order подходит для копирования и сериализации дерева (сначала создаём узел, потом его потомков). Post-order — для удаления и для вычислений «снизу вверх», когда результат в узле зависит от результатов в поддеревьях: так вычисляют высоту, размер поддеревьев, значение арифметического выражения по его дереву. In-order, как мы вскоре увидим, выдаёт элементы дерева поиска в отсортированном порядке.

### Обход в ширину

Обход в ширину идёт по уровням: сначала корень, затем все узлы глубины 1, затем глубины 2 и так далее. Рекурсией здесь не обойтись — нужна очередь, знакомая нам по главе о базовых структурах:

```python
from collections import deque


def level_order(root):
    if root is None:
        return
    queue = deque([root])
    while queue:
        node = queue.popleft()      # берём узел из начала очереди
        print(node.value)
        if node.left:               # и ставим его потомков в конец
            queue.append(node.left)
        if node.right:
            queue.append(node.right)
```

Для того же дерева получится `5 3 8 1 4` — ровно по уровням. Любой обход посещает каждый узел один раз и проходит по каждому ребру дважды, поэтому все они работают за \\( O(n) \\), где \\( n \\) — число узлов. Дополнительная память — \\( O(h) \\) на стек рекурсии у DFS (где \\( h \\) — высота дерева) и до \\( O(n) \\) на очередь у BFS (самый широкий уровень).

## Двоичное дерево поиска

**Двоичное дерево поиска** (англ. binary search tree, BST) — двоичное дерево, в каждом узле которого выполняется свойство порядка: все значения в левом поддереве строго меньше значения узла, а все значения в правом — строго больше.

Это свойство превращает поиск в аналог двоичного поиска по отсортированному массиву. Сравнили искомый ключ с корнем: меньше — идём налево, больше — направо. На каждом шаге спускаемся на уровень ниже, отбрасывая целое поддерево:

```python
def find(root, key):
    while root is not None and root.value != key:
        root = root.left if key < root.value else root.right
    return root  # узел с ключом key или None, если ключа нет
```

Вставка устроена так же: спускаемся, как при поиске, и подвешиваем новый узел на место, где упёрлись в `None`:

```python
def insert(root, key):
    if root is None:
        return Node(key)          # нашли свободное место
    if key < root.value:
        root.left = insert(root.left, key)
    elif key > root.value:
        root.right = insert(root.right, key)
    return root                   # ключ уже есть — ничего не меняем
```

Поиск, вставка и удаление стоят \\( O(h) \\) — мы проходим один путь от корня вниз. А in-order-обход дерева поиска выдаёт ключи по возрастанию: сначала всё меньшее (левое поддерево), потом узел, потом всё большее. Получается структура, которая одновременно поддерживает быстрый поиск, вставку, удаление и перебор в отсортированном порядке — то, чего не умеют ни отсортированный массив (медленная вставка), ни хеш-таблица (нет порядка).

### Сбалансированность

Вся эффективность BST держится на высоте \\( h \\). Если вставлять ключи в случайном порядке, дерево получается «кустистым» и \\( h \approx \log_2 n \\). Но если вставить ключи 1, 2, 3, ..., n по порядку, каждый новый узел уйдёт направо, и дерево выродится в связный список высотой \\( n \\). Все операции станут линейными.

Дерево называется **сбалансированным**, если у каждого узла высоты левого и правого поддеревьев отличаются не больше чем на единицу. У сбалансированного дерева \\( h = O(\log n) \\), а значит, все операции работают за \\( O(\log n) \\).

Заставить дерево оставаться сбалансированным при любых вставках и удалениях можно — для этого придуманы самобалансирующиеся деревья (АВЛ-дерево, красно-чёрное дерево), которые после каждой операции делают небольшие локальные перестройки — повороты. Именно они прячутся за `std::map` в C++ и `TreeMap` в Java, о которых мы упоминали в главе про хеш-таблицы. В стандартной библиотеке Python дерева поиска нет — обычно хватает `dict`, `set` и модуля `bisect` для отсортированного списка.

## Куча

**Куча** (англ. heap) — структура данных для задач, где нужно быстро находить максимум (или минимум) меняющегося набора элементов. В **невозрастающей куче** (max-heap) выполняется основное свойство кучи: значение любого узла не меньше значений его потомков. Значит, в корне всегда лежит максимум. В min-heap всё наоборот — в корне минимум.

В отличие от дерева поиска, куча не упорядочивает элементы полностью — между левым и правым поддеревом никакого порядка нет. Взамен куча обходится **почти полным** двоичным деревом: все уровни, кроме последнего, заполнены целиком, а последний заполняется слева направо. Такое дерево не бывает вырожденным, его высота всегда \\( O(\log n) \\).

### Куча в массиве

Почти полное дерево можно хранить без всяких ссылок — в обычном массиве, выписав узлы по уровням:

```
Куча:                Массив:

      9              [9, 7, 8, 3, 1, 4]
     / \              0  1  2  3  4  5
    7   8
   / \  /
  3  1 4
```

Индексы связаны простой арифметикой: у узла с индексом \\( i \\) потомки лежат в ячейках \\( 2i + 1 \\) и \\( 2i + 2 \\), а родитель — в ячейке \\( \lfloor (i-1)/2 \rfloor \\). Никаких классов и указателей: любой массив уже готов стать деревом.

Держится куча на двух операциях «просеивания»:

* **просеивание вверх** (sift up): новый элемент дописывается в конец массива и меняется местами с родителем, пока он больше родителя;
* **просеивание вниз** (sift down): если корень стал меньше потомков, он меняется местами с бóльшим из них и опускается, пока свойство кучи не восстановится.

Оба просеивания проходят не больше одного пути от корня до листа, то есть стоят \\( O(\log n) \\). На них строится **приоритетная очередь**: добавить элемент — \\( O(\log n) \\), посмотреть максимум — \\( O(1) \\), извлечь максимум (переставить последний элемент в корень и просеять вниз) — \\( O(\log n) \\).

В Python куча реализована модулем `heapq` — это min-heap поверх обычного списка:

```python
import heapq

distances = [5.2, 1.1, 3.7, 0.4]
heapq.heapify(distances)          # превращает список в кучу за O(n)
heapq.heappush(distances, 2.6)    # добавление за O(log n)
print(heapq.heappop(distances))   # 0.4 — минимум, за O(log n)
```

Если нужен max-heap, есть стандартный трюк: хранить в куче элементы с обратным знаком. Он ещё пригодится нам в следующей главе — в алгоритме построения остовного дерева.

### Пирамидальная сортировка

Куча даёт ещё один способ сортировать за \\( O(n \log n) \\) — **пирамидальную сортировку** (англ. heap sort). Идея в два этапа:

1. Превратить массив в max-heap, просеяв вниз все внутренние узлы от последнего к корню.
2. Повторять \\( n - 1 \\) раз: обменять корень (текущий максимум) с последним элементом неотсортированной части и просеять новый корень вниз. Максимумы один за другим встают в конец массива на свои окончательные места.

В отличие от сортировки слиянием, heap sort не требует дополнительной памяти — всё происходит в исходном массиве. В отличие от быстрой сортировки, у него нет плохих входов: любой массив обрабатывается за \\( O(n \log n) \\). Платить за это приходится неустойчивостью и несколько большей константой — на практике heap sort обычно чуть медленнее quick sort. Полную реализацию мы разберём ниже в задачах.

## Деревья в физических задачах

Деревья в вычислительной физике — не абстракция, а рабочий инструмент. Вот три типичных сюжета.

**Поиск соседей и k-d деревья.** В молекулярной динамике, методе SPH или при кластеризации экспериментальных точек постоянно нужно отвечать на вопрос: какие частицы находятся рядом с данной? Перебор всех пар стоит \\( O(N^2) \\). **k-d дерево** (k-dimensional tree) рекурсивно делит пространство плоскостями пополам, так что запрос «ближайшие соседи точки» выполняется в среднем за \\( O(\log N) \\). В SciPy оно уже реализовано:

```python
import numpy as np
from scipy.spatial import KDTree

points = np.random.rand(100_000, 3)      # частицы в единичном кубе
tree = KDTree(points)                    # построение за O(N log N)

dist, idx = tree.query(points[0], k=10)          # 10 ближайших соседей
neighbors = tree.query_ball_point(points[0], r=0.05)  # все соседи в радиусе
```

**Гравитационная задача N тел и октодеревья.** Прямое суммирование сил между \\( N \\) телами требует \\( O(N^2) \\) операций на шаг — для галактики из миллиардов звёзд это безнадёжно. Алгоритм Барнса — Хата строит **октодерево** (англ. octree): куб пространства рекурсивно делится на 8 октантов, пока в каждом листе не останется по частице. Для далёкой группы частиц незачем суммировать вклады по одной — достаточно одного слагаемого от её суммарной массы в центре масс, который хранится в узле дерева. Критерий простой: если угловой размер ячейки \\( s/d \\) меньше порога \\( \theta \\), ячейка не раскрывается. Сложность падает до \\( O(N \log N) \\), и именно такие деревья (вместе с более хитрым быстрым мультипольным методом) работают внутри современных астрофизических кодов вроде GADGET.

**Иерархические данные.** Формат HDF5, стандарт де-факто для больших численных данных, устроен как дерево: группы содержат подгруппы и датасеты, как каталоги и файлы. Деревом является и геометрия детектора в Geant4 (объёмы, вложенные в объёмы), и символьное выражение в SymPy — там узлы это операции, а листья — переменные и константы. Когда встречаешь иерархию, знай: под капотом почти наверняка дерево и рекурсивные обходы из этой главы.

## Разбор задач

Разберём несколько классических задач о деревьях. Во всех задачах, где на вход подаётся корень дерева, используется класс `Node`, описанный выше. Попробуй сначала решить каждую задачу самостоятельно — все они собраны в [тренажёре](https://contest.yandex.ru/contest/24809/problems/).

### Задача 1. Максимальная глубина

**Условие.** Дан корень двоичного дерева. Найди его максимальную глубину — наибольшее число узлов на пути от корня до листа (включая корень и лист).

**Идея решения.** Задача рекурсивна по построению: глубина дерева — это глубина более глубокого из поддеревьев плюс один (сам корень). Базовый случай — пустое дерево глубины 0.

```python
def max_depth(root):
    # Базовый случай: пустое дерево не добавляет к глубине ничего
    if root is None:
        return 0
    # Более глубокое из поддеревьев плюс сам корень
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

**Сложность.** По времени — \\( O(n) \\): каждый узел посещается один раз. По памяти — \\( O(h) \\) на стек рекурсии, где \\( h \\) — высота дерева.

### Задача 2. Сбалансированное дерево

**Условие.** Определи, сбалансировано ли двоичное дерево: у каждого узла высоты левого и правого поддеревьев должны отличаться не больше чем на единицу.

**Идея решения.** Напрашивается лобовое решение: для каждого узла посчитать высоты поддеревьев функцией из предыдущей задачи и сравнить. Но тогда высота каждого узла будет вычисляться заново на каждом уровне выше него, и в худшем случае получится \\( O(n^2) \\).

Лучше совместить оба вычисления в одном обходе. Пусть функция возвращает высоту поддерева, а если поддерево несбалансировано — специальное значение-сигнал `-1`, которое немедленно передаётся наверх без дальнейших проверок.

```python
def check_height(root):
    """Высота поддерева или -1, если оно несбалансировано."""
    if root is None:
        return 0

    left = check_height(root.left)
    if left == -1:                 # слева уже нашли дисбаланс
        return -1

    right = check_height(root.right)
    if right == -1:                # справа уже нашли дисбаланс
        return -1

    if abs(left - right) > 1:      # дисбаланс в текущем узле
        return -1

    return 1 + max(left, right)


def is_balanced(root):
    return check_height(root) != -1
```

**Сложность.** По времени — \\( O(n) \\): один post-order-обход, высота каждого узла вычисляется ровно один раз. По памяти — \\( O(h) \\) на стек рекурсии.

### Задача 3. Дерево поиска

**Условие.** Проверь, является ли двоичное дерево деревом поиска: значения в левом поддереве каждого узла строго меньше значения узла, в правом — строго больше.

**Идея решения.** Частая ошибка — проверять только соседние узлы: `left.value < node.value < right.value`. Такой локальной проверки недостаточно:

```
Дерево поиска:        Не дерево поиска:
      5                     5
     / \                   / \
    3   8                 3   8
   / \                   / \
  1   4                 1   6
```

В правом дереве узел 6 больше своего родителя 3 — локально всё хорошо. Но 6 находится в левом поддереве корня 5, а значит, обязан быть меньше 5. Условие глобальное: каждый узел ограничен всеми своими предками.

Будем спускаться по дереву и передавать вниз интервал допустимых значений \\( (\text{low}, \text{high}) \\). Уходя налево, ужесточаем верхнюю границу значением узла, уходя направо — нижнюю.

```python
def is_bst(root, low=float('-inf'), high=float('inf')):
    if root is None:
        return True
    # Значение узла обязано лежать строго внутри интервала предков
    if not (low < root.value < high):
        return False
    return (is_bst(root.left, low, root.value)      # слева всё < root.value
            and is_bst(root.right, root.value, high))  # справа всё > root.value
```

Есть и изящная альтернатива: сделать in-order-обход и проверить, что значения идут строго по возрастанию, — для дерева поиска это критерий.

**Сложность.** По времени — \\( O(n) \\), по памяти — \\( O(h) \\) на стек рекурсии.

### Задача 4. Сколько существует деревьев поиска

**Условие.** Сколько различных двоичных деревьев поиска можно построить из всех чисел от 1 до \\( n \\)? Число \\( n \\) не превосходит 20.

**Идея решения.** Выберем корнем число \\( k \\). Тогда числа \\( 1, \dots, k-1 \\) обязаны попасть в левое поддерево, а \\( k+1, \dots, n \\) — в правое, и каждое из поддеревьев — само дерево поиска. Число деревьев из \\( m \\) последовательных чисел зависит только от \\( m \\), поэтому получаем рекуррентность

\\[ C_n = \sum_{k=1}^{n} C_{k-1} \, C_{n-k}, \qquad C_0 = 1. \\]

Это знаменитые **числа Каталана** — они же считают правильные скобочные последовательности и одномерные случайные блуждания, не опускающиеся ниже нуля. Для них известна замкнутая формула

\\[ C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{n! \, (n+1)!}. \\]

```python
from math import comb


def count_bst(n):
    # Число Каталана: C(2n, n) / (n + 1), деление всегда нацело
    return comb(2 * n, n) // (n + 1)
```

Если формулу не помнишь, ответ считается и по рекуррентности — динамическим программированием:

```python
def count_bst_dp(n):
    counts = [1] + [0] * n           # counts[0] = 1: пустое дерево одно
    for size in range(1, n + 1):
        for root in range(1, size + 1):
            # root - 1 чисел уходит налево, size - root — направо
            counts[size] += counts[root - 1] * counts[size - root]
    return counts[n]
```

Важно работать с целыми числами: наивное `fac(2*n) / (fac(n) * fac(n+1))` через вещественное деление начнёт терять точность — `float` хранит лишь около 16 значащих цифр, а \\( C_{20} = 6\,564\,120\,420 \\) уже требует точного ответа.

**Сложность.** Формула с биномиальным коэффициентом — \\( O(n) \\) умножений; вариант с динамикой — \\( O(n^2) \\) операций и \\( O(n) \\) памяти.

### Задача 5. Удаление узла из дерева поиска

**Условие.** Дано дерево поиска с уникальными целыми ключами. Удали узел с заданным ключом так, чтобы дерево осталось корректным деревом поиска, и верни корень изменённого дерева. Если ключа нет — верни дерево без изменений. Создавать новые узлы нельзя, сложность должна быть \\( O(h) \\).

**Идея решения.** Сначала спускаемся к удаляемому узлу, как при обычном поиске. Дальше три случая:

1. У узла нет потомков — просто убираем его (родитель начинает ссылаться на `None`).
2. Один потомок — подвешиваем потомка на место удаляемого узла.
3. Два потомка — находим **преемника**: минимальный узел правого поддерева (идём направо, затем налево до упора). Преемник больше всего левого поддерева и меньше всего остального правого, поэтому может законно встать на место удаляемого узла. Вырезаем его со старого места (у него нет левого потомка, так что это случай 1 или 2) и переставляем.

```python
def remove(root, key):
    if root is None:                     # ключа в дереве нет
        return None

    if key < root.value:                 # ищем слева
        root.left = remove(root.left, key)
    elif key > root.value:               # ищем справа
        root.right = remove(root.right, key)
    else:                                # нашли узел с ключом key
        if root.left is None:            # случаи 1 и 2: нет левого потомка
            return root.right
        if root.right is None:           # случай 2: нет правого потомка
            return root.left

        # Случай 3: ищем преемника — минимум правого поддерева
        parent, succ = root, root.right
        while succ.left is not None:
            parent, succ = succ, succ.left

        # Вырезаем преемника со старого места...
        if parent.left is succ:
            parent.left = succ.right
        else:
            parent.right = succ.right

        # ...и ставим его на место удаляемого узла
        succ.left = root.left
        succ.right = root.right
        return succ

    return root
```

**Сложность.** По времени — \\( O(h) \\): спуск к узлу и спуск к преемнику вместе образуют один путь от корня вниз. По памяти — \\( O(h) \\) на рекурсию поиска (её несложно переписать циклом до \\( O(1) \\)).

### Задача 6. Пирамидальная сортировка

**Условие.** По результатам соревнования дан список участников: логин, число решённых задач \\( P \\) и штраф \\( F \\). Отсортируй таблицу результатов: выше стоит тот, у кого больше решённых задач; при равенстве — тот, у кого меньше штраф; если и штрафы равны — тот, чей логин идёт раньше по алфавиту. Кучу нужно реализовать самостоятельно, встроенными сортировками и `heapq` пользоваться нельзя.

```
Ввод:                  Вывод:
5                      gena
alla 4 100             timofey
gena 6 1000            alla
gosha 2 90             gosha
rita 2 90              rita
timofey 4 80
```

**Идея решения.** Это задача на сортировку по составному ключу — вспомни раздел про сортировку по ключу из главы о сортировках. Подберём ключ так, чтобы обычное сравнение кортежей «меньше» означало «выше в таблице»: число решённых задач берём с минусом (больше задач — меньше ключ), штраф и логин — как есть:

```python
def sort_key(user):
    login, solved, penalty = user
    return (-solved, penalty, login)
```

Остаётся отсортировать массив по этому ключу пирамидальной сортировкой. Строим max-heap прямо в исходном массиве, затем раз за разом переставляем максимум (худшего из оставшихся участников) в конец неотсортированной части:

```python
def sift_down(items, start, end):
    """Просеивает элемент start вниз внутри items[start:end + 1]."""
    root = start
    while True:
        child = 2 * root + 1               # левый потомок
        if child > end:                    # потомков нет — дно кучи
            break
        # Из двух потомков выбираем большего
        if child + 1 <= end and sort_key(items[child]) < sort_key(items[child + 1]):
            child += 1
        if sort_key(items[root]) < sort_key(items[child]):
            items[root], items[child] = items[child], items[root]
            root = child                   # спускаемся за элементом дальше
        else:
            break                          # свойство кучи восстановлено


def heap_sort(items):
    n = len(items)
    # Этап 1: строим кучу — просеиваем все внутренние узлы справа налево
    for start in range((n - 2) // 2, -1, -1):
        sift_down(items, start, n - 1)
    # Этап 2: снимаем максимум с вершины кучи в конец массива
    for end in range(n - 1, 0, -1):
        items[0], items[end] = items[end], items[0]
        sift_down(items, 0, end - 1)


def main():
    n = int(input())
    users = []
    for _ in range(n):
        login, solved, penalty = input().split()
        users.append((login, int(solved), int(penalty)))

    heap_sort(users)

    print('\n'.join(user[0] for user in users))


if __name__ == '__main__':
    main()
```

После этапа 1 максимальный (по нашему ключу — худший) участник стоит в корне кучи, то есть в ячейке 0. Обмен с последним элементом ставит его на окончательное место, а однократное просеивание вниз восстанавливает кучу в укоротившейся части массива. В итоге массив отсортирован по возрастанию ключа — лучшие участники в начале.

**Сложность.** Построение кучи — \\( O(n) \\) (низкие узлы просеиваются на маленькую глубину), затем \\( n - 1 \\) просеиваний по \\( O(\log n) \\). Итого \\( O(n \log n) \\) по времени в худшем случае и \\( O(1) \\) дополнительной памяти — сортировка происходит на месте. В боевом коде, конечно, достаточно `sorted(users, key=sort_key)` — но теперь ты знаешь, что могло бы происходить у него внутри.

## Резюме

* Дерево — рекурсивная структура: корень и поддеревья, каждое из которых само дерево. Базовый случай алгоритмов — пустое дерево `None`.
* Обходы в глубину (pre-, in-, post-order) пишутся рекурсией, обход в ширину — очередью; все стоят \\( O(n) \\).
* Дерево поиска даёт поиск, вставку и удаление за \\( O(h) \\); чтобы \\( h \\) была \\( O(\log n) \\), дерево должно быть сбалансированным.
* Куча — почти полное дерево в массиве: максимум за \\( O(1) \\), вставка и извлечение за \\( O(\log n) \\); на ней строятся приоритетная очередь и heap sort.
* В физических расчётах деревья ускоряют поиск соседей (k-d деревья), задачу N тел (октодеревья Барнса — Хата) и организуют иерархические данные (HDF5).

В следующей главе мы уберём у дерева ограничения — разрешим циклы и произвольные связи — и получим самую общую структуру данных: граф.
