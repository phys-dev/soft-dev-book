# Деревья

В предыдущих главах мы работали с линейными структурами данных: в массиве, связном списке, стеке и очереди элементы выстроены друг за другом, как вагоны поезда. Но далеко не все данные устроены так просто. Файловая система на твоём диске, структура HDF5-файла с записанными результатами измерений, иерархия объёмов детектора в Geant4, дерево вызовов, собранное профилировщиком, устроены как иерархии. Для их описания существует отдельная структура данных, дерево.

С деревьями мы уже негласно встречались. В главе про рекурсию дерево вариантов помогало понять генерацию последовательностей, составленных из нулей и единиц, а сортировку слиянием мы рисовали как дерево вызовов, порождённых рекурсией. Теперь познакомимся с деревьями как с полноценной структурой данных, у которой есть свой интерфейс и своя цена операций.

## Что такое дерево

**Деревом** называют набор узлов (вершин), соединённых рёбрами, в котором выполнены три условия:

* есть один выделенный узел, **корень** (англ. root);
* у каждого узла, кроме корня, в точности один **родитель** (англ. parent);
* от корня до любого узла можно дойти по рёбрам, причём единственным способом, ведущим туда.

И ещё, забегая в следующую главу. Дерево представляет собой связный граф, не содержащий циклов. А рисуют его программисты, в отличие от ботаников, корнем вверх.

Основная терминология:

* **потомками** (детьми) узла называют узлы, которым он приходится родителем;
* **листом** (англ. leaf) называется узел, не обременённый потомками;
* **внутренний узел** имеет хотя бы одного потомка;
* **поддерево** составляют узел вместе со всеми его потомками, потомками потомков и так далее; каждый узел можно считать корнем собственного поддерева, подвешенного под ним;
* **глубина узла** равна числу рёбер, пройденных на пути от корня до узла (у корня глубина 0);
* **уровень** объединяет узлы одной глубины;
* **высота дерева** равна наибольшей глубине, найденной среди всех узлов.

Сделаем оговорку. Глубину и высоту иногда измеряют не в рёбрах, а в узлах, и тогда все числа, получаемые на выходе, на единицу больше. Оба соглашения встречаются в литературе, поэтому в задачах всегда уточняй, что именно считается. Ниже, в разборе задачи про максимальную глубину, мы будем считать её в узлах, как требует условие, записанное там.

Главное свойство дерева состоит в его рекурсивности. Дерево складывается из корня и поддеревьев, каждое из которых само дерево. Поэтому почти все алгоритмы, написанные для деревьев, естественно записываются рекурсивно и сводятся к тому, чтобы обработать корень, а затем рекурсивно обработать его поддеревья. Базовый случай, как водится, пустое дерево. Всё, обсуждавшееся в главе про рекурсию, здесь заработает в полную силу.

## Двоичные деревья и класс Node

**Двоичным (бинарным) деревом** называют дерево, в котором у каждого узла не больше двух потомков, различимых как **левый** и **правый**. Двоичные деревья особенно важны, ведь на них построены деревья поиска и кучи, а любое дерево общего вида сводится к двоичному.

В Python узел дерева удобно описывать классом со ссылками на потомков, построенным по тому же принципу, что и элемент связного списка, только ссылок, хранимых в узле, теперь две:

```python
class Node:
    def __init__(self, value, left=None, right=None):
        self.value = value  # данные, хранящиеся в узле
        self.left = left    # ссылка на левого потомка (или None)
        self.right = right  # ссылка на правого потомка (или None)
```

Соберём небольшое дерево, составленное из пяти узлов:

```
      5
     / \
    3   8
   / \
  1   4
```

```python
root = Node(5, Node(3, Node(1), Node(4)), Node(8))
```

Всё дерево представлено одной ссылкой на корень, и, зная его, доберёшься до любого узла, висящего ниже. Пустым деревом служит просто `None`. Поэтому функции, работающие с деревьями, принимают корень и первым делом проверяют, не равен ли он `None`; вот тебе и базовый случай, требуемый рекурсией.

## Обходы дерева

Обойти дерево значит побывать в каждом узле по одному разу. В отличие от массива, где порядок обхода очевиден, у дерева есть несколько порядков, считающихся естественными. Все они делятся на два семейства: обходы в глубину (DFS, англ. depth-first search), уходящие вниз по ветке, и обход в ширину (BFS, англ. breadth-first search), идущий по уровням.

### Обходы в глубину

Обход в глубину сначала уходит по ветке до самого низа и только потом возвращается. Реализация, написанная рекурсией, тривиальна, а три классических варианта отличаются лишь моментом, выбранным для обработки самого узла относительно его поддеревьев:

```python
def preorder(root):        # корень -> левое -> правое
    if root is None:
        return
    print(root.value)      # обрабатываем узел до потомков
    preorder(root.left)
    preorder(root.right)


def inorder(root):         # левое -> корень -> правое
    if root is None:
        return
    inorder(root.left)
    print(root.value)      # обрабатываем узел между потомками
    inorder(root.right)


def postorder(root):       # левое -> правое -> корень
    if root is None:
        return
    postorder(root.left)
    postorder(root.right)
    print(root.value)      # обрабатываем узел после потомков
```

Для дерева, нарисованного выше, `preorder` напечатает `5 3 1 4 8`, `inorder` выдаст `1 3 4 5 8`, а `postorder` закончит порядком `1 4 3 8 5`.

Каждый вариант полезен по-своему. Pre-order подходит для копирования и сериализации, идущей сверху вниз: сначала создаём узел, потом его потомков. Post-order годится для удаления и для вычислений, идущих «снизу вверх», когда результат в узле зависит от чисел, посчитанных в поддеревьях; так находят высоту, размер поддеревьев, значение арифметического выражения, разобранного в дерево. In-order, как мы вскоре увидим, выдаёт элементы дерева поиска в порядке, совпадающем с отсортированным.

### Обход в ширину

Обход в ширину идёт по уровням, сначала корень, затем все узлы глубины 1, затем глубины 2 и так далее. Рекурсией здесь не обойтись, нужна очередь, разобранная нами в главе о базовых структурах:

```python
from collections import deque


def level_order(root):
    if root is None:
        return
    queue = deque([root])
    while queue:
        node = queue.popleft()      # берём узел из начала очереди
        print(node.value)
        if node.left:               # и ставим его потомков в конец
            queue.append(node.left)
        if node.right:
            queue.append(node.right)
```

Для того же дерева получится `5 3 8 1 4`, строго по уровням. Любой обход посещает каждый узел по одному разу (обход в глубину вдобавок проходит по каждому ребру дважды, вниз и обратно), поэтому все они работают за \\( O(n) \\), где \\( n \\) — число узлов. Дополнительной памяти требуется \\( O(h) \\) на стек рекурсии у DFS (где \\( h \\) — высота дерева) и до \\( O(n) \\) на очередь у BFS, забитую самым широким уровнем.

## Двоичное дерево поиска

**Двоичным деревом поиска** (англ. binary search tree, BST) называют двоичное дерево, в каждом узле которого выполняется свойство порядка: все значения, сложенные в левом поддереве, строго меньше значения узла, а все значения в правом строго больше.

Свойство порядка, связывающее узел с поддеревьями, превращает поиск в аналог двоичного поиска по отсортированному массиву. Сравнили искомый ключ с корнем. Оказался меньше, идём налево, оказался больше, направо; на каждом шаге спускаемся на уровень ниже, отбрасывая целое поддерево, заведомо не содержащее ключа:

```python
def find(root, key):
    while root is not None and root.value != key:
        root = root.left if key < root.value else root.right
    return root  # узел с ключом key или None, если ключа нет
```

При вставке мы спускаемся так же, как при поиске, и подвешиваем созданный узел в то место, где спуск упёрся в `None`:

```python
def insert(root, key):
    if root is None:
        return Node(key)          # нашли свободное место
    if key < root.value:
        root.left = insert(root.left, key)
    elif key > root.value:
        root.right = insert(root.right, key)
    return root                   # ключ уже есть — ничего не меняем
```

Поиск, вставка и удаление стоят \\( O(h) \\), поскольку мы проходим один путь, проложенный от корня вниз. А in-order-обход дерева поиска выдаёт ключи по возрастанию; сначала всё меньшее (левое поддерево), потом узел, потом всё большее. Получается структура, умеющая разом и быстрый поиск, и вставку, и удаление, и перебор по порядку. Ни отсортированный массив с его медленной вставкой, ни хеш-таблица, лишённая порядка, так не могут.

### Сбалансированность

Вся эффективность BST держится на высоте \\( h \\), определяющей цену любой операции. Если вставлять ключи в случайном порядке, дерево получается «кустистым» и \\( h \approx \log_2 n \\). Но если вставить ключи 1, 2, 3, ..., n по порядку, каждый новый узел уйдёт направо, и дерево, выродившееся в связный список, вытянется на высоту \\( n \\). Все операции, обещанные быстрыми, станут линейными.

Дерево называется **сбалансированным**, если у каждого узла высоты левого и правого поддеревьев отличаются не больше чем на единицу. У дерева, удовлетворяющего этому условию, \\( h = O(\log n) \\), а значит, все операции, перечисленные выше, работают за \\( O(\log n) \\).

Заставить дерево оставаться сбалансированным при любых вставках и удалениях можно, и для этого придуманы самобалансирующиеся деревья (АВЛ-дерево, красно-чёрное дерево), делающие после каждой операции небольшие локальные перестройки, называемые поворотами. Они и прячутся за `std::map` в C++ и `TreeMap` в Java, упомянутыми в главе про хеш-таблицы. В стандартной библиотеке Python дерева поиска нет, поскольку обычно хватает `dict`, `set` и модуля `bisect`, приспособленного к отсортированному списку.

## Куча

**Куча** (англ. heap) служит структурой данных для задач, в которых нужно быстро находить максимум (или минимум) в наборе элементов, меняющемся на ходу. В **невозрастающей куче** (max-heap) выполняется основное свойство кучи: значение любого узла не меньше значений, записанных у его потомков. Значит, в корне всегда лежит максимум. В min-heap всё наоборот, в корне минимум.

В отличие от дерева поиска, куча не упорядочивает элементы полностью: между поддеревьями, висящими слева и справа, никакого порядка нет. Взамен куча всегда остаётся **почти полным** двоичным деревом. Все уровни, кроме последнего, заполнены целиком, а последний, заполняемый слева направо, дописывается по мере роста. Дерево, устроенное так, не бывает вырожденным, и его высота всегда \\( O(\log n) \\).

### Куча в массиве

Почти полное дерево хранится без всяких ссылок, в обычном массиве, с узлами, выписанными по уровням:

```
Куча:                Массив:

      9              [9, 7, 8, 3, 1, 4]
     / \              0  1  2  3  4  5
    7   8
   / \  /
  3  1 4
```

Индексы связаны простой арифметикой. У узла с индексом \\( i \\) потомки лежат в ячейках \\( 2i + 1 \\) и \\( 2i + 2 \\), а родитель в ячейке \\( \lfloor (i-1)/2 \rfloor \\). Никаких классов, никаких указателей: любой массив, заполненный числами, уже готов стать деревом, разложенным по уровням.

Держится куча на двух операциях, называемых «просеиванием» и применяемых после каждого изменения:

* **просеивание вверх** (sift up): элемент, дописанный в конец массива, меняется местами с родителем, пока он больше родителя;
* **просеивание вниз** (sift down): корень, ставший меньше потомков, меняется местами с бóльшим из них и опускается, пока свойство кучи не восстановится.

Оба просеивания проходят не больше одного пути, ведущего от корня до листа, то есть стоят \\( O(\log n) \\). На них строится **приоритетная очередь**, отдающая добавление элемента за \\( O(\log n) \\), просмотр максимума за \\( O(1) \\), а извлечение максимума, при котором последний элемент переставлен в корень и просеян вниз, снова за \\( O(\log n) \\).

В Python куча реализована модулем `heapq` как min-heap, надстроенный над обычным списком, передаваемым в функции модуля:

```python
import heapq

distances = [5.2, 1.1, 3.7, 0.4]
heapq.heapify(distances)          # превращает список в кучу за O(n)
heapq.heappush(distances, 2.6)    # добавление за O(log n)
print(heapq.heappop(distances))   # 0.4 — минимум, за O(log n)
```

Если нужен max-heap, применяют стандартный приём, храня в куче элементы, взятые с обратным знаком. Он ещё пригодится нам в следующей главе, в алгоритме, строящем остовное дерево.

### Пирамидальная сортировка

Куча даёт ещё один способ сортировать за \\( O(n \log n) \\), называемый **пирамидальной сортировкой** (англ. heap sort). Идея в два этапа:

1. Превратить массив в max-heap, просеяв вниз все внутренние узлы, начиная с последнего и заканчивая корнем.
2. Повторять \\( n - 1 \\) раз: обменять корень (текущий максимум) с последним элементом части, ещё не отсортированной, и просеять новый корень вниз. Максимумы, снятые с вершины, один за другим встают в конец массива на свои окончательные места.

Дополнительной памяти heap sort, в отличие от сортировки слиянием, не требует, потому что всё происходит в исходном массиве. И плохих входов у него, в отличие от быстрой сортировки, не бывает: любой массив, подаваемый на вход, обрабатывается за \\( O(n \log n) \\). Платить за это приходится неустойчивостью и несколько большей константой, из-за которой на практике heap sort обычно чуть медленнее quick sort. Полную реализацию, написанную с нуля, мы разберём ниже в задачах.

## Деревья в физических задачах

Деревья в вычислительной физике остаются не абстракцией, а рабочим инструментом. Вот три типичных сюжета.

**Поиск соседей и k-d деревья.** В молекулярной динамике, методе SPH или при кластеризации точек, измеренных в эксперименте, постоянно нужно выяснять, какие частицы находятся рядом с выбранной. Перебор всех пар стоит \\( O(N^2) \\). **k-d дерево** (k-dimensional tree) рекурсивно делит пространство плоскостями пополам, и запрос, ищущий ближайших соседей точки, выполняется в среднем за \\( O(\log N) \\). В SciPy оно уже реализовано классом, отлаженным до нас:

```python
import numpy as np
from scipy.spatial import KDTree

points = np.random.rand(100_000, 3)      # частицы в единичном кубе
tree = KDTree(points)                    # построение за O(N log N)

dist, idx = tree.query(points[0], k=10)          # 10 ближайших соседей
neighbors = tree.query_ball_point(points[0], r=0.05)  # все соседи в радиусе
```

**Гравитационная задача N тел и октодеревья.** Прямое суммирование сил, действующих между \\( N \\) телами, требует \\( O(N^2) \\) операций на шаг, что для галактики из миллиардов звёзд безнадёжно. Алгоритм Барнса — Хата строит **октодерево** (англ. octree): куб пространства, вмещающий всю систему, рекурсивно делится на 8 октантов, пока в каждом листе не останется по частице. Для далёкой группы частиц незачем суммировать вклады по одной, достаточно слагаемого от её суммарной массы, приложенной в центре масс и записанной прямо в узле дерева. Критерий, решающий судьбу ячейки, прост: если её угловой размер \\( s/d \\) меньше порога \\( \theta \\), ячейка не раскрывается. Сложность падает до \\( O(N \log N) \\), и такие деревья, дополненные более хитрым быстрым мультипольным методом, работают внутри современных астрофизических кодов вроде GADGET.

**Иерархические данные.** Формат HDF5, ставший стандартом де-факто для больших численных данных, устроен как дерево: группы содержат подгруппы и датасеты, напоминающие каталоги и файлы. Деревом остаётся и геометрия детектора в Geant4, набранная из объёмов, вложенных в объёмы, и символьное выражение в SymPy, где узлами служат операции, а листьями — переменные и константы, стоящие в формуле. Встретил иерархию — почти наверняка под капотом дерево и рекурсивные обходы, разобранные в этой главе.

## Разбор задач

Разберём несколько классических задач о деревьях. Во всех задачах, где на вход подаётся корень, используется класс `Node`, описанный выше. Попробуй сначала решить каждую задачу самостоятельно, благо все они собраны в [тренажёре](https://contest.yandex.ru/contest/24809/problems/), доступном онлайн.

### Задача 1. Максимальная глубина

**Условие.** Дан корень двоичного дерева. Найди его максимальную глубину, то есть наибольшее число узлов, лежащих на пути от корня до листа (включая корень и лист).

**Идея решения.** Задача рекурсивна по построению, ведь глубина дерева равна глубине более глубокого из поддеревьев плюс единица, добавленная за сам корень. Базовым случаем служит пустое дерево, имеющее глубину 0.

```python
def max_depth(root):
    # Базовый случай: пустое дерево не добавляет к глубине ничего
    if root is None:
        return 0
    # Более глубокое из поддеревьев плюс сам корень
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

**Сложность.** По времени \\( O(n) \\), так как каждый узел посещается один раз. По памяти \\( O(h) \\) на стек рекурсии, растущий вместе с высотой дерева \\( h \\).

### Задача 2. Сбалансированное дерево

**Условие.** Определи, сбалансировано ли двоичное дерево, то есть отличаются ли у каждого узла высоты поддеревьев, висящих слева и справа, не больше чем на единицу.

**Идея решения.** Напрашивается лобовое решение, при котором высоты поддеревьев, посчитанные функцией из предыдущей задачи, сравниваются в каждом узле. Но тогда высота каждого узла будет вычисляться заново на каждом уровне, лежащем выше него, и в худшем случае получится \\( O(n^2) \\).

Лучше совместить оба вычисления в одном обходе. Пусть функция возвращает высоту поддерева, а для поддерева, признанного несбалансированным, специальное значение-сигнал `-1`, немедленно передаваемое наверх без дальнейших проверок.

```python
def check_height(root):
    """Высота поддерева или -1, если оно несбалансировано."""
    if root is None:
        return 0

    left = check_height(root.left)
    if left == -1:                 # слева уже нашли дисбаланс
        return -1

    right = check_height(root.right)
    if right == -1:                # справа уже нашли дисбаланс
        return -1

    if abs(left - right) > 1:      # дисбаланс в текущем узле
        return -1

    return 1 + max(left, right)


def is_balanced(root):
    return check_height(root) != -1
```

**Сложность.** По времени \\( O(n) \\), поскольку делается один post-order-обход, и высота, вычисляемая в узле, считается ровно однажды. По памяти \\( O(h) \\) на стек рекурсии.

### Задача 3. Дерево поиска

**Условие.** Проверь, служит ли двоичное дерево деревом поиска: значения, лежащие в левом поддереве каждого узла, строго меньше значения узла, а в правом строго больше.

**Идея решения.** Частая ошибка состоит в проверке одних лишь соседних узлов: `left.value < node.value < right.value`. Проверки, ограниченной парой соседей, недостаточно:

```
Дерево поиска:        Не дерево поиска:
      5                     5
     / \                   / \
    3   8                 3   8
   / \                   / \
  1   4                 1   6
```

В правом дереве узел 6 больше своего родителя 3, и локально всё хорошо. Но 6 сидит в левом поддереве корня 5, а значит, обязан быть меньше 5. Условие тут глобальное; каждый узел ограничен всеми предками, стоящими над ним.

Будем спускаться по дереву и передавать вниз интервал значений, разрешённых узлу, \\( (\text{low}, \text{high}) \\). Уходя налево, ужесточаем верхнюю границу значением узла, а уходя направо, нижнюю.

```python
def is_bst(root, low=float('-inf'), high=float('inf')):
    if root is None:
        return True
    # Значение узла обязано лежать строго внутри интервала предков
    if not (low < root.value < high):
        return False
    return (is_bst(root.left, low, root.value)      # слева всё < root.value
            and is_bst(root.right, root.value, high))  # справа всё > root.value
```

Есть и изящная альтернатива: сделать in-order-обход и проверить, что значения, выданные им, идут строго по возрастанию. Для дерева поиска это и критерий.

**Сложность.** По времени \\( O(n) \\), по памяти \\( O(h) \\) на стек рекурсии, растущий вместе с глубиной спуска.

### Задача 4. Сколько существует деревьев поиска

**Условие.** Определи, сколько различных двоичных деревьев поиска можно построить из чисел, идущих от 1 до \\( n \\). Число \\( n \\) не превосходит 20.

**Идея решения.** Выберем корнем число \\( k \\). Тогда числа \\( 1, \dots, k-1 \\) обязаны попасть в левое поддерево, а \\( k+1, \dots, n \\) в правое, причём каждое из поддеревьев само остаётся деревом поиска. Число деревьев, собранных из \\( m \\) последовательных чисел, зависит только от \\( m \\), поэтому получаем рекуррентность

\\[ C_n = \sum_{k=1}^{n} C_{k-1} \, C_{n-k}, \qquad C_0 = 1. \\]

Это знаменитые **числа Каталана**, считающие заодно правильные скобочные последовательности и одномерные случайные блуждания, не опускающиеся ниже нуля. Для них известна замкнутая формула, выведенная давным-давно

\\[ C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{n! \, (n+1)!}. \\]

```python
from math import comb


def count_bst(n):
    # Число Каталана: C(2n, n) / (n + 1), деление всегда нацело
    return comb(2 * n, n) // (n + 1)
```

Если формулу не помнишь, ответ считается и по рекуррентности, выписанной выше, динамическим программированием:

```python
def count_bst_dp(n):
    counts = [1] + [0] * n           # counts[0] = 1: пустое дерево одно
    for size in range(1, n + 1):
        for root in range(1, size + 1):
            # root - 1 чисел уходит налево, size - root — направо
            counts[size] += counts[root - 1] * counts[size - root]
    return counts[n]
```

Важно работать с целыми числами. Наивное `fac(2*n) / (fac(n) * fac(n+1))` считает через `float`, несущий около 16 значащих цифр, а промежуточный \\( 40! \approx 8{,}16 \cdot 10^{47} \\) точно в нём не представим. До \\( n = 30 \\) ответ всё же выходит верным: ошибки, накопленные в числителе и знаменателе, гасят друг друга при делении. А вот \\( C_{31} \\) наивная формула уже занижает на единицу. Полагаться на такое везение не стоит, тем более что целочисленный вариант, написанный выше, ничем не сложнее.

**Сложность.** Формула с биномиальным коэффициентом требует \\( O(n) \\) умножений; вариант, построенный на динамике, обходится в \\( O(n^2) \\) операций и \\( O(n) \\) памяти.

### Задача 5. Удаление узла из дерева поиска

**Условие.** Дано дерево поиска с уникальными целыми ключами. Удали узел с заданным ключом так, чтобы дерево осталось корректным деревом поиска, и верни корень изменённого дерева. Если ключа нет, верни дерево нетронутым. Создавать новые узлы нельзя, сложность должна быть \\( O(h) \\).

**Идея решения.** Сначала спускаемся к удаляемому узлу, как при обычном поиске. Дальше три случая:

1. Если у узла нет потомков, просто убираем его, и родитель начинает ссылаться на `None`.
2. При одном потомке подвешиваем его на место, освобождённое удаляемым узлом.
3. При двух потомках находим **преемника**, то есть узел, минимальный в правом поддереве (идём направо, затем налево до упора). Преемник больше всего левого поддерева и меньше остального правого, поэтому законно встаёт на освободившееся место. Вырезаем его со старого места, где нет левого потомка и работает случай 1 или 2, и переставляем наверх.

```python
def remove(root, key):
    if root is None:                     # ключа в дереве нет
        return None

    if key < root.value:                 # ищем слева
        root.left = remove(root.left, key)
    elif key > root.value:               # ищем справа
        root.right = remove(root.right, key)
    else:                                # нашли узел с ключом key
        if root.left is None:            # случаи 1 и 2: нет левого потомка
            return root.right
        if root.right is None:           # случай 2: нет правого потомка
            return root.left

        # Случай 3: ищем преемника — минимум правого поддерева
        parent, succ = root, root.right
        while succ.left is not None:
            parent, succ = succ, succ.left

        # Вырезаем преемника со старого места...
        if parent.left is succ:
            parent.left = succ.right
        else:
            parent.right = succ.right

        # ...и ставим его на место удаляемого узла
        succ.left = root.left
        succ.right = root.right
        return succ

    return root
```

**Сложность.** По времени \\( O(h) \\), поскольку спуск к узлу и спуск к преемнику вместе образуют один путь, проложенный от корня вниз. По памяти \\( O(h) \\) на рекурсию поиска, переписываемую циклом до \\( O(1) \\).

### Задача 6. Пирамидальная сортировка

**Условие.** По результатам соревнования дан список участников: логин, число решённых задач \\( P \\) и штраф \\( F \\). Отсортируй таблицу: выше стоит тот, у кого больше решённых задач; при равенстве тот, у кого меньше штраф; если и штрафы равны, тот, чей логин идёт раньше по алфавиту. Кучу нужно реализовать самостоятельно, встроенными сортировками и `heapq` пользоваться нельзя.

```
Ввод:                  Вывод:
5                      gena
alla 4 100             timofey
gena 6 1000            alla
gosha 2 90             gosha
rita 2 90              rita
timofey 4 80
```

**Идея решения.** Это задача на сортировку по составному ключу, так что вспомни раздел, посвящённый сортировке по ключу, в главе о сортировках. Подберём ключ так, чтобы обычное сравнение кортежей «меньше» означало «выше в таблице»: число решённых задач берём с минусом (чем больше задач, тем меньше ключ), а штраф и логин оставляем нетронутыми:

```python
def sort_key(user):
    login, solved, penalty = user
    return (-solved, penalty, login)
```

Остаётся отсортировать массив по ключу, собранному выше, пирамидальной сортировкой. Строим max-heap прямо в исходном массиве, затем раз за разом переставляем максимум, то есть худшего из оставшихся участников, в конец неотсортированной части:

```python
def sift_down(items, start, end):
    """Просеивает элемент start вниз внутри items[start:end + 1]."""
    root = start
    while True:
        child = 2 * root + 1               # левый потомок
        if child > end:                    # потомков нет — дно кучи
            break
        # Из двух потомков выбираем большего
        if child + 1 <= end and sort_key(items[child]) < sort_key(items[child + 1]):
            child += 1
        if sort_key(items[root]) < sort_key(items[child]):
            items[root], items[child] = items[child], items[root]
            root = child                   # спускаемся за элементом дальше
        else:
            break                          # свойство кучи восстановлено


def heap_sort(items):
    n = len(items)
    # Этап 1: строим кучу — просеиваем все внутренние узлы справа налево
    for start in range((n - 2) // 2, -1, -1):
        sift_down(items, start, n - 1)
    # Этап 2: снимаем максимум с вершины кучи в конец массива
    for end in range(n - 1, 0, -1):
        items[0], items[end] = items[end], items[0]
        sift_down(items, 0, end - 1)


def main():
    n = int(input())
    users = []
    for _ in range(n):
        login, solved, penalty = input().split()
        users.append((login, int(solved), int(penalty)))

    heap_sort(users)

    print('\n'.join(user[0] for user in users))


if __name__ == '__main__':
    main()
```

После этапа 1 участник, худший по нашему ключу, стоит в корне кучи, то есть в ячейке 0. Обмен с последним элементом ставит его на окончательное место, а однократное просеивание вниз восстанавливает кучу в укоротившейся части массива. В итоге массив отсортирован по возрастанию ключа, и лучшие участники, поднятые наверх, стоят в начале.

**Сложность.** Построение кучи занимает \\( O(n) \\), поскольку узлы, сидящие низко, просеиваются на маленькую глубину, а затем идут \\( n - 1 \\) просеиваний, стоящих по \\( O(\log n) \\). Итого \\( O(n \log n) \\) по времени в худшем случае и \\( O(1) \\) дополнительной памяти, ведь сортировка идёт на месте. В боевом коде, конечно, достаточно `sorted(users, key=sort_key)`, но теперь ты знаешь, что спрятано у него внутри.

## Резюме

* Дерево представляет собой рекурсивную структуру, составленную из корня и поддеревьев, каждое из которых само дерево. Базовым случаем алгоритмов, написанных для него, служит пустое дерево `None`.
* Обходы в глубину (pre-, in-, post-order) пишутся рекурсией, а обход в ширину очередью, хранящей текущий уровень; все стоят \\( O(n) \\).
* Дерево поиска даёт поиск, вставку и удаление за \\( O(h) \\); чтобы высота \\( h \\), определяющая цену, была \\( O(\log n) \\), дерево должно быть сбалансированным.
* Куча укладывается в массив как почти полное дерево, отдающее максимум за \\( O(1) \\), а вставку и извлечение за \\( O(\log n) \\); на ней построены приоритетная очередь и heap sort.
* В физических расчётах деревья ускоряют поиск соседей (k-d деревья), задачу N тел (октодеревья Барнса — Хата) и держат иерархические данные, сложенные в HDF5.

В следующей главе мы уберём у дерева ограничения, разрешив циклы и произвольные связи. Получится самая общая структура данных, называемая графом.
