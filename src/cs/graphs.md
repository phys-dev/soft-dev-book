# Графы

Дерево из предыдущей главы остаётся структурой удобной, но частной, поскольку у каждого узла в точности один родитель, а между любыми двумя узлами единственный путь. Реальные связи так устроены далеко не всегда.

Города соединены дорогами, причём из каждого можно уехать несколькими маршрутами. Атомы в молекуле связаны в кольца, а узлы электрической цепи соединяются проводниками, образуя контуры. Компьютеры в сети связаны друг с другом множеством путей. Всё это описывается самой общей структурой, графом.

Граф остаётся, пожалуй, главной структурой данных в прикладной информатике, поскольку к нему сводится масса практических задач, которые на первый взгляд не имеют к графам никакого отношения.

## Определения

**Граф** \\( G = (V, E) \\) складывается из множества вершин \\( V \\) (англ. vertices) и множества рёбер \\( E \\) (англ. edges), каждое из которых соединяет пару вершин.

Основные разновидности:

* **Неориентированный граф** имеет рёбра без направления: если из \\( u \\) можно попасть в \\( v \\), то и обратно тоже (дороги с двусторонним движением).
* **Ориентированный граф** (орграф, англ. directed graph) снабжает рёбра направлением, при котором ребро \\( (u, v) \\) не означает существования ребра \\( (v, u) \\) (односторонние улицы, ссылки между веб-страницами, зависимости между задачами).
* **Взвешенный граф** приписывает каждому ребру число: длину дороги, сопротивление проводника, пропускную способность канала, энергию связи.

Ещё немного терминологии:

* **смежными** называют вершины, соединённые ребром;
* **степень вершины** равна числу инцидентных ей рёбер (в орграфе различают входящую и исходящую степени);
* **путь** есть последовательность вершин, в которой соседние соединены рёбрами;
* **цикл** представляет собой путь, начинающийся и заканчивающийся в одной вершине;
* **связный граф** позволяет добраться из любой вершины до любой другой;
* **компонента связности** составляет максимальный связный кусок графа;
* **петля** соединяет вершину с самой собой, а **кратными рёбрами** зовут несколько рёбер между одной парой вершин.

Отсюда видно место дерева в общей картине. **Дерево есть связный неориентированный граф без циклов**, у которого рёбер на одно меньше, чем вершин. А граф без циклов, но не обязательно связный, называется лесом.

## Как хранить граф

От способа хранения зависит и объём памяти, и сложность операций, а основных вариантов два.

### Матрица смежности

Квадратная таблица \\( n \times n \\), где на пересечении \\( i \\)-й строки и \\( j \\)-го столбца стоит единица (или вес ребра), если ребро из \\( i \\) в \\( j \\) есть, и ноль в противном случае. У неориентированного графа матрица симметрична.

```python
n = 5
matrix = [[0] * n for _ in range(n)]  # граф без рёбер

def add_edge_matrix(matrix, u, v, directed=False):
    """Добавляет ребро в матрицу смежности (вершины нумеруются с нуля)."""
    matrix[u][v] = 1
    if not directed:
        matrix[v][u] = 1
```

Проверка «есть ли ребро между \\( u \\) и \\( v \\)» выполняется мгновенно, за \\( O(1) \\). Но памяти нужно \\( O(n^2) \\) независимо от числа рёбер, а перебор всех соседей вершины требует \\( O(n) \\), поскольку придётся просмотреть всю строку, даже если сосед всего один.

### Список смежности

Для каждой вершины хранится список её соседей.

```python
from collections import defaultdict

graph = defaultdict(list)

def add_edge_list(graph, u, v, directed=False):
    """Добавляет ребро в список смежности."""
    graph[u].append(v)
    if not directed:
        graph[v].append(u)
```

Памяти требуется \\( O(n + m) \\), где \\( m \\) — число рёбер, а перебор соседей вершины занимает время, пропорциональное их количеству. Платой служит проверка наличия конкретного ребра за \\( O(\deg v) \\) вместо \\( O(1) \\).

**Выбор между ними.** Правило простое, и для **плотного** графа (число рёбер сравнимо с \\( n^2 \\)) берут матрицу, для **разреженного** (рёбер порядка \\( n \\)) список. Реальные графы почти всегда разреженные: у человека в социальной сети сотни друзей, а не миллионы, у атома в молекуле единицы связей. По умолчанию бери список смежности.

| Операция | Матрица смежности | Список смежности |
|---|---|---|
| Память | \\( O(n^2) \\) | \\( O(n + m) \\) |
| Проверить ребро \\( (u,v) \\) | \\( O(1) \\) | \\( O(\deg u) \\) |
| Перебрать соседей \\( u \\) | \\( O(n) \\) | \\( O(\deg u) \\) |
| Добавить ребро | \\( O(1) \\) | \\( O(1) \\) |

Есть и третий способ, **список рёбер**, то есть просто перечень пар вершин. Для обходов он неудобен, зато идеален для алгоритмов, которые перебирают рёбра целиком (скажем, для алгоритма Краскала), и в таком виде граф обычно приходит на вход.

## Обходы графа

Обходом называют систематическое посещение всех вершин, достижимых из стартовой. У графа, в отличие от дерева, есть циклы, поэтому появляется обязательный элемент, **множество посещённых вершин**. Без него обход зациклится.

### Поиск в глубину (DFS)

Идея такая. Из текущей вершины уходим как можно дальше вглубь, а когда идти больше некуда, возвращаемся и пробуем другое направление. Это тот же самый обход в глубину, что и у деревьев, только с проверкой на повторное посещение.

```python
def dfs_recursive(graph, vertex, visited=None):
    """Рекурсивный обход в глубину. Возвращает вершины в порядке обхода."""
    if visited is None:
        visited = set()
    visited.add(vertex)
    order = [vertex]
    for neighbour in sorted(graph[vertex]):
        if neighbour not in visited:
            order.extend(dfs_recursive(graph, neighbour, visited))
    return order
```

Рекурсия хороша для чтения и опасна на практике. Глубина рекурсии в Python ограничена (по умолчанию около 1000), и на графе из ста тысяч вершин программа упадёт с `RecursionError`. Поэтому в боевых решениях DFS пишут итеративно, заменяя стек вызовов явным стеком:

```python
def dfs_iterative(graph, start):
    """Итеративный обход в глубину через явный стек."""
    visited = set()
    order = []
    stack = [start]
    while stack:
        vertex = stack.pop()
        if vertex in visited:
            continue
        visited.add(vertex)
        order.append(vertex)
        # соседей кладём в обратном порядке, чтобы снимать по возрастанию
        for neighbour in sorted(graph[vertex], reverse=True):
            if neighbour not in visited:
                stack.append(neighbour)
    return order
```

Тут важная деталь. Проверка `if vertex in visited` стоит **после** снятия со стека, а не только перед добавлением. Одна и та же вершина попадает в стек по нескольку раз через разных соседей, поэтому отсеивать её надо в момент обработки.

### Поиск в ширину (BFS)

Идея иная, ведь сначала мы посещаем всех соседей стартовой вершины, потом соседей соседей и так далее, расходясь кругами, как волна по воде. От DFS отличие в одну строчку, вместо стека очередь.

```python
from collections import deque

def bfs(graph, start):
    """Обход в ширину. Возвращает вершины в порядке обхода."""
    visited = {start}
    order = []
    queue = deque([start])
    while queue:
        vertex = queue.popleft()          # берём из начала очереди
        order.append(vertex)
        for neighbour in sorted(graph[vertex]):
            if neighbour not in visited:
                visited.add(neighbour)    # помечаем сразу при добавлении
                queue.append(neighbour)
    return order
```

Заметь: в BFS вершина помечается посещённой **в момент добавления в очередь**, иначе она успеет попасть туда несколько раз.

Оба обхода работают за \\( O(n + m) \\): каждая вершина и каждое ребро обрабатываются один раз. Сделаем оговорку к коду выше, где вызов `sorted` внутри обхода добавляет \\( O(m \log n) \\); он стоит там лишь для того, чтобы вывод был воспроизводим. В рабочем коде списки смежности сортируют один раз заранее, как в задачах в конце главы. Выбор между ними определяется задачей:

* **BFS** посещает вершины в порядке возрастания расстояния от старта, поэтому он и находит **кратчайшие пути в невзвешенном графе**;
* **DFS** естественно ложится на рекурсию и используется для поиска циклов, топологической сортировки, компонент связности и разбора структуры графа.

## Кратчайшие пути

В невзвешенном графе кратчайший путь ищет BFS, и достаточно попутно запоминать расстояние и предка каждой вершины.

```python
def bfs_shortest_paths(graph, start):
    """Расстояния (в рёбрах) и предки на кратчайших путях от start."""
    dist = {start: 0}
    parent = {start: None}
    queue = deque([start])
    while queue:
        vertex = queue.popleft()
        for neighbour in graph[vertex]:
            if neighbour not in dist:
                dist[neighbour] = dist[vertex] + 1
                parent[neighbour] = vertex
                queue.append(neighbour)
    return dist, parent
```

Восстановить сам путь потом легко, идя от конечной вершины по ссылкам `parent` до старта и разворачивая результат.

Если рёбра **взвешенные**, BFS уже не годится, так как путь из трёх коротких рёбер бывает короче пути из одного длинного. Здесь работает **алгоритм Дейкстры**. Идея жадная: поддерживаем текущие оценки расстояний и на каждом шаге берём ещё не обработанную вершину с наименьшей оценкой (она уже не улучшится), после чего пробуем улучшить оценки её соседей, и эта операция называется *релаксацией*.

```python
import heapq

def dijkstra(graph, start):
    """Кратчайшие расстояния во взвешенном графе с неотрицательными весами.

    graph — список смежности вида {вершина: [(сосед, вес), ...]}.
    """
    dist = {start: 0}
    heap = [(0, start)]           # приоритетная очередь (расстояние, вершина)
    while heap:
        d, vertex = heapq.heappop(heap)
        if d > dist.get(vertex, float("inf")):
            continue              # устаревшая запись, вершина уже обработана
        for neighbour, weight in graph[vertex]:
            new_dist = d + weight
            if new_dist < dist.get(neighbour, float("inf")):
                dist[neighbour] = new_dist
                heapq.heappush(heap, (new_dist, neighbour))
    return dist
```

Куча (см. главу про [деревья](./trees.md)) даёт сложность \\( O(m \log n) \\). Важное ограничение состоит в том, что веса должны быть неотрицательными, потому что на рёбрах с отрицательным весом жадность ломается, и нужен алгоритм Беллмана — Форда.

## Топологическая сортировка

Пусть ориентированный граф описывает зависимости: ребро \\( u \to v \\) означает «\\( u \\) должно быть выполнено раньше \\( v \\)». Компиляция модулей, порядок расчётных этапов в пайплайне обработки данных, установка пакетов ставят одну и ту же задачу, выстроить вершины в линию так, чтобы все рёбра шли слева направо. Это и есть топологическая сортировка, и возможна она тогда и только тогда, когда в графе нет циклов (иначе зависимости противоречивы).

Простейшим способом служит DFS, при котором вершина добавляется в результат после того, как обработаны все её потомки, а в конце список разворачивается.

```python
def topological_sort(graph, vertices):
    """Топологическая сортировка ориентированного ациклического графа."""
    visited = set()
    order = []

    def visit(vertex):
        visited.add(vertex)
        for neighbour in graph[vertex]:
            if neighbour not in visited:
                visit(neighbour)
        order.append(vertex)      # добавляем на выходе из вершины

    for vertex in vertices:
        if vertex not in visited:
            visit(vertex)
    return order[::-1]            # разворачиваем
```

## Минимальное остовное дерево

**Остовным деревом** (англ. spanning tree) связного графа называют подмножество рёбер, связывающее все вершины и не содержащее циклов, то есть дерево на всех \\( n \\) вершинах из \\( n-1 \\) ребра. Минимальным остовным деревом (MST) зовётся то, у которого суммарный вес рёбер наименьший. Классическая постановка требует соединить все дома оптоволокном, потратив минимум кабеля.

Два классических алгоритма, оба жадные:

* **Алгоритм Прима** растит дерево из одной вершины: на каждом шаге добавляется самое лёгкое ребро, ведущее из уже построенной части наружу. Удобно реализуется через кучу, сложность \\( O(m \log n) \\). По духу это Дейкстра, только вместо расстояния от старта минимизируется вес одного ребра.
* **Алгоритм Краскала** идёт от рёбер: сортирует их все по весу и добавляет по очереди те, что не образуют цикл. Проверка «не образует ли цикл» делается структурой «система непересекающихся множеств» (DSU). Сложность \\( O(m \log m) \\).

Полезное наблюдение. Заменишь в алгоритме Прима «минимальное ребро» на «максимальное», получишь **максимальное** остовное дерево; эту задачу мы и разберём в конце главы.

## Графы в физических задачах

Графы в физике встречаются чаще, чем кажется на первый взгляд.

* **Электрические цепи.** Схема буквально представляет собой граф из узлов и ветвей. Законы Кирхгофа записываются через матрицу инцидентности графа, а число независимых контурных уравнений равно \\( m - n + 1 \\), то есть количеству рёбер, не вошедших в остовное дерево.
* **Модель Изинга и перколяция.** Спины на решётке служат вершинами, а взаимодействия соседей рёбрами. Алгоритмы кластерного обновления (Свендсена — Ванга, Вольфа) сводятся к поиску компонент связности, а задача о перколяции сводится к вопросу о существовании компоненты, соединяющей края решётки.
* **Молекулы и структуры.** Атомы и химические связи образуют граф, а поиск колец в молекуле оборачивается поиском циклов. На этом же представлении работают графовые нейронные сети, предсказывающие свойства веществ.
* **Марковские цепи и графы состояний.** Состояния системы становятся вершинами, а переходы с вероятностями взвешенными рёбрами орграфа.
* **Трассировка и планирование.** Разводка кабелей на установке, маршрут манипулятора, планирование эксперимента сводятся к задачам о кратчайшем пути или остовном дереве.

Для практических расчётов писать алгоритмы руками не обязательно, потому что готовые есть в библиотеке **NetworkX**.

```python
import networkx as nx

# граф-решётка 4 x 4 — например, узлы двумерной модели Изинга
lattice = nx.grid_2d_graph(4, 4)

print(nx.number_connected_components(lattice))       # компоненты связности
print(nx.shortest_path(lattice, (0, 0), (3, 3)))     # кратчайший путь
mst = nx.minimum_spanning_tree(lattice)              # остовное дерево
```

Впрочем, разбираться в том, как эти алгоритмы устроены внутри, всё равно придётся. Библиотека не подскажет, что твоя задача сводится к поиску компонент связности.

## Разбор задач

Разберём несколько базовых задач на графы, и, как и в предыдущих главах, сначала попробуй решить сам; задачи собраны в [тренажёре](https://contest.yandex.ru/contest/25069/problems/).

Во всех задачах вершины нумеруются с единицы, а граф подаётся на вход списком рёбер: в первой строке числа \\( n \\) и \\( m \\) (количество вершин и рёбер), далее \\( m \\) строк с парами вершин.

### Задача 1. Построить список смежности

**Условие.** Дан ориентированный граф списком рёбер. Построй его список смежности: для каждой вершины \\( i \\) выведи число исходящих рёбер, а затем номера вершин, в которые они ведут, в порядке возрастания.

**Идея решения.** Прямая реализация определения. Заводим список списков и проходим по рёбрам, добавляя конец каждого ребра в список его начала. Сортировку делаем один раз в конце.

```python
n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]        # вершины нумеруются с единицы

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)                    # граф ориентированный: только u -> v

for vertex in range(1, n + 1):
    neighbours = sorted(graph[vertex])
    print(len(neighbours), *neighbours)
```

**Сложность.** По времени \\( O(n + m \log n) \\), поскольку чтение рёбер стоит \\( O(m) \\), а сортировка всех списков смежности в сумме \\( \sum_i d_i \log d_i \le m \log n \\). По памяти \\( O(n + m) \\).

### Задача 2. Перевести список рёбер в матрицу смежности

**Условие.** Дан ориентированный граф списком рёбер. Выведи его матрицу смежности \\( n \times n \\): на пересечении \\( i \\)-й строки и \\( j \\)-го столбца стоит единица, если есть ребро из \\( i \\) в \\( j \\).

**Идея решения.** Заводим нулевую матрицу и расставляем единицы. Единственная тонкость состоит в том, чтобы не создать матрицу через `[[0] * n] * n`. Так получится \\( n \\) ссылок на **один и тот же** список, и запись в одну строку изменит все разом. Классическая ловушка; к её устройству мы ещё вернёмся в главе про объекты и память.

```python
n, m = map(int, input().split())
matrix = [[0] * n for _ in range(n)]      # именно так, а не [[0] * n] * n

for _ in range(m):
    u, v = map(int, input().split())
    matrix[u - 1][v - 1] = 1              # переходим к нумерации с нуля

for row in matrix:
    print(*row)
```

**Сложность.** По времени \\( O(n^2 + m) \\) (вывод матрицы уже стоит \\( O(n^2) \\)), по памяти \\( O(n^2) \\).

### Задача 3. Обход в глубину

**Условие.** Задан неориентированный граф. Обойди с помощью DFS все вершины, достижимые из заданной вершины \\( s \\), и выведи их в порядке обхода. Соседи каждой вершины рассматриваются в порядке возрастания номеров.

**Идея решения.** Итеративный DFS со стеком (граф может содержать до \\( 10^5 \\) вершин, рекурсия не выдержит). Чтобы соседи обрабатывались по возрастанию, кладём их в стек в обратном порядке, рассчитывая на то, что снимается всегда последний положенный.

```python
n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)                    # граф неориентированный

start = int(input())
for neighbours in graph:
    neighbours.sort(reverse=True)         # сортируем один раз заранее

visited = [False] * (n + 1)
stack, order = [start], []

while stack:
    vertex = stack.pop()
    if visited[vertex]:                   # вершина могла попасть в стек дважды
        continue
    visited[vertex] = True
    order.append(vertex)
    for neighbour in graph[vertex]:
        if not visited[neighbour]:
            stack.append(neighbour)

print(*order)
```

**Сложность.** По времени \\( O(n + m) \\) плюс сортировка списков смежности, по памяти \\( O(n + m) \\).

### Задача 4. Обход в ширину

**Условие.** Та же постановка, но обход выполняется в ширину.

**Идея решения.** Меняем стек на `deque` и снимаем элементы с начала, соседей сортируем уже по возрастанию и помечаем вершину посещённой при добавлении в очередь.

```python
from collections import deque

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

start = int(input())
for neighbours in graph:
    neighbours.sort()

visited = [False] * (n + 1)
visited[start] = True
queue, order = deque([start]), []

while queue:
    vertex = queue.popleft()              # берём из начала очереди
    order.append(vertex)
    for neighbour in graph[vertex]:
        if not visited[neighbour]:
            visited[neighbour] = True     # помечаем сразу при добавлении
            queue.append(neighbour)

print(*order)
```

**Сложность.** Та же, что у DFS: \\( O(n + m) \\) по времени и памяти. Посмотри, до чего мало отличается код двух принципиально разных обходов: вся разница в том, с какого конца мы берём вершины из контейнера.

### Задача 5. Компоненты связности

**Условие.** Дан неориентированный граф. Найди его компоненты связности: выведи их количество, а затем вершины каждой компоненты по возрастанию. Компоненты упорядочены по номеру первой вершины.

**Идея решения.** Запускаем обход из каждой ещё не посещённой вершины: всё, что обход соберёт за один запуск, и есть одна компонента. Если перебирать стартовые вершины по возрастанию, компоненты автоматически получатся в нужном порядке.

```python
n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

visited = [False] * (n + 1)
components = []

for vertex in range(1, n + 1):
    if visited[vertex]:
        continue
    component, stack = [], [vertex]       # новая компонента
    while stack:
        current = stack.pop()
        if visited[current]:
            continue
        visited[current] = True
        component.append(current)
        stack.extend(graph[current])
    components.append(sorted(component))

print(len(components))
for component in components:
    print(*component)
```

**Сложность.** По времени \\( O(n + m) \\) плюс сортировка компонент, по памяти \\( O(n + m) \\). Внешний цикл по вершинам, вопреки первому впечатлению, не делает алгоритм квадратичным, поскольку каждая вершина обрабатывается по одному разу, а цикл лишь ищет стартовые точки.

### Задача 6. Самая дорогая сеть

**Условие.** Дан связный взвешенный неориентированный граф. Найди вес максимального остовного дерева, набора рёбер, связывающего все вершины и имеющего наибольший суммарный вес. Если граф несвязен, дерева не существует.

**Идея решения.** Алгоритм Прима, только на каждом шаге выбирается не минимальное, а максимальное ребро. Модуль `heapq` реализует лишь min-heap, поэтому применим стандартный трюк, положив в кучу вес со знаком минус, отчего «минимальный» элемент кучи окажется максимальным по модулю.

Начинаем с первой вершины и складываем в кучу все исходящие из неё рёбра. Затем на каждом шаге достаём самое тяжёлое ребро; если оно ведёт в новую вершину, добавляем её в остов, прибавляем вес к ответу и складываем в кучу её рёбра. Если после завершения цикла в остов вошли не все вершины, значит, граф несвязен.

```python
import heapq

def add_vertex(vertex, graph, added, heap):
    """Добавляет вершину в остов и кладёт её рёбра в кучу."""
    added[vertex] = True
    for neighbour, weight in graph[vertex]:
        if not added[neighbour]:
            heapq.heappush(heap, (-weight, neighbour))   # минус: нужен max-heap

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, weight = map(int, input().split())
    graph[u].append((v, weight))
    graph[v].append((u, weight))

added = [False] * (n + 1)
added[0] = True                           # нулевой вершины не существует
heap, total = [], 0

add_vertex(1, graph, added, heap)         # растим остов из первой вершины
in_tree = 1                               # сколько вершин уже в остове

while in_tree < n and heap:
    weight, vertex = heapq.heappop(heap)
    if not added[vertex]:                 # ребро внутрь остова пропускаем
        total += -weight
        add_vertex(vertex, graph, added, heap)
        in_tree += 1

print(total if in_tree == n else "Oops! I did it again")
```

**Сложность.** По времени \\( O(m \log n) \\), ведь каждое ребро попадает в кучу не более одного раза, а операции с кучей стоят \\( O(\log n) \\). По памяти \\( O(n + m) \\).

## Резюме

* Граф служит самой общей структурой для описания связей, а дерево и список остаются его частными случаями.
* Разреженные графы храни списком смежности (\\( O(n+m) \\) памяти), а плотные матрицей смежности (\\( O(n^2) \\), зато проверка ребра за \\( O(1) \\)).
* DFS и BFS отличаются только контейнером, стеком против очереди, и оба работают за \\( O(n + m) \\).
* BFS находит кратчайшие пути в невзвешенном графе, а Дейкстра во взвешенном с неотрицательными весами за \\( O(m \log n) \\).
* Обязательно помечай посещённые вершины: в отличие от дерева, у графа есть циклы, и без пометок обход не завершится.
* Компоненты связности, топологическая сортировка и остовные деревья составляют три классических применения обходов, к которым сводится масса практических задач.
