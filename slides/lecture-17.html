Изложение. Цель лекции состоит в том, чтобы оценивать стоимость алгоритма до запуска и подтверждать оценку измерением. Оценка до запуска необходима потому, что порядок роста определяет выполнимость расчёта сильнее, чем язык или компьютер. Рассмотрим миллион событий детектора, которые требуется сравнить попарно, например в поиске совпадений по времени: алгоритм O(n²) совершает около 10¹² операций. Цикл Python выполняет порядка 3·10⁷ простейших итераций в секунду, и такой расчёт занял бы около восьми часов. Переход к коду на C, будь то NumPy или компилируемый язык, повышает скорость примерно до 10⁹ операций в секунду, то есть уменьшает константу, но не порядок роста, и расчёт всё равно занимает около четверти часа. Алгоритм O(n log n) — сортировка событий по времени и проход по соседним парам — выполняет ту же работу примерно за 2·10⁷ операций, то есть меньше чем за секунду даже на чистом Python. Таким образом, удачно выбранный алгоритм или структура данных сокращает время на порядки, причём чаще, чем низкоуровневая оптимизация. Вместе с тем оценка остаётся гипотезой, пока не подтверждена измерением: константы, кеш процессора и устройство интерпретатора меняют реальное время, и каждая оценка лекции проверяется на стенде.

Изложение. Алгоритмом называется конечная последовательность точных инструкций, приводящая к результату за конечное число шагов. От такой последовательности требуются шесть свойств. Дискретность означает, что алгоритм распадается на отдельные шаги, выполняемые по одному в определённом порядке. Детерминированность — что на одних и тех же входных данных получается один и тот же результат при любом числе запусков; при разборе демонстрации с частым символом будет показано, как легко нарушить это свойство, перебирая элементы множества строк. Понятность — что каждый шаг посилен исполнителю и не допускает двоякого толкования: инструкция «посолить по вкусу» в алгоритм не годится. Завершаемость — что работа заканчивается за конечное число шагов. Массовость — что алгоритм решает задачу для целого класса входных данных, а не для единственного набора. Результативность — что на выходе получается ответ, пусть даже им является сообщение об отсутствии решения. Существуют задачи, для которых доказано, что решающего их алгоритма нет. Самая известная из них — проблема останова: по алгоритму и входным данным определить, остановится ли алгоритм или будет работать бесконечно. Доказательство ведётся от противного: предполагаемый распознаватель встраивается в программу, которая поступает наоборот его предсказанию, и эта программа подаётся на вход самой себе — получается противоречие. Отсюда, в частности, вытекает, что никакой анализатор кода не позволяет в общем случае гарантировать завершение произвольной программы.

Важно

Бинарный поиск требует упорядоченного массива: на неупорядоченном он может не найти и имеющийся элемент.

Изложение. Рассмотрим задачу: в массиве длины N найти заданное число и вернуть его индекс либо −1, если числа нет. Линейный поиск перебирает элементы по порядку; в худшем случае, когда искомый элемент оказывается последним или отсутствует, он выполняет N сравнений, и вычислительная сложность линейно зависит от размера входа. Вычислительная сложность представляет собой число элементарных операций, совершаемых алгоритмом, как функцию размера входных данных. Если массив упорядочен по возрастанию, искомое число находится гораздо быстрее. Бинарный поиск сравнивает x с серединой рассматриваемого отрезка и отбрасывает ту половину, в которой x заведомо нет; после каждой итерации длина отрезка уменьшается вдвое, и в худшем случае требуется ⌊log₂ N⌋ + 1 итераций. Пример главы — словарь из 100 страниц: делить его пополам можно не более семи раз, поскольку 2⁷ = 128 ≥ 100, и для поиска слова достаточно просмотреть не более семи страниц. Алгоритм известен также как двоичный поиск, метод деления пополам и дихотомия; физику он знаком по методу половинного деления при поиске корня уравнения. Предусловие алгоритма существенно: бинарный поиск применим только к упорядоченному массиву. На неупорядоченных данных он не завершается ошибкой, а, как правило, возвращает −1 для элементов, которые в массиве есть, — это будет видно в демонстрации.

O-нотация

f(n) = O(g(n)), если найдутся c > 0 и n₀:
f(n) ≤ c·g(n) при всех n ≥ n₀
 
5n + 3 ≤ 6n при n ≥ 3  ⇒  5n + 3 = O(n)

Пояснение

Основание логарифма под знаком O роли не играет: логарифмы различаются множителем.

Важно

Константы определяют применимость при конкретных размерах данных: лучшая асимптотика может проиграть при большой константе.

Изложение. Чтобы говорить о скорости алгоритма без привязки к конкретной машине, используется O-нотация. Запись f(n) = O(g(n)) означает, что существуют постоянная c > 0 и порог n₀, начиная с которого f(n) ≤ c·g(n): функция f растёт не быстрее g с точностью до постоянного множителя. Например, алгоритм, совершающий 5n + 3 операций, имеет сложность O(n), поскольку 5n + 3 ≤ 6n при n ≥ 3. Константы и младшие члены в оценке отбрасываются: они зависят от процессора, компилятора и интерпретатора, тогда как характер роста от них не зависит. В таблице собраны классы, встречающиеся чаще всего, с примерами из лекции. Обращение к элементу массива по индексу требует O(1) операций, бинарный поиск — O(log n), проход по массиву — O(n), сортировка слиянием — O(n log n), перебор всех пар n частиц — O(n²), умножение матриц n × n по определению — O(n³), перебор всех подмножеств n предметов — O(2^n). Основание логарифма под знаком O роли не играет: логарифмы по разным основаниям отличаются постоянным множителем. Отброшенные константы, однако, не исчезают из практики. Они определяют применимость алгоритма при конкретных размерах данных: асимптотически лучший алгоритм может проигрывать на практике, если его константа велика, а выигрыш от асимптотики растёт медленно. В демонстрации с простыми числами линейное решето O(n) окажется не быстрее классического решета O(n log log n), а в демонстрации с поиском функция на Python уступает функции на C в девять раз при одной и той же сложности.

Пояснение

В логарифмических осях степенная зависимость — прямая, наклон которой равен показателю k.

Изложение. Сложность чаще всего видна по структуре кода, и несколько признаков покрывают большинство случаев. Цикл, проходящий по всему массиву, означает линейную сложность. Для вложенных циклов необходимо подсчитать суммарное число итераций внутреннего цикла, а не глубину вложенности: часто получается произведение длин, но не всегда. У решета Эратосфена два вложенных цикла, а работает оно за O(n log log n), поскольку внутренний цикл для простого p выполняется около n/p раз, а сумма обратных простых растёт как log log n. Деление пополам на каждом шаге означает логарифмическую сложность, а полный перебор всех комбинаций — экспоненциальную. Оценку по коду подтверждает эмпирическое правило, которое позволяет определить показатель степени по измерениям. Если время работы растёт как степень размера входа, t ~ N^k, то при удвоении N время возрастает в 2^k раз: вдвое для линейного алгоритма и вчетверо для квадратичного. Прологарифмировав, получим log t = k·log N + const: в логарифмических осях степенная зависимость изображается прямой, наклон которой равен показателю k. Для O(n log n) отношение немного больше двух, а наклон немного больше единицы, поскольку логарифм растёт медленнее любой степени. Таким образом, двух-трёх замеров с удвоением N достаточно, чтобы отличить линейный алгоритм от квадратичного, не заглядывая в код. Правило работает при одном условии: размеры должны быть достаточно велики, чтобы постоянные накладные расходы — вызов функции, создание объектов — не маскировали рост.

итерация Python — сотни машинных инструкций

Изложение. Оценим время исполнения цикла из 10⁹ итераций. Тактовая частота современного процессора составляет около 2,5 ГГц: за секунду проходит 2,5·10⁹ тактов. Если каждая итерация занимает один такт, получим t = 10⁹ · 1 / 2,5·10⁹ = 0,4 с. Глава уточняет, что итерация пустого цикла состоит из трёх действий — прибавить единицу, проверить условие и перейти к началу цикла, — и 3·10⁹ инструкций при одной инструкции за такт займут около 1,2 с. Такая оценка верна лишь по порядку величины. Тактовая частота и число инструкций в секунду являются разными величинами: суперскалярное ядро выполняет несколько независимых инструкций за такт, сложные инструкции занимают несколько тактов, а обращение к памяти может занять сотни тактов. Поэтому константу в оценке временной сложности заранее узнать не удаётся, и это ещё одна причина пользоваться O-нотацией. Интерпретатор Python добавляет свою константу: каждая итерация цикла на Python выполняется сотнями машинных инструкций — выборка байт-кода, проверка типов, поиск имён, создание объектов целых чисел, работа со счётчиками ссылок, — тогда как итерация того же цикла на C++ без оптимизации занимает около десяти инструкций. Сравнение с компилируемым языком требует осторожности. При сборке с оптимизацией -O2 компилятор обнаруживает, что переменная цикла нигде не используется, и удаляет цикл целиком, так что измерение показывает почти нулевое время. Это классическая ловушка микробенчмарков, и одного использования результата для её обхода недостаточно: если значение счётчика после цикла вычислимо заранее, как здесь i = 10⁹, компилятор подставляет готовое значение и цикл не выполняет (в GCC такая замена включена начиная с -O1). Поэтому счётчик объявляют volatile либо делают результат цикла зависящим от данных, неизвестных при компиляции.

Пояснение

При нехватке памяти операционная система переносит страницы в файл подкачки на диске, и программа замедляется на порядки даже при малой временной сложности.

Для физика

Таблица калибровки каналов детектора вместо пересчёта по формуле для каждого события — память в обмен на время.

Изложение. Временная сложность показывает, насколько экономно алгоритм расходует процессорное время; вторым ресурсом является оперативная память. Пространственной сложностью алгоритма называется зависимость объёма потребляемой памяти от размера входных данных; как и для времени, интерес представляет асимптотика, а не точный объём. Различают полную и дополнительную память. Вход занимает O(n) у любого алгоритма, поэтому при сравнении алгоритмов необходимо учитывать дополнительную память, сверх входных данных: без этой оговорки все решения одной задачи требовали бы одинаковых O(n), и сравнивать было бы нечего. Время и память допускают обмен. Сохранённая вспомогательная информация позволяет вычислять меньше: таблица заранее вычисленных значений, кеш результатов, индекс по ключу. Выбор не всегда прост: либо хранить больше и меньше вычислять, либо вычислять медленнее, но уложиться в отведённую память. Выход за пределы памяти обходится особенно дорого. Если программам не хватает оперативной памяти, операционная система переносит редко используемые страницы в файл подкачки на диске и возвращает их по мере обращения. Диск медленнее оперативной памяти на несколько порядков, поэтому программа замедляется на порядки даже при малой временной сложности, а когда исчерпан и файл подкачки, одна из программ завершается аварийно. Для физика типичный пример обмена — таблица калибровки детектора: поправки к каждому каналу вычисляются один раз и затем берутся из массива, а не пересчитываются по формуле для каждого события.

Изложение. Код, разделённый на функции, удобно тестировать: для каждой функции пишутся юнит-тесты. Необходимо продумать краевые случаи — входные данные, на которых программы отказывают чаще всего; таблица главы сводит их в три группы. Самый маленький тест — пустая строка, ноль или наименьшее допустимое отрицательное число, пустой набор данных. Самый большой тест — самая длинная строка и наибольшее число, допустимые условием, набор максимального размера; он позволяет проверить не столько ответ, сколько время и память, то есть оценку сложности. Особые случаи — строки с разным регистром, с кириллицей и латиницей, отрицательные числа, ноль, чётные и нечётные, вещественные числа, наборы с одинаковыми элементами, упорядоченные и неупорядоченные наборы. Пример ошибки, которую находит самый маленький тест, даёт решето Эратосфена в распространённой записи: строка numbers[0] = numbers[1] = False при n = 0 обращается ко второму элементу списка, состоящего из одного элемента, и завершается исключением IndexError. Исправление — отдельная ветвь для n < 2, показанная на слайде о решете. Наборы с одинаковыми элементами, в свою очередь, проверяют сортировки: быстрая сортировка, раскладывающая элементы лишь на две части — меньшие опоры и все остальные, — на таком наборе уходит в бесконечную рекурсию, которая в Python завершается исключением RecursionError.

Изложение. Задача главы: дана строка, требуется найти самый часто встречающийся в ней символ. Глава приводит три решения. Второе перебирает различные символы строки и для каждого проходит строку: N·K сравнений, где K — число различных символов, и O(K) памяти на их множество. def eratosthenes(n):
    if n < 2:
        return [False] * (n + 1)
    numbers = list(range(n + 1))
    numbers[0] = numbers[1] = False
    for num in range(2, math.isqrt(n) + 1):
        if numbers[num]:
            for j in range(num * num, n + 1, num):

Пояснение

Линейное решето записывает каждое составное число ровно один раз, на шаге i = x / lp[x].

Изложение. Простейшая проверка числа на простоту перебирает все возможные делители от 2 до n − 1; поиск всех простых до n таким способом требует порядка n² делений. Делители, превышающие √n, проверять необязательно: если n = a·b и a > √n, то b < √n, и делитель b был бы найден раньше. Это сокращает работу до O(n√n), однако для каждого числа делители по-прежнему перебираются заново. Решето Эратосфена устроено иначе: выписываются числа от 0 до n, 0 и 1 отмечаются как непростые, а затем для каждого очередного простого p отмечаются составными все кратные p. Отмечать их достаточно начиная с p², поскольку меньшие кратные уже отмечены меньшими простыми, а внешний цикл достаточно вести до √n. Решето работает за O(n log log n): для простого p внутренний цикл выполняет около n/p отметок, а сумма обратных простых растёт как log log n. Линейное решето выполняет O(n) операций: вместо отметок оно записывает для каждого числа x его наименьший простой делитель lp[x], и каждое составное число записывается ровно один раз — на шаге i = x / lp[x]. Множитель log log n растёт настолько медленно, что при n = 10⁶ составляет около 2,6, и разница в асимптотике легко перекрывается разницей констант — демонстрация это покажет. Решето требует O(n) памяти, тогда как перебор делителей — O(1): ещё один пример обмена памяти на время.

Важно

При вычитании близких величин совпадающие старшие цифры уничтожаются: остаются младшие, искажённые округлением.

Изложение. Оперативная память разбита на ячейки размером в один байт, и у каждой ячейки есть свой номер — адрес; процессор обращается к данным по адресам. Один байт из восьми бит позволяет закодировать 2⁸ = 256 значений, например целое число от 0 до 255 или символ ASCII типа char. Тип int в C++ обычно занимает 4 байта. Целые со знаком представлены в дополнительном коде: старший бит отвечает за знак, 2³¹ комбинаций отведены отрицательным числам от −2³¹ до −1, ещё 2³¹ — неотрицательным от 0 до 2³¹ − 1; ноль занимает один из неотрицательных кодов, поэтому положительных чисел на одно меньше, чем отрицательных. Беззнаковый unsigned int хранит числа от 0 до 2³² − 1, около 4,3 миллиарда. Вещественные числа чаще всего представлены типом double из 8 байт: 1 бит знака, 11 бит порядка и 52 бита мантиссы, к которым добавляется подразумеваемая старшая единица, — всего 53 двоичных разряда, около шестнадцати десятичных цифр. Диапазон double простирается до 10³⁰⁸ по модулю, однако диапазон не то же самое, что точность. Расстояние от единицы до следующего представимого числа называется машинным эпсилон и равно 2^−52 ≈ 2,2·10^−16; добавка, которую единица ещё различает при округлении к ближайшему, примерно вдвое меньше. Шаг сетки представимых чисел растёт вместе с самим числом, оставаясь относительным. Отсюда 0.1 + 0.2 ≠ 0.3: ни одна из этих дробей в двоичной записи не конечна. Отсюда же потеря точности при вычитании близких величин: совпадающие старшие цифры взаимно уничтожаются, и в разности остаётся столько верных цифр, сколько их было в различающейся младшей части.

Изложение. Структурой данных называется способ организации информации в памяти, позволяющий выполнять с ней определённый набор операций. Простейшая структура — массив постоянного размера: он хранит элементы одного типа в одном непрерывном участке памяти, нулевой элемент в начале участка и далее по порядку, без пропусков. Адрес участка программа получает в момент создания массива от распределителя памяти — функции malloc и её аналогов — или от указателя стека. Пусть массив numbers из десяти целых чисел типа int начинается с адреса 1000. Каждое число занимает 4 байта, нулевой элемент занимает байты с 1000 по 1003, и элемент с индексом 1 записан по адресу 1004; в общем случае адрес элемента i равен адресу начала плюс i, умноженному на размер элемента. Поэтому чтение и запись по индексу требуют одного вычисления адреса и выполняются за O(1), независимо от длины массива. Других операций у массива постоянного размера нет: добавить элемент или записать объект другого типа нельзя. В C такой массив объявляется как int numbers[10], в C++ — как std::array<int, 10>. Непрерывное расположение обеспечивает и второе преимущество, не видное в O-нотации: процессор загружает память не по байту, а строками кеша длиной 64–128 байт, и последовательный проход по массиву использует каждую загруженную строку целиком.

Элемент можно вставить в любую позицию i, однако все элементы правее неё приходится сдвинуть на одну позицию, и вставка требует O(n − i) операций. Пояснение

realloc расширяет блок на месте, если за ним свободно: оценка описывает худший случай.

Изложение. Когда ёмкость исчерпана, массив необходимо расширить. Расширить его на месте удаётся не всегда: если за участком в памяти уже лежат данные других объектов, расширение перезаписало бы их. Тогда программа производит реаллокацию: выделяет новый, больший участок и копирует туда накопленные элементы, что требует O(n) операций. Почему при этом добавление в конец требует в среднем O(1)? Рассмотрим две стратегии роста. Если увеличивать ёмкость каждый раз на 100 ячеек, реаллокации происходят в сто раз реже, чем при росте на одну ячейку, но при каждой из них копируется всё накопленное: 100 + 200 + … ≈ n²/200 копирований, то есть O(n²) в сумме и O(n) на одно добавление. Если же увеличивать ёмкость вдвое, то при 2^k < n ≤ 2^(k+1) суммарное число копирований равно 1 + 2 + … + 2^k = 2^(k+1) − 1 ≤ 2n, и на одно добавление приходится не более двух копирований. В общем случае при росте в r раз сумма копирований меньше n·r/(r − 1): геометрическая прогрессия сходится. Оценку такого рода называют амортизированной: редкие дорогие операции распределяются по всем дешёвым, и средняя стоимость остаётся постоянной. CPython растит список не вдвое, а примерно в 1,125 раза: новая ёмкость вычисляется как newsize + newsize/8 + 6 с округлением вниз до кратного четырём. Копирований при этом больше — оценка даёт не более девяти на элемент вместо двух, — но их число по-прежнему линейно, а запас ёмкости у больших списков составляет около 12,5 %. Отметим, что функция realloc расширяет блок на месте, если за ним свободно, и копирования не происходит вовсе; приведённая оценка описывает худший случай.

Пояснение

std::list в C++, LinkedList в Java; list в Python — динамический массив.

Изложение. Элементы массива расположены в памяти последовательно, поэтому вставка в начало и удаление из начала требуют O(n) операций. Структурой, не требующей при этом сдвигать остальные элементы, является связный список. В нём каждый элемент — узел — хранит значение и ссылку на следующий узел; последний узел ссылается в никуда, в Python — на None. Точку входа называют головой списка. Вставка нового узла после известного требует изменения двух ссылок и выполняется за O(1), независимо от длины списка. Платой за это является доступ по индексу: узлы лежат в памяти вразброс, и до нужного приходится идти от головы, перебирая звенья, что требует O(n) операций. Двигаться по односвязному списку можно только в одном направлении, поэтому быстро удалить узел не удаётся: неизвестно, какой узел на него ссылается, и поиск предыдущего требует O(n). Двусвязный список хранит ссылки в обе стороны и позволяет удалить узел за O(1). Узлы, разбросанные по памяти, удобны, когда элементов много и разместить их единым блоком не удаётся, однако последовательный проход по ним медленнее, чем по массиву: каждый переход к следующему узлу представляет собой обращение по новому адресу. Связный список присутствует в стандартных библиотеках многих языков: std::list в C++, LinkedList в Java. В Python класс list остаётся динамическим массивом, хотя и называется списком.

Пояснение

Стек — интерфейс, а не способ хранения: реализуется на массиве или на связном списке.

Изложение. Стек работает по принципу LIFO — last in, first out, «последним пришёл, первым ушёл»: извлечь можно только элемент, положенный последним. Наглядной моделью служит стопка книг в коробке: взять можно только верхнюю. В отличие от массивов и связных списков, стек представляет собой прежде всего интерфейс к данным, а не способ их хранения. Он определяет операции push — добавить элемент на вершину, pop — извлечь элемент с вершины, peek — получить вершину без извлечения, size — узнать число элементов, иногда также isEmpty. Обычно стек реализуют на массиве: добавление и удаление в конце динамического массива выполняются за O(1). Класс Stack главы делает именно это, используя список Python; тело класса записано с отступом в четыре пробела по PEP 8. Если элементов очень много и выделить под них единый блок невозможно, предпочтительнее связный список. На стеке реализована кнопка «назад» в браузере и отмена последних действий в редакторах, на нём основан обход дерева или графа в глубину, и, наконец, сам исполняемый код опирается на стек вызовов, которому посвящена следующая часть.

Для физика

deque(maxlen=1000) — скользящее окно из последней тысячи отсчётов детектора.

Изложение. Очередь работает по принципу FIFO — first in, first out: первым извлекается элемент, добавленный раньше всех, как в очереди к кассе. Как и стек, очередь задаёт интерфейс: push добавляет элемент в конец, pop извлекает из начала, peek возвращает начало без удаления, size — число элементов; реализуют её так, чтобы и вставка, и удаление выполнялись за O(1). Дек, от double-ended queue, представляет собой двустороннюю очередь: он позволяет добавлять и удалять элементы с любого конца за O(1). Дек обобщает обе структуры: работа с одним концом даёт стек, вход с одного конца и выход с другого — очередь. В Python дек находится в модуле collections. Класс deque устроен как цепочка связанных блоков по 64 ссылки: добавление к любому концу не затрагивает уже уложенные элементы, а при заполнении крайнего блока к цепочке присоединяется новый. Отдельного класса простой очереди для однопоточного кода в Python нет, её роль выполняет дек; классы queue.Queue и queue.SimpleQueue решают другую задачу — обмен данными между потоками, рассмотренный в лекции 9. Для физика дек ограниченной длины является готовым скользящим окном: deque(maxlen=1000) хранит последнюю тысячу отсчётов детектора, и при добавлении нового отсчёта самый старый удаляется автоматически, за O(1).

Важно

Хеш-таблицы и деревья поиска снимают ограничение O(n) на поиск по значению — лекция 18.

Изложение. Сводная таблица главы позволяет выбрать структуру под задачу. Массив постоянного размера даёт доступ по индексу за O(1), но не допускает вставок. Связный список вставляет в начало за O(1), но доступ по индексу требует O(n); добавление в конец списка, хранящего только голову, тоже требует O(n), а при ссылке на хвост — O(1), и так устроены реализации стандартных библиотек. Дек выполняет операции с обоими концами за O(1), а доступ к середине требует O(n). Правило выбора, работающее почти всегда, таково: если необходим произвольный доступ по индексу — список; если необходимы быстрые операции с обоими концами, а середина лишь пробегается целиком, — дек; вызовы insert(0, x) или pop(0) внутри цикла почти наверняка означают, что требуется дек. Универсальной структуры не существует: если элементы постоянно добавляются и снимаются с обоих концов, а в коде используется список, программа выполняет O(n) операций там, где достаточно O(1). Последний столбец таблицы объединяет все структуры: поиск по значению у каждой требует O(n) операций. Это ограничение снимают хеш-таблицы, в которых поиск выполняется в среднем за O(1), и сбалансированные деревья поиска с их O(log n); им посвящена лекция 18.

Изложение. Код программы разделён на функции, и вся программа представима как одна функция, вызывающая множество других. Пусть функция main вызывает функцию A, та вызывает B, а B — функцию C. После возврата из C управление должно вернуться в B, туда, откуда C была вызвана, поэтому при каждом вызове на стек вызовов помещается кадр: адрес инструкции, ожидающей выполнения после возврата, аргументы функции и её локальные переменные. Кадр выполняющейся функции лежит на вершине, под ним — кадры функций, ожидающих возврата. Рассмотрим пример главы: функция say_hello приветствует пользователя по имени и вызывает print_horoscope, передавая ей имя в верхнем регистре. При входе в say_hello на стеке выделяется кадр с аргументом name = 'Гоша'. Вызов print_horoscope кладёт поверх него новый кадр со своим name = 'ГОША'. Когда print_horoscope завершается, её кадр снимается, управление возвращается по сохранённому адресу, и в say_hello переменная name снова равна 'Гоша'. Таким образом, одноимённые переменные разных вызовов не конфликтуют: каждая существует в своём кадре. Вызовы print и upper на схеме не показаны, хотя и они помещаются на стек и снимаются с него. Кадр существует, пока функция не вернула управление, поэтому глубина стека в каждый момент равна длине цепочки незавершённых вызовов.

Память

O(d) на стеке, d — глубина рекурсии

Важно

Бесконечная рекурсия в Python не зависает: примерно через 1000 вызовов возникает RecursionError.

Изложение. Функция, вызывающая саму себя с изменёнными аргументами, называется рекурсивной; она пользуется тем же стеком вызовов. Корректная рекурсия состоит из двух частей. Рекурсивный случай сводит задачу к меньшей: функция stairs_builder главы строит одну ступеньку, сообщает, что осталось построить n − 1 ступеней, и вызывает себя для оставшихся. Базовый случай останавливает углубление и вычисляет ответ явно, без рекурсивного вызова: при n = 0 строить больше нечего. Факториал записывается так же: n! = n·(n − 1)!, а 0! = 1! = 1 составляет базовый случай. Типичных ошибок две: пропущенный базовый случай и параметр, который в рекурсивном вызове не меняется или меняется не в сторону базового случая; в обоих случаях цепочка вызовов не обрывается. Необходимо убедиться, что при любом допустимом входе функция за конечное число шагов сводится к базовому случаю. Каждый уровень рекурсии хранит на стеке свой кадр, поэтому рекурсия глубины d требует O(d) памяти, и вычисление n! расходует O(n). Бесконечная рекурсия не работает вечно и не приводит к зависанию: каждый вызов расходует память стека, а она ограничена. В Python углубление останавливает сам интерпретатор: примерно после тысячи вложенных вызовов возникает исключение RecursionError.

Изложение. Ограничений глубины рекурсии два. Первое устанавливает интерпретатор: по умолчанию sys.getrecursionlimit() возвращает 1000, и при превышении предела возникает RecursionError; функция sys.setrecursionlimit() позволяет поднять порог. Второе ограничение — стек потока операционной системы, обычно 8 МБ; его достигают, только сняв первое. Здесь важна версия Python. До версии 3.10 включительно каждый вызов питоновской функции рекурсивно вызывал функцию интерпретатора на C и расходовал стек C, поэтому даже с поднятым порогом рекурсию глубже нескольких десятков тысяч уровней довести было нельзя: на Python 3.9 глубина 30 000 проходит, а на 50 000 процесс завершается аварийно. Начиная с 3.11 вызов одной питоновской функции из другой обходится без рекурсии на C, и чистая рекурсия с поднятым порогом достигает миллиона уровней, расходуя память кучи. Если же цепочка вызовов проходит через код на C, например через метод __repr__, вызываемый встроенной функцией, стек C по-прежнему расходуется на каждом уровне, и в 3.11 такая рекурсия на глубине в несколько десятков тысяч уровней завершает процесс аварийно, без исключения. В 3.12 предел интерпретатора распространяется только на код Python, а рекурсию через код на C ограничивает отдельный механизм. Фактический предел, таким образом, определяется памятью, а для вызовов через код на C — размером стека потока. В разных языках переполнение стека проявляется по-разному: исключением StackOverflowError в Java или ошибкой сегментации в программе на C.

def length(e):              # явный стек
    stack, count = [e], 0
    while stack:
        cur = stack.pop()
        if cur is not None:
            count += 1
            stack.append(cur.nxt)
    return count

Пояснение

Рекурсия экономит время программиста, но не процессора: вызов функции дороже итерации цикла.

Изложение. Против переполнения стека применяются два приёма. Иногда рекурсию можно заменить циклом: факториал вычисляется накоплением произведения в переменной, стек вызовов не растёт вовсе, а память составляет O(1). В общем случае, например при обходе дерева каталогов, вместо стека вызовов используется собственный стек — список, в который складываются ещё не обработанные элементы: такой стек позволяет обойти предел интерпретатора, и ограничением становится лишь доступная память. Функция length подсчитывает длину цепочки именно так. Отдельный случай представляет хвостовая рекурсия, в которой рекурсивный вызов является последним действием функции. Компиляторы ряда языков превращают такой вызов в переход без нового кадра, однако CPython этого не делает: интерпретатор сохраняет полную трассировку стека для сообщений об ошибках, и хвостовая рекурсия расходует стек так же, как обычная. Рекурсия не ускоряет работу программы и, как показало измерение, может её замедлить: каждый вызов функции дороже итерации цикла. Вместе с тем рекурсия экономит время программиста: код, написанный рекурсивно, получается компактным и понятным, и для задач, рекурсивных по своей природе, — обхода деревьев, разбиения пополам, перебора вариантов — он проще и надёжнее цикла, нагруженного счётчиками.

Для физика

2^n конфигураций n корректоров: при n = 64 — 1,8·10¹⁹, полный перебор невозможен.

Изложение. Рекурсия часто применяется для генерации объектов, устроенных единообразно, например последовательностей. Рассмотрим генерацию всех последовательностей длины n из нулей и единиц. Функция generate принимает число n ещё не дописанных символов и строку prefix, накопленную к этому моменту. Базовый случай — n = 0: строка готова и печатается. В рекурсивном случае функция вызывает себя дважды: в первый раз дописывая к prefix цифру 0, во второй — цифру 1, и каждый раз уменьшая n на единицу. Решение удобно представлять бинарным деревом, растущим от пустой строки: переход влево соответствует приписыванию 0, вправо — приписыванию 1. Дерево имеет глубину n, а его листья — ровно 2^n построенных последовательностей. Глубина рекурсии, а значит и память стека, составляет всего O(n), тогда как число вызовов пропорционально числу листьев, O(2^n); поскольку каждый лист строит и печатает строку длины n, точная оценка времени составляет O(n·2^n). К той же схеме сводится перебор подмножеств: если каждый из n предметов может быть взят или отложен, набор описывается строкой, где 1 означает взятый предмет, а 0 — отложенный, и наборов ровно 2^n. Для физика такую структуру имеет, например, перебор конфигураций n корректоров, каждый из которых включён или выключен: при n = 20 конфигураций около миллиона, при n = 64 — 1,8·10¹⁹, и полный перебор невозможен; необходимо применять методы, отбрасывающие заведомо неудачные ветви дерева.

Изложение. Сортировки представляют собой алгоритмы, упорядочивающие данные: контакты в телефоне показываются по алфавиту, расписание составляется по времени отправления, поисковая система ранжирует ответы по релевантности. Во многих задачах с упорядоченными данными работать проще. Найти элемент быстрее чем за O(n), воспользовавшись бинарным поиском, возможно только в упорядоченном массиве. Таблицу «10 лучших» проще собрать из списка, упорядоченного по нужному признаку. Нередко сортировка становится узким местом всего решения. Лучшей сортировки в общем случае не существует: для данных разной природы и разных ограничений выигрывают разные алгоритмы. Глава иллюстрирует выбор двумя ситуациями. В первой данные лежат на старом сервере, где почти не осталось свободной памяти, а отчёт требуется через неделю: предпочтительнее более медленный алгоритм, обходящийся O(1) дополнительной памяти. Во второй на новом мощном сервере каждую секунду обновляется рейтинг, и список лучших необходимо пересчитывать без задержек: предпочтительнее быстрый алгоритм, требующий больше памяти. Обстоятельств, определяющих выбор, три: срочность ответа; объём входных данных — тысячу элементов любой алгоритм упорядочит за неощутимое время, а на пяти миллионах разница становится решающей; объём свободной памяти, позволяющий или не позволяющий собрать результат во второй копии массива.

Изложение. Сортировка, сохраняющая взаимный порядок элементов с равным значением сравниваемого признака, называется устойчивой. Разница важна, когда данные сортируют несколько раз подряд по разным ключам: устойчивая сортировка сохраняет результат предыдущего прохода, а неустойчивая его перемешивает. Пусть события двух детекторов упорядочены по времени; после второго прохода по номеру детектора устойчивая сортировка оставит события каждого детектора в порядке времени. Признак, по которому элементы сравниваются, называется ключом сортировки. Функции сортировки задают порядок двумя способами. Функция одного аргумента key вычисляет ключ для каждого объекта; sorted и list.sort в Python вызывают её один раз на элемент и сравнивают вычисленные ключи. Компаратор — функция двух аргументов, сравнивающая объекты напрямую, — задаёт порядок гибче, и сортировку по любому ключу легко переписать через компаратор. Обратное преобразование выполняет обёртка functools.cmp_to_key; однако компаратор вызывается на каждом сравнении, и не всякий компаратор задаёт корректный порядок, поэтому обычно проще пользоваться ключом. Сортировка по нескольким признакам сразу записывается составным ключом-кортежем: кортежи сравниваются поэлементно, сначала по детектору, затем по времени, и результат совпадает с двумя последовательными проходами устойчивой сортировки.

def merge(left, right):
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if right[j] < left[i]:  # равные — из левой
            merged.append(right[j])
            j += 1
        else:
            merged.append(left[i])
            i += 1
    return merged + left[i:] + right[j:]

Изложение. Сортировка слиянием складывается из трёх действий, повторяемых на каждом уровне: массив разбивается на две части примерно одинакового размера, каждая часть сортируется тем же алгоритмом рекурсивно, а две упорядоченные части сливаются в одну. Базовый случай — массив из одного элемента, уже отсортированный. Слияние выполняется одним проходом: из головных элементов двух частей каждый раз забирается меньший, а хвост, оставшийся от одной из частей, дописывается целиком. Оценим сложность. Разбиение пополам продолжается, пока длина части не станет равной единице, поэтому глубина рекурсии составляет log₂ n уровней. На каждом уровне все части вместе содержат n элементов, и слияния уровня требуют O(n) операций. Получим O(n log n), причём в худшем случае так же, как в среднем: от входных данных глубина не зависит. Дополнительная память составляет O(n). В приведённой реализации срезы и слитые списки создаются заново, однако одновременно существуют только списки текущей ветви рекурсии: n/2 + n/4 + … < n элементов и результат слияния. Сортировка слиянием устойчива: при равенстве головных элементов приоритет отдаётся элементу левой части, и это правило обеспечивает сохранение взаимного порядка равных элементов на каждом уровне, вплоть до последнего слияния.

    less, equal, greater = [], [], []
    for num in nums:
        if num < pivot:
            less.append(num)

Изложение. Быстрая сортировка, предложенная Ч. Хоаром, опирается на стратегию «разделяй и властвуй», но распределяет работу иначе, чем слияние: разделение на части сложнее, а части, отсортированные рекурсивно, объединяются простым дописыванием. Выбирается опорный элемент; элементы, меньшие опоры, раскладываются в один массив, большие — в другой, а равные опоре остаются посередине и в рекурсию больше не передаются: без этой предосторожности массив одинаковых чисел приводил бы к бесконечной рекурсии. Разбиение выполняется одним проходом за O(n). Если опора делит массив примерно пополам, уровней рекурсии O(log n), и сложность составляет O(n log n) в среднем. Если же опорой оказывается максимум или минимум, длина части уменьшается лишь на единицу, уровней становится n, и сложность возрастает до O(n²). Под любое простое фиксированное правило — первый элемент, средний, медиана трёх — можно подобрать вырождающий массив (гарантию O(n log n) даёт лишь опора, равная точной медиане, найденной за линейное время, но такой выбор сильно увеличивает константу); при случайной опоре плохое разбиение зависит не от данных, а от жребия, и вероятность квадратичного исхода исчезающе мала. Версия главы с тремя новыми списками требует O(n) дополнительной памяти, и на практике от неё избавляются, выполняя разбиение на месте: по схеме Ломуто массив проходится один раз, и каждый элемент, меньший опоры, меняется местами с элементом на границе. Памяти такой сортировке почти не требуется — только стек вызовов, O(log n) при удачных разбиениях. Однако разбиение на месте неустойчиво: элементы перебрасываются через весь массив. Версия с тремя списками, напротив, порядок равных сохраняет, что и подтвердила демонстрация устойчивости.

Изложение. Встроенные sorted() и list.sort() реализуют Timsort — гибрид сортировки слиянием и вставками, предложенный Т. Петерсом для Python в 2002 году. Алгоритм находит во входе уже упорядоченные участки — серии, — короткие серии удлиняет сортировкой вставками до нескольких десятков элементов, а затем сливает серии попарно. Если при слиянии одна серия выигрывает сравнение много раз подряд, включается галоп — экспоненциальный поиск места, с которого начинается следующий блок, что позволяет переносить целые участки без поэлементного сравнения. Сортировка устойчива и адаптивна: на упорядоченном входе она выполняет n − 1 сравнений и O(n) операций. Начиная с версии 3.11 порядок слияния серий выбирается по правилу powersort, остальное устройство Timsort сохранилось. Сравним с нижней границей. Любая сортировка сравнением должна различить все n! перестановок входа, а каждое сравнение даёт не более одного бита информации, поэтому в худшем случае необходимо не менее log₂(n!) ≈ n·log₂ n − 1,44n сравнений; при n = 1000 это 8529. Сортировка слиянием и Timsort на случайных данных к этой границе близки. В стандартных библиотеках C++ функция std::sort в распространённых реализациях, libstdc++ и libc++, представляет собой интроспективную сортировку: быструю сортировку, переходящую к пирамидальной при слишком глубокой рекурсии; стандарт требует лишь O(n log n) сравнений. Вывод главы остаётся в силе: собственную сортировку в рабочем коде писать незачем, поскольку встроенная почти всегда быстрее и лучше отлажена, — в демонстрации разница составила от 7 до 100 раз. Изложение. Отсортировать быстрее чем за O(n log n) возможно, но лишь для узкого класса задач, устроенных особым образом. Пример главы — массив чисел, обозначающих номера месяцев от 0 до 11. Заводится массив из 12 счётчиков, заполненный нулями; проход по исходному массиву увеличивает счётчик каждого встреченного месяца; затем проход по счётчикам выписывает каждый номер столько раз, сколько накоплено в его счётчике. Для значений от 0 до k − 1 алгоритм выполняет O(n + k) операций и требует O(k) памяти на счётчики и O(n) на результат. Элементы ни разу не сравниваются друг с другом, поэтому граница log₂(n!), доказанная для сортировок сравнением, на сортировку подсчётом не распространяется. Выигрыш сохраняется, пока k сопоставимо с n: сортировать подсчётом миллион чисел, разбросанных по диапазону до миллиарда, бессмысленно — массив счётчиков окажется в тысячу раз длиннее исходного. Приведённая реализация восстанавливает массив из одних счётчиков: она годится для чисел, но записи, привязанные к ключам, не переносит вовсе. Для записей необходим устойчивый вариант. По массиву счётчиков вычисляются префиксные суммы — позиции, с которых начинаются блоки значений, — и затем каждая запись ставится на очередное место своего блока; записи перебираются слева направо, и после каждой граница её блока сдвигается на одну позицию вперёд, поэтому записи с равными ключами сохраняют исходный порядок. Проход справа налево также устойчив, однако для него префиксные суммы должны давать концы блоков, а граница перед каждой записью уменьшается; с началами блоков такой проход выводит записи за пределы своего блока. Сортировка подсчётом на чистом Python занимает 22,5 мс, встроенная sorted() — 84,7 мс, в 3,8 раза дольше: алгоритм O(n + k), написанный на интерпретируемом языке, оказывается быстрее реализации O(n log n) на C. Второй проход в сценарии выписывает каждый блок одним вызовом extend, а не вложенным циклом с append, как в листинге главы на предыдущем слайде; с циклом главы подсчёт занимает примерно на четверть больше времени, но остаётся более чем вдвое быстрее sorted(). Счёт операций это объясняет: подсчёт выполняет n + k = 1 004 096 операций, а сортировка сравнением — порядка n·log₂ n ≈ 2·10⁷ сравнений. В NumPy та же пара — bincount с repeat против np.sort — даёт 1,0 и 1,8 мс. Второй запуск показывает устойчивый вариант с префиксными суммами на 20 записях вида «канал:номер события». После сортировки по каналу номера событий внутри каждого канала возрастают, и результат совпадает с устойчивой sorted(). Последние строки показывают предел применимости: для 12-битного кода счётчики занимают 32 КиБ, для 16-битного — 512 КиБ, для 24-битного — 128 МиБ, а для 30-битного — 8 ГиБ, больше всей памяти стенда; при таком k подсчёт теряет смысл. Третий запуск строит рисунок массива счётчиков.

Изложение. Подведём итоги. Сложность алгоритма оценивается до запуска и подтверждается измерением: при удвоении N линейный алгоритм замедляется вдвое, квадратичный — вчетверо, а в логарифмических осях наклон прямой равен показателю степени. Константы, отброшенные O-нотацией, определяют применимость при конкретных размерах данных: линейное решето оказалось не быстрее классического, а функция на C при той же сложности быстрее в девять раз. Память является вторым ресурсом: объекты Python занимают в 4–17 раз больше памяти, чем те же данные в массиве NumPy, а геометрический рост ёмкости обеспечивает списку O(1) на добавление в среднем — не более девяти копирований на элемент при росте в 1,125 раза. Список подходит для доступа по индексу, дек — для работы с концами, и рост отношения времён с N указывает на разную сложность. Глубина рекурсии ограничена интерпретатором и стеком, а явный стек снимает предел. Сортировка сравнением не может выполнить меньше log₂(n!) сравнений в худшем случае, а сортировка подсчётом обходит эту границу при малом диапазоне значений. Наконец, устойчивость сортировки необходима, когда данные упорядочивают по нескольким ключам.
