Цель лекции

Класс как модель объекта: состояние, его согласованность, единый интерфейс

Класс связывает данные с операциями над ними: вместо разрозненных переменных и обрабатывающих их функций получается объект, отвечающий за своё состояние. Классы в Python не обязательны — модуль из функций остаётся полноценной программой, а класс нужен там, где есть состояние, которое требуется поддерживать согласованным, или где одну операцию выполняют по-разному для объектов разного вида.

Изложение. Класс решает две задачи. Первая — согласованность состояния: данные объекта предполагается менять через его методы и свойства, которые проверяют допустимые значения и пересчитывают зависимые величины, поэтому объект не оказывается в противоречивом состоянии. Вторая — единый интерфейс: объекты разных классов с одинаковыми методами обрабатываются одним кодом, не проверяющим их тип. В Python классы не обязательны: модуль из десятка функций является полноценной программой, и оформлять его в виде класса без явной причины не требуется. От Java и C++ Python отличается тем, что не скрывает механику: экземпляр передаётся методу явным первым аргументом, а почти всё, что выглядит особым свойством языка, сводится к нескольким протоколам, разобранным в лекции. Для физиков: объектами являются массив NumPy, фигура и оси Matplotlib, результат scipy.optimize.minimize; понимание классов объясняет, как устроены эти библиотеки, и позволяет описывать собственные модели — частицы, детекторы, результаты измерений — так же удобно.

class Particle:
    """Материальная точка."""
 
    def __init__(self, mass, v=0.0):
        self.mass = mass
        self.v = v
 
    def kinetic_energy(self):
        return self.mass * self.v ** 2 / 2
 
p = Particle(2.0, v=3.0)
p.kinetic_energy()       # 9.0

Пояснение

Методы — функции в теле класса; self — обычный параметр, имя которого закреплено соглашением.

Изложение. Класс объявляется инструкцией class: её тело выполняется при выполнении инструкции — обычно один раз, при импорте модуля, — и получившиеся имена — функции и значения — становятся атрибутами класса. Вызов класса как функции создаёт экземпляр и передаёт аргументы методу __init__, который записывает начальное состояние в атрибуты экземпляра через self. Методы — обычные функции, объявленные в теле класса; первым параметром они получают экземпляр, на котором вызваны, и по правилу «явное лучше неявного» этот параметр объявляется явно. Имя self является соглашением, а не ключевым словом. По PEP 8 имена классов записываются в стиле CapWords (Particle, MeasurementSeries), а имена методов и атрибутов — строчными буквами с подчёркиваниями. Для физиков: класс Particle объединяет массу и скорость с величинами, вычисляемыми из них; функция kinetic_energy(m, v) из прошлой лекции становится методом, которому параметры не передаются: они уже хранятся в объекте.

class PositiveFloat(float):
    def __new__(cls, value):
        if value <= 0:
            raise ValueError("нужно > 0")
        return super().__new__(cls, value)
 
PositiveFloat(2.5) + 1   # 3.5
PositiveFloat(-1)        # ValueError

Пояснение

__init__ называют конструктором условно: объект уже создан методом __new__. У неизменяемых типов значение задаётся в __new__.

Изложение. Вызов класса выполняется в два шага. Сначала метод __new__ создаёт объект — пустую заготовку нужного класса; затем, если __new__ вернул экземпляр этого класса, вызывается __init__, который заполняет атрибуты. Поэтому название «конструктор», закрепившееся за __init__, условно: к его вызову объект уже существует. Переопределять __new__ приходится редко — при наследовании от неизменяемых типов (int, float, str, tuple), у которых значение задаётся при создании и в __init__ его уже не изменить, а также для кеширования экземпляров. Рассмотрим класс PositiveFloat на слайде: он наследует float и проверяет значение до создания объекта. __new__ получает те же аргументы, что и вызов класса, поэтому значение доступно ему до создания объекта; результат остаётся числом, и PositiveFloat(2.5) + 1 даёт обычный float 3.5. Для физиков: подкласс float с проверкой знака подходит для величин, положительных по смыслу, — масс, времён жизни, концентраций: объект проверен при создании и при этом участвует в арифметике как обычное число. Результат арифметики — обычный float, и проверка на него уже не действует: PositiveFloat(2.5) - 3 даёт -0.5.

Одно подчёркивание в начале означает внутренний атрибут, к которому код снаружи класса не обращается; язык это не проверяет, но это учитывают линтеры и автодополнение, а у имён модуля — и from module import *. Два подчёркивания в начале включают искажение имени (name mangling): внутри класса Particle имя __tag заменяется на _Particle__tag. Механизм защищает от случайного совпадения имён в базовом классе и подклассе — если оба объявят __cache, атрибуты не столкнутся, — а не скрывает данные: по полному имени атрибут доступен. Имена с двумя подчёркиваниями с обеих сторон, такие как __init__, зарезервированы для специальных методов и не искажаются.

Изложение. Атрибут, объявленный в теле класса, принадлежит классу и один на все экземпляры; атрибут, присвоенный через self, принадлежит экземпляру. При чтении a.unit интерпретатор ищет имя сначала в словаре экземпляра, затем в словаре класса, затем в базовых классах в порядке MRO; порядок MRO рассматривается в третьей части, а исключения из этой схемы — дескрипторы — в пятой. Присваивание a.unit = "MeV" записывает значение в словарь экземпляра и заслоняет атрибут класса только у этого экземпляра; после del a.unit снова виден атрибут класса. Атрибуты класса подходят для констант, настроек по умолчанию и общих реестров. Изменяемый атрибут класса создаётся один раз при выполнении тела класса — та же ловушка, что у изменяемых значений по умолчанию: список hits оказывается общим для всех детекторов, а список, свой для каждого экземпляра, необходимо создавать в __init__. Для физиков: единицы измерения и калибровочные константы, общие для всех детекторов одного типа, естественно хранить в атрибутах класса, а накопленные отсчёты конкретного детектора — только в атрибутах экземпляра.

Важно

Опечатка в присваивании не вызывает ошибки: det.treshold = 0.2 создаёт новый атрибут.

Изложение. Атрибуты экземпляра хранятся в словаре __dict__; функция vars(obj) возвращает тот же словарь. Отсюда динамика: атрибут добавляется и после создания объекта, а функции getattr, setattr, hasattr и delattr работают с именем, заданным строкой во время выполнения, например при загрузке настроек из файла. getattr с третьим аргументом возвращает значение по умолчанию вместо AttributeError. Оборотная сторона той же свободы — опечатка в имени при присваивании без предупреждения создаёт новый атрибут, а прежний остаётся без изменений. Защиту обеспечивают __slots__ на следующем слайде, классы данных с параметром slots=True или frozen=True из второй части и статические анализаторы. Для физиков: параметры моделирования, прочитанные из YAML или JSON, переносятся в объект циклом с setattr; при этом имена целесообразно проверять по списку допустимых, иначе опечатка в файле настроек без сообщения об ошибке создаст лишний параметр, а нужный останется со значением по умолчанию.

Для физика

Для миллионов объектов-событий применяется __slots__, для массивов чисел — NumPy: событие из двух float64 занимает 16 байт.

Изложение. Словарь у каждого экземпляра обеспечивает гибкость, но занимает память. Атрибут класса __slots__ перечисляет допустимые атрибуты заранее, и интерпретатор хранит значения в фиксированных ячейках объекта без словаря. Замер в Python 3.12 для объекта с двумя полями, включающий 8 байт ссылки на него в списке, даёт 88 байт для обычного класса, пока к __dict__ не обращались, 152 байта после создания словаря и 56 байт со __slots__. Взамен теряется динамика: атрибут вне списка вызывает AttributeError, слабые ссылки работают, только если '__weakref__' указан в слотах, а подкласс без собственного __slots__ снова получает словарь. Скорость доступа к атрибутам меняется мало. Таким образом, __slots__ добавляют, когда профилирование показало, что память расходуется на множество мелких объектов. Для физиков: к памяти самих объектов добавляются числа: каждое отдельное значение float — объект в 24 байта. Миллион событий из двух чисел в объектах со __slots__ занимает около 100 МБ, а в структурированном массиве NumPy из двух float64 — 16 МБ вместе со значениями; для массовых данных объекты заменяются массивами.

Пояснение

Алгоритм C3: подкласс раньше родителей, порядок родителей сохраняется, каждый класс — один раз.

Изложение. Родителей у класса может быть несколько. Порядок, в котором интерпретатор перебирает классы при поиске атрибута, называется MRO (method resolution order) и хранится в атрибуте __mro__; метод mro() возвращает тот же порядок списком. Его вычисляет алгоритм линеаризации C3, предложенный для языка Dylan и используемый в Python с версии 2.3. Он обеспечивает три гарантии: подкласс предшествует своим родителям, порядок родителей в объявлении сохраняется, каждый класс встречается один раз. В ромбе D(B, C) с общим предком A порядок — D, B, C, A, object: A проверяется после обоих своих подклассов. Если требования противоречат друг другу, как в class Bad(A, B), где B — подкласс A, но указан в списке базовых классов после него, класс не создаётся и возникает TypeError. Для физиков: множественное наследование встречается в библиотеках визуализации и графических интерфейсов, где виджеты собираются из примесей; в расчётном коде иерархии обычно неглубокие.

Примесь (mixin) представляет собой класс, который не описывает самостоятельную сущность, а добавляет к чужому классу одну черту: строковое представление, преобразование в словарь, журналирование, блокировку. Важно

Признак неудачного наследования: подкласс отключает унаследованные методы или нарушает гарантии родителя.

Изложение. Наследование выражает отношение «является»: электрон — частица, и любой код, работающий с частицей, обязан работать и с электроном (принцип подстановки Лисков). Если же объект лишь использует другой — детектор состоит из каналов, ускоритель — из магнитов и резонаторов, — это композиция: объект хранит другие объекты в атрибутах и поручает им работу. Композицию проще понимать и тестировать, её части заменяются независимо, а глубокие иерархии наследования связывают классы жёстко. Признак неудачного наследования — подкласс, отключающий унаследованные методы или меняющий их смысл, как квадрат, унаследованный от прямоугольника с независимо изменяемыми сторонами. Таким образом, прежде чем строить иерархию, проверяют, не решается ли задача композицией: объект, содержащий другой объект, почти всегда проще объекта, унаследованного от него. Для физиков: модель установки собирается из объектов-компонентов: магнитная структура ускорителя — список элементов (дрейф, квадруполь, диполь) с общим методом матрицы перехода, а не иерархия, в которой ускоритель наследуется от квадруполя.

    @abstractmethod
    def step(self, f, t, y, h): ...
 
    def run(self, f, y0, t0, t1, n):
        h, t, y = (t1 - t0) / n, t0, y0
        for _ in range(n):
            y, t = self.step(f, t, y, h), t + h
        return y
 
class Euler(Integrator):
    def step(self, f, t, y, h):
        return y + h * f(t, y)

Важно

Специальные методы ищутся у типа, а не у экземпляра: присваивание obj.__len__ = ... не меняет len(obj).

Изложение. Модель данных Python представляет собой набор специальных методов, через которые объект участвует в синтаксисе и встроенных функциях. Их имена окружены двойными подчёркиваниями, и вызывает их интерпретатор, а не программист: len(x) вызывает x.__len__(), выражение x + y — x.__add__(y), цикл for — x.__iter__(). При определении нужных методов собственный класс ведёт себя как встроенный тип: складывается, сравнивается, индексируется, перебирается в цикле, печатается. Неявный вызов ищет специальный метод у типа объекта, минуя словарь экземпляра, поэтому метод, присвоенный экземпляру, не действует на len(x) или +; так сделано и ради скорости, и ради корректности для самих классов, которые тоже объекты. Полный перечень методов — раздел Data model справочника языка; протокол менеджеров контекста (__enter__ и __exit__) в рамках лекции не рассматривается, его описывает раздел With Statement Context Managers справочника языка. Для физиков: NumPy построен на той же модели данных: массив определяет __add__, __mul__, __getitem__ и десятки других методов, поэтому выражение a * b + c записывается для массивов так же, как для чисел.

Важно

Равные объекты обязаны иметь равные хеши; объект, изменившийся после попадания в множество, поиск в нём его не находит.

Изложение. Шесть методов сравнения — __eq__, __ne__, __lt__, __le__, __gt__, __ge__ — записывать полностью не требуется: __ne__ по умолчанию обращает результат __eq__, а декоратор functools.total_ordering достраивает остальные по __eq__ и одному из методов упорядочивания. Определение __eq__ без __hash__ делает класс нехешируемым: интерпретатор присваивает __hash__ = None, и объект не попадает в множество и в ключи словаря. Причина — правило «равные объекты имеют равные хеши»: хеш по умолчанию основан на идентичности объекта и с новым равенством не согласован. Если объект хешируемый, хеш вычисляют из тех же полей, что участвуют в сравнении, и только для объектов, которые после создания не меняются: изменение поля после помещения в множество делает объект ненаходимым. Заметим, что сравнение с объектом другого типа завершается возвратом NotImplemented, как в арифметике: тогда Energy(1) == None даёт False, а не AttributeError, а Energy(1) < 1 — понятный TypeError. Для физиков: энергетические уровни, версии калибровок и прогоны с номерами сортируются и сравниваются по одному полю; total_ordering избавляет от записи остальных методов сравнения.

С __len__ и __getitem__ объект уже перебирается в цикле; полный набор методов последовательности даёт collections.abc.Sequence.

Изложение. Коллекции определяются протоколами — наборами методов. __len__ даёт функцию len и, при отсутствии __bool__, истинность: пустая коллекция ложна. __getitem__ даёт индексирование, а получив объект slice — срезы. Современным протоколом перебора является метод __iter__, возвращающий итератор; он рассматривается в лекции об итераторах, генераторах и корутинах. __contains__ ускоряет проверку in, если ответ получается без перебора. Наследование от collections.abc.Sequence добавит index, count и __reversed__ по тем же двум методам. Изложение. Метод __call__ делает экземпляр вызываемым: g(x) выполняет g.__call__(x). Такой объект подходит везде, где ожидается функция: в интеграторе, оптимизаторе, в sorted как ключ, и функция callable(g) возвращает для него True. По сравнению с замыканием и partial из прошлой лекции объект с __call__ хранит параметры в именованных атрибутах, что позволяет читать и изменять их; у объекта есть repr и могут быть другие методы — нормировка, производная, построение графика. На __call__ построены декораторы, реализованные классами, и объекты, сохраняющие состояние между вызовами. Для физиков: модели для curve_fit удобнее писать функциями с параметрами-аргументами, а для интегрирования и построения графиков с найденными параметрами — объектами с __call__, такими как Gaussian(mu, sigma).

Изложение. Четыре метода перехватывают работу с атрибутами. __getattr__ вызывается только тогда, когда обычный поиск не нашёл атрибут, поэтому подходит для подстановки значений, объектов-посредников и ленивой загрузки. __getattribute__ вызывается при любом чтении и переопределяется редко: ошибка в нём нарушает доступ ко всем атрибутам, включая служебные. Тонкость __getattr__: он вызывается при любой AttributeError обычного поиска, в том числе возникшей внутри геттера свойства, и тем самым маскирует ошибку в свойстве. __setattr__ и __delattr__ перехватывают любую запись и любое удаление; внутри них запись необходимо выполнять через object.__setattr__ или super().__setattr__, иначе self.name = value снова вызовет перехватчик и приведёт к бесконечной рекурсии. Для неизвестного имени __getattr__ обязан возбуждать AttributeError, а не KeyError: на этом основаны hasattr, getattr со значением по умолчанию, копирование copy и сериализация pickle. Для физиков: объект настроек с доступом через точку и запретом записи защищает параметры расчёта от случайного изменения посреди программы.

Изложение. Дескриптор является объектом, класс которого определяет хотя бы один из методов __get__, __set__, __delete__. Помещённый в атрибут класса, он перехватывает обращение к этому атрибуту у всех экземпляров: чтение obj.x вызывает __get__(obj, type(obj)), запись — __set__, удаление — __delete__. Метод __set_name__ (3.6, PEP 487) вызывается при создании класса и сообщает дескриптору имя, под которым он записан. Дескрипторы данных определяют __set__ или __delete__, остальные — только __get__. Порядок поиска при чтении атрибута: дескриптор данных в классе и его базовых классах имеет приоритет над словарём экземпляра, словарь экземпляра — над дескриптором не данных и обычным атрибутом класса, а __getattr__ вызывается последним. Таким образом, свойство нельзя заслонить атрибутом экземпляра, а метод — можно.

Пояснение

Каждый шаг — точка вмешательства: от простого декоратора до метакласса.

Изложение. Создание класса проходит несколько шагов, и каждый даёт точку вмешательства. Сначала выбирается метакласс — наиболее производный из указанного аргументом metaclass и метаклассов базовых классов, при их отсутствии — type. Воспользуемся метаклассом Meta, который печатает имя создаваемого класса и ключи его пространства имён: для Detector — __module__, __qualname__ и gain; подкласс Tracker создаётся тем же метаклассом без явного указания. Базовый класс Integrator с __init_subclass__ регистрирует подкласс Euler под именем 'euler', переданным в строке объявления, а промежуточный ImplicitEuler без имени создаётся и в реестр не попадает. Перечисление Spin — экземпляр метакласса EnumType, и Spin(-1) возвращает член DOWN.

Пояснение

Сверху вниз растут возможности и сложность: выбирается первое средство, решающее задачу.

Изложение. Механизмы лекции упорядочены от простого к сложному. Для записи с именованными полями достаточно dataclass. Проверка или вычисление одного атрибута — свойство. Одна и та же проверка для многих атрибутов — дескриптор. Общий интерфейс и общий алгоритм для семейства классов — абстрактный базовый класс или протокол. Поведение встроенного типа — магические методы. Реестр и проверка подклассов — __init_subclass__. Изменение самого создания класса — метакласс. Каждое следующее средство даёт больше возможностей, но сложнее для читателя кода; таким образом, выбирается первое средство, которое решает задачу.

Изложение. Класс связывает состояние с операциями над ним; атрибуты экземпляра хранятся в его словаре, атрибуты класса общие для всех экземпляров, а __slots__ заменяет словарь фиксированными ячейками. Функция в теле класса становится связанным методом при обращении через экземпляр; classmethod и staticmethod меняют привязку, свойства добавляют логику атрибуту без изменения интерфейса, а классы данных избавляют от однообразного кода. Атрибуты ищутся по порядку разрешения методов, super() вызывает следующий класс в нём, а композиция часто проще наследования. Магические методы включают объект в операторы и встроенные функции, и возврат NotImplemented передаёт операцию другому операнду. Дескрипторы объясняют методы, свойства и слоты. Класс является объектом метакласса type, и большинство задач, ради которых писали метаклассы, решают __init_subclass__ и декораторы классов. Следующая лекция посвящена итераторам, генераторам и корутинам.
