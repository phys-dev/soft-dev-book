Графы

Дерево из предыдущей главы — очень удобная, но всё-таки частная структура: в нём у каждого узла ровно один родитель, а между любыми двумя узлами существует единственный путь. Реальные связи так устроены далеко не всегда.

Города соединены дорогами, причём из каждого можно уехать несколькими маршрутами. Атомы в молекуле связаны в кольца. Узлы электрической цепи соединяются проводниками, образуя контуры. Компьютеры в сети связаны друг с другом множеством путей. Всё это описывается самой общей структурой — графом.

Граф — это, пожалуй, главная структура данных в прикладной информатике: к задачам на графах сводится огромное количество практических задач, которые на первый взгляд не имеют к ним отношения.

Определения

Граф \( G = (V, E) \) — множество вершин \( V \) (англ. vertices) и множество рёбер \( E \) (англ. edges), каждое из которых соединяет пару вершин.

Основные разновидности:

  • Неориентированный граф — рёбра не имеют направления: если из \( u \) можно попасть в \( v \), то и обратно тоже (дороги с двусторонним движением).
  • Ориентированный граф (орграф, англ. directed graph) — рёбра имеют направление, ребро \( (u, v) \) не означает существования ребра \( (v, u) \) (односторонние улицы, ссылки между веб-страницами, зависимости между задачами).
  • Взвешенный граф — каждому ребру приписано число: длина дороги, сопротивление проводника, пропускная способность канала, энергия связи.

Ещё немного терминологии:

  • смежные вершины — соединённые ребром;
  • степень вершины — число инцидентных ей рёбер (в орграфе различают входящую и исходящую степени);
  • путь — последовательность вершин, в которой соседние соединены рёбрами;
  • цикл — путь, начинающийся и заканчивающийся в одной вершине;
  • связный граф — граф, в котором из любой вершины достижима любая другая;
  • компонента связности — максимальный связный кусок графа;
  • петля — ребро из вершины в саму себя; кратные рёбра — несколько рёбер между одной парой вершин.

Отсюда видно место дерева в общей картине: дерево — связный неориентированный граф без циклов, у которого рёбер ровно на одно меньше, чем вершин. А граф без циклов, но не обязательно связный, называется лесом.

Как хранить граф

От способа хранения зависит и объём памяти, и сложность операций. Есть два основных варианта.

Матрица смежности

Квадратная таблица \( n \times n \), где на пересечении \( i \)-й строки и \( j \)-го столбца стоит единица (или вес ребра), если ребро из \( i \) в \( j \) есть, и ноль в противном случае. У неориентированного графа матрица симметрична.

n = 5
matrix = [[0] * n for _ in range(n)]  # граф без рёбер

def add_edge_matrix(matrix, u, v, directed=False):
    """Добавляет ребро в матрицу смежности (вершины нумеруются с нуля)."""
    matrix[u][v] = 1
    if not directed:
        matrix[v][u] = 1

Проверка «есть ли ребро между \( u \) и \( v \)» выполняется мгновенно, за \( O(1) \). Но памяти нужно \( O(n^2) \) независимо от числа рёбер, а перебор всех соседей вершины требует \( O(n) \) — придётся просмотреть всю строку, даже если сосед всего один.

Список смежности

Для каждой вершины хранится список её соседей.

from collections import defaultdict

graph = defaultdict(list)

def add_edge_list(graph, u, v, directed=False):
    """Добавляет ребро в список смежности."""
    graph[u].append(v)
    if not directed:
        graph[v].append(u)

Памяти требуется \( O(n + m) \), где \( m \) — число рёбер, а перебор соседей вершины занимает время, пропорциональное их количеству. Плата — проверка наличия конкретного ребра за \( O(\deg v) \) вместо \( O(1) \).

Что выбирать? Практическое правило простое: если граф плотный (число рёбер сравнимо с \( n^2 \)) — матрица; если разреженный (рёбер порядка \( n \)) — список. Реальные графы почти всегда разреженные: у человека в социальной сети сотни друзей, а не миллионы; у атома в молекуле — единицы связей. Поэтому по умолчанию бери список смежности.

ОперацияМатрица смежностиСписок смежности
Память\( O(n^2) \)\( O(n + m) \)
Проверить ребро \( (u,v) \)\( O(1) \)\( O(\deg u) \)
Перебрать соседей \( u \)\( O(n) \)\( O(\deg u) \)
Добавить ребро\( O(1) \)\( O(1) \)

Есть и третий способ — список рёбер: просто перечень пар вершин. Он неудобен для обходов, зато идеален для алгоритмов, которые перебирают рёбра целиком (например, алгоритм Краскала), и именно в таком виде граф обычно приходит на вход.

Обходы графа

Обход — систематическое посещение всех вершин, достижимых из стартовой. У графа, в отличие от дерева, есть циклы, поэтому появляется обязательный элемент: множество посещённых вершин. Без него обход зациклится.

Поиск в глубину (DFS)

Идея: из текущей вершины уходим как можно дальше вглубь, а когда идти больше некуда — возвращаемся и пробуем другое направление. Это тот же самый обход в глубину, что и у деревьев, только с проверкой на повторное посещение.

def dfs_recursive(graph, vertex, visited=None):
    """Рекурсивный обход в глубину. Возвращает вершины в порядке обхода."""
    if visited is None:
        visited = set()
    visited.add(vertex)
    order = [vertex]
    for neighbour in sorted(graph[vertex]):
        if neighbour not in visited:
            order.extend(dfs_recursive(graph, neighbour, visited))
    return order

Рекурсия хороша для чтения, но опасна на практике: глубина рекурсии в Python ограничена (по умолчанию около 1000), и на графе из ста тысяч вершин программа упадёт с RecursionError. Поэтому в боевых решениях DFS пишут итеративно, заменяя стек вызовов явным стеком:

def dfs_iterative(graph, start):
    """Итеративный обход в глубину через явный стек."""
    visited = set()
    order = []
    stack = [start]
    while stack:
        vertex = stack.pop()
        if vertex in visited:
            continue
        visited.add(vertex)
        order.append(vertex)
        # соседей кладём в обратном порядке, чтобы снимать по возрастанию
        for neighbour in sorted(graph[vertex], reverse=True):
            if neighbour not in visited:
                stack.append(neighbour)
    return order

Обрати внимание на важную деталь: проверка if vertex in visited стоит после снятия со стека, а не только перед добавлением. Одна и та же вершина может попасть в стек несколько раз через разных соседей, поэтому её нужно отсеивать в момент обработки.

Поиск в ширину (BFS)

Идея: сначала посещаем всех соседей стартовой вершины, потом соседей соседей и так далее — расходимся кругами, как волна по воде. Отличие от DFS в одну строчку: вместо стека используется очередь.

from collections import deque

def bfs(graph, start):
    """Обход в ширину. Возвращает вершины в порядке обхода."""
    visited = {start}
    order = []
    queue = deque([start])
    while queue:
        vertex = queue.popleft()          # берём из начала очереди
        order.append(vertex)
        for neighbour in sorted(graph[vertex]):
            if neighbour not in visited:
                visited.add(neighbour)    # помечаем сразу при добавлении
                queue.append(neighbour)
    return order

Заметь: в BFS вершина помечается посещённой в момент добавления в очередь, иначе она успеет попасть туда несколько раз.

Оба обхода работают за \( O(n + m) \) — каждая вершина и каждое ребро обрабатываются один раз. Выбор между ними определяется задачей:

  • BFS посещает вершины в порядке возрастания расстояния от старта, поэтому именно он находит кратчайшие пути в невзвешенном графе;
  • DFS естественно ложится на рекурсию и используется для поиска циклов, топологической сортировки, компонент связности и разбора структуры графа.

Кратчайшие пути

В невзвешенном графе кратчайший путь ищет BFS: достаточно попутно запоминать расстояние и предка каждой вершины.

def bfs_shortest_paths(graph, start):
    """Расстояния (в рёбрах) и предки на кратчайших путях от start."""
    dist = {start: 0}
    parent = {start: None}
    queue = deque([start])
    while queue:
        vertex = queue.popleft()
        for neighbour in graph[vertex]:
            if neighbour not in dist:
                dist[neighbour] = dist[vertex] + 1
                parent[neighbour] = vertex
                queue.append(neighbour)
    return dist, parent

Восстановить сам путь потом легко: идти от конечной вершины по ссылкам parent до старта и развернуть результат.

Если рёбра взвешенные, BFS уже не годится: путь из трёх коротких рёбер может оказаться короче пути из одного длинного. Здесь работает алгоритм Дейкстры. Его идея — жадная: поддерживаем текущие оценки расстояний и на каждом шаге берём ещё не обработанную вершину с наименьшей оценкой (она уже не улучшится), после чего пробуем улучшить оценки её соседей — эта операция называется релаксацией.

import heapq

def dijkstra(graph, start):
    """Кратчайшие расстояния во взвешенном графе с неотрицательными весами.

    graph — список смежности вида {вершина: [(сосед, вес), ...]}.
    """
    dist = {start: 0}
    heap = [(0, start)]           # приоритетная очередь (расстояние, вершина)
    while heap:
        d, vertex = heapq.heappop(heap)
        if d > dist.get(vertex, float("inf")):
            continue              # устаревшая запись, вершина уже обработана
        for neighbour, weight in graph[vertex]:
            new_dist = d + weight
            if new_dist < dist.get(neighbour, float("inf")):
                dist[neighbour] = new_dist
                heapq.heappush(heap, (new_dist, neighbour))
    return dist

Куча (см. главу про деревья) даёт сложность \( O(m \log n) \). Важное ограничение: веса должны быть неотрицательными — на рёбрах с отрицательным весом жадность ломается, и нужен алгоритм Беллмана — Форда.

Топологическая сортировка

Пусть ориентированный граф описывает зависимости: ребро \( u \to v \) означает «\( u \) должно быть выполнено раньше \( v \)». Компиляция модулей, порядок расчётных этапов в пайплайне обработки данных, установка пакетов — везде одна и та же задача: выстроить вершины в линию так, чтобы все рёбра шли слева направо. Это и есть топологическая сортировка, и возможна она тогда и только тогда, когда в графе нет циклов (иначе зависимости противоречивы).

Простейший способ — DFS: вершина добавляется в результат после того, как обработаны все её потомки, а в конце список разворачивается.

def topological_sort(graph, vertices):
    """Топологическая сортировка ориентированного ациклического графа."""
    visited = set()
    order = []

    def visit(vertex):
        visited.add(vertex)
        for neighbour in graph[vertex]:
            if neighbour not in visited:
                visit(neighbour)
        order.append(vertex)      # добавляем на выходе из вершины

    for vertex in vertices:
        if vertex not in visited:
            visit(vertex)
    return order[::-1]            # разворачиваем

Минимальное остовное дерево

Остовное дерево (англ. spanning tree) связного графа — подмножество рёбер, которое связывает все вершины и не содержит циклов, то есть дерево на всех \( n \) вершинах из \( n-1 \) ребра. Минимальное остовное дерево (MST) — то, у которого суммарный вес рёбер наименьший. Классическая постановка: соединить все дома оптоволокном, потратив минимум кабеля.

Два классических алгоритма, оба жадные:

  • Алгоритм Прима растит дерево из одной вершины: на каждом шаге добавляется самое лёгкое ребро, ведущее из уже построенной части наружу. Удобно реализуется через кучу, сложность \( O(m \log n) \). По духу это Дейкстра, только вместо расстояния от старта минимизируется вес одного ребра.
  • Алгоритм Краскала идёт от рёбер: сортирует их все по весу и добавляет по очереди те, что не образуют цикл. Проверка «не образует ли цикл» делается структурой «система непересекающихся множеств» (DSU). Сложность \( O(m \log m) \).

Полезное наблюдение: если в алгоритме Прима заменить «минимальное ребро» на «максимальное», получится максимальное остовное дерево — именно эта задача разбирается в конце главы.

Графы в физических задачах

Графы в физике встречаются чаще, чем кажется на первый взгляд.

  • Электрические цепи. Схема — это буквально граф: узлы и ветви. Законы Кирхгофа записываются через матрицу инцидентности графа, а число независимых контурных уравнений равно \( m - n + 1 \) — количеству рёбер, не вошедших в остовное дерево. Остовное дерево цепи — не абстракция, а рабочий инструмент расчёта.
  • Модель Изинга и перколяция. Спины на решётке — вершины, взаимодействия соседей — рёбра. Алгоритмы кластерного обновления (Свендсена — Ванга, Вольфа) — поиск компонент связности; задача о перколяции — вопрос о существовании компоненты, соединяющей края решётки.
  • Молекулы и структуры. Атомы и химические связи образуют граф; поиск колец в молекуле — поиск циклов. На этом же представлении работают графовые нейронные сети, предсказывающие свойства веществ.
  • Марковские цепи и графы состояний. Состояния системы — вершины, переходы с вероятностями — взвешенные рёбра орграфа.
  • Трассировка и планирование. Разводка кабелей на установке, маршрут манипулятора, планирование эксперимента — задачи о кратчайшем пути или остовном дереве.

Для практических расчётов не обязательно писать алгоритмы руками: есть библиотека NetworkX.

import networkx as nx

# граф-решётка 4 x 4 — например, узлы двумерной модели Изинга
lattice = nx.grid_2d_graph(4, 4)

print(nx.number_connected_components(lattice))       # компоненты связности
print(nx.shortest_path(lattice, (0, 0), (3, 3)))     # кратчайший путь
mst = nx.minimum_spanning_tree(lattice)              # остовное дерево

Впрочем, разбираться в том, как эти алгоритмы устроены внутри, всё равно необходимо: библиотека не подскажет, что твоя задача сводится к поиску компонент связности.

Разбор задач

Разберём несколько базовых задач на графы. Как и в предыдущих главах, сначала попробуй решить сам — задачи собраны в тренажёре.

Во всех задачах вершины нумеруются с единицы, а граф подаётся на вход списком рёбер: в первой строке числа \( n \) и \( m \) (количество вершин и рёбер), далее \( m \) строк с парами вершин.

Задача 1. Построить список смежности

Условие. Дан ориентированный граф списком рёбер. Построй его список смежности: для каждой вершины \( i \) выведи число исходящих рёбер, а затем номера вершин, в которые они ведут, в порядке возрастания.

Идея решения. Прямая реализация определения. Заводим список списков и проходим по рёбрам, добавляя конец каждого ребра в список его начала. Сортировку делаем один раз в конце.

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]        # вершины нумеруются с единицы

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)                    # граф ориентированный: только u -> v

for vertex in range(1, n + 1):
    neighbours = sorted(graph[vertex])
    print(len(neighbours), *neighbours)

Сложность. По времени — \( O(n + m \log n) \): чтение рёбер стоит \( O(m) \), а сортировка всех списков смежности в сумме \( \sum_i d_i \log d_i \le m \log n \). По памяти — \( O(n + m) \).

Задача 2. Перевести список рёбер в матрицу смежности

Условие. Дан ориентированный граф списком рёбер. Выведи его матрицу смежности \( n \times n \): на пересечении \( i \)-й строки и \( j \)-го столбца стоит единица, если есть ребро из \( i \) в \( j \).

Идея решения. Заводим нулевую матрицу и расставляем единицы. Единственная тонкость — не создать матрицу через [[0] * n] * n: так получится \( n \) ссылок на один и тот же список, и запись в одну строку изменит все сразу. Это классическая ловушка, к устройству которой мы ещё вернёмся в главе про объекты и память.

n, m = map(int, input().split())
matrix = [[0] * n for _ in range(n)]      # именно так, а не [[0] * n] * n

for _ in range(m):
    u, v = map(int, input().split())
    matrix[u - 1][v - 1] = 1              # переходим к нумерации с нуля

for row in matrix:
    print(*row)

Сложность. По времени — \( O(n^2 + m) \) (вывод матрицы уже стоит \( O(n^2) \)), по памяти — \( O(n^2) \).

Задача 3. Обход в глубину

Условие. Задан неориентированный граф. Обойди с помощью DFS все вершины, достижимые из заданной вершины \( s \), и выведи их в порядке обхода. Соседи каждой вершины рассматриваются в порядке возрастания номеров.

Идея решения. Итеративный DFS со стеком (граф может содержать до \( 10^5 \) вершин, рекурсия не выдержит). Чтобы соседи обрабатывались по возрастанию, кладём их в стек в обратном порядке — снимается всегда последний положенный.

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)                    # граф неориентированный

start = int(input())
for neighbours in graph:
    neighbours.sort(reverse=True)         # сортируем один раз заранее

visited = [False] * (n + 1)
stack, order = [start], []

while stack:
    vertex = stack.pop()
    if visited[vertex]:                   # вершина могла попасть в стек дважды
        continue
    visited[vertex] = True
    order.append(vertex)
    for neighbour in graph[vertex]:
        if not visited[neighbour]:
            stack.append(neighbour)

print(*order)

Сложность. По времени — \( O(n + m) \) плюс сортировка списков смежности, по памяти — \( O(n + m) \).

Задача 4. Обход в ширину

Условие. Та же постановка, но обход выполняется в ширину.

Идея решения. Меняем стек на deque и снимаем элементы с начала. Соседей сортируем уже по возрастанию, и помечаем вершину посещённой при добавлении в очередь.

from collections import deque

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

start = int(input())
for neighbours in graph:
    neighbours.sort()

visited = [False] * (n + 1)
visited[start] = True
queue, order = deque([start]), []

while queue:
    vertex = queue.popleft()              # берём из начала очереди
    order.append(vertex)
    for neighbour in graph[vertex]:
        if not visited[neighbour]:
            visited[neighbour] = True     # помечаем сразу при добавлении
            queue.append(neighbour)

print(*order)

Сложность. Та же, что у DFS: \( O(n + m) \) по времени и памяти. Обрати внимание, насколько мало отличается код двух принципиально разных обходов — вся разница в том, с какого конца мы берём вершины из контейнера.

Задача 5. Компоненты связности

Условие. Дан неориентированный граф. Найди его компоненты связности: выведи их количество, а затем вершины каждой компоненты по возрастанию. Компоненты упорядочены по номеру первой вершины.

Идея решения. Запускаем обход из каждой ещё не посещённой вершины: всё, что обход соберёт за один запуск, и есть одна компонента. Если перебирать стартовые вершины по возрастанию, компоненты автоматически получатся в нужном порядке.

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

visited = [False] * (n + 1)
components = []

for vertex in range(1, n + 1):
    if visited[vertex]:
        continue
    component, stack = [], [vertex]       # новая компонента
    while stack:
        current = stack.pop()
        if visited[current]:
            continue
        visited[current] = True
        component.append(current)
        stack.extend(graph[current])
    components.append(sorted(component))

print(len(components))
for component in components:
    print(*component)

Сложность. По времени — \( O(n + m) \) плюс сортировка компонент, по памяти — \( O(n + m) \). Ключевая мысль: внешний цикл по вершинам не делает алгоритм квадратичным — каждая вершина обрабатывается ровно один раз, а внешний цикл лишь находит стартовые точки.

Задача 6. Самая дорогая сеть

Условие. Дан связный взвешенный неориентированный граф. Найди вес максимального остовного дерева — набора рёбер, который связывает все вершины и имеет наибольший суммарный вес. Если граф несвязен, дерева не существует.

Идея решения. Алгоритм Прима, только на каждом шаге выбирается не минимальное, а максимальное ребро. Модуль heapq реализует лишь min-heap, поэтому применим стандартный приём: кладём в кучу вес со знаком минус — тогда «минимальный» элемент кучи окажется максимальным по модулю.

Начинаем с первой вершины и складываем в кучу все исходящие из неё рёбра. Затем на каждом шаге достаём самое тяжёлое ребро; если оно ведёт в новую вершину — добавляем её в остов, прибавляем вес к ответу и складываем в кучу её рёбра. Если после завершения цикла в остов вошли не все вершины, значит, граф несвязен.

import heapq

def add_vertex(vertex, graph, added, heap):
    """Добавляет вершину в остов и кладёт её рёбра в кучу."""
    added[vertex] = True
    for neighbour, weight in graph[vertex]:
        if not added[neighbour]:
            heapq.heappush(heap, (-weight, neighbour))   # минус: нужен max-heap

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, weight = map(int, input().split())
    graph[u].append((v, weight))
    graph[v].append((u, weight))

added = [False] * (n + 1)
added[0] = True                           # нулевой вершины не существует
heap, total = [], 0

add_vertex(1, graph, added, heap)         # растим остов из первой вершины

while not all(added) and heap:
    weight, vertex = heapq.heappop(heap)
    if not added[vertex]:                 # ребро внутрь остова пропускаем
        total += -weight
        add_vertex(vertex, graph, added, heap)

print(total if all(added) else "Oops! I did it again")

Сложность. По времени — \( O(m \log n) \): каждое ребро попадает в кучу не более одного раза, а операции с кучей стоят \( O(\log n) \). По памяти — \( O(n + m) \).

Резюме

  • Граф — самая общая структура для описания связей; дерево и список — его частные случаи.
  • Разреженные графы храни списком смежности (\( O(n+m) \) памяти), плотные — матрицей смежности (\( O(n^2) \), зато проверка ребра за \( O(1) \)).
  • DFS и BFS отличаются только контейнером — стек против очереди — и оба работают за \( O(n + m) \).
  • BFS находит кратчайшие пути в невзвешенном графе, Дейкстра — во взвешенном с неотрицательными весами за \( O(m \log n) \).
  • Обязательно помечай посещённые вершины: в отличие от дерева, у графа есть циклы, и без пометок обход не завершится.
  • Компоненты связности, топологическая сортировка и остовные деревья — три классических применения обходов, к которым сводится масса практических задач.
